# Gowin公式資料との照合と、IP生成オプションの調査（2026-11-04）

目的：再生成IP（新ツール）が400MHzで校正を完了せず、旧IP（サンプル）は完了する原因を絞る。公式資料（IPUG281-2.6J、IPUG1182-1.1J、RN281、公式リファレンスデザイン）と我々の設定を照合し、IP生成オプションを網羅的に生成してネットリストを比較した。**原因は特定されていない。** 作成者は実機に触れていない（実機はユーザー指示で一時停止中）。資料はメインセッションが `D:\esp\gowin-ddr3-docs\`、`D:\esp\gowin-docs\` に展開したもの（再配布しない）。

## 1. 公式資料から読み取ったこと（IPUG281-2.6J、第3・4・7章）
- **Memory Clock**：DDR3レートに対応する周波数。800Mbpsなら400MHz。クロック比1:4の最大レートは、GW2Aを含む「その他のデバイス」で800Mbps（＝400MHzが上限）、1:2は533Mbps。→ サンプルの400MHz（実PLLは398.25MHz）は上限いっぱい。新ツールが420MHz以上を受理しない（既定の200MHz相当に戻る）事実と整合する。
- **clk**：低速の連続クロックで、推奨50MHz。サンプルも我々も27MHzを接続し、324MHzでは校正が通っている（実機）。
- **リセット**：`rst_n` はIPに送る前に `clk` で同期解放が必要。任意のリセット論理を接続できる。`pll_lock` はPLLのLOCK信号だけを接続する（そうしないとクロック安定を検出できず、初期化失敗が起きやすい）。→ 我々は `pll_lock` をPLLのLOCKに接続している。`rst_n` は `raw_reset_n && pll_lock && reset_hold==0` で、`reset_hold` は `clk` 同期で解放される（起動直後に非同期入力が解放されるだけの場合は同期解放）。324MHzで動作しているため、原因とは考えにくい。
- **OUTPUT DRV**：DQ／DQSの出力強度。LOW＝RZQ/6＝40Ω、HIGH＝RZQ/7＝34Ω。**「DDR3の初期化に失敗したり、読み書きでビットエラーが出たりした場合は、デバッグのためにこのオプションを変更してみることができる」**。→ 試す価値がある変種として用意（5章）。
- **Debug Parameter／Debug Port**：「エンジニアのデバッグ用で、お客様が注意を払う必要はない」。
- **ユーザーアドレス**：幅 ＝ Rank＋Bank＋Row＋Column。**最上位ビット（Rank）は使えないので0に固定**。Rank Addressは機能しない。x16・1:4では28ビットのユーザーアドレス幅の例がある（我々は27ビット＋rank0）。
- **SIM**：シミュレーション以外ではチェックしない（我々はfalse）。
- **帯域効率**：1:4では90%（資料の値。実測ではない）。
- **IPUG1182（PHY IP）**：PHYは Write Leveling と Read Calibration を行う初期化モジュールを持ち、温度自動調整（−40〜85℃対応）の機能もある。初期化完了は `ddr_init_internal`（我々の `init_calib_complete` の元）。

## 2. 我々の設定の妥当性（H5TQ1G63EFR-PBC：資料上の型番。個体の刻印は未確認）
| 項目 | 我々 | 根拠・判定 |
|---|---|---|
| 行／列／バンク | 13／10／3 | 1Gb x16の規格（ハイニックスのデータシート、SHA-256 f4ac9e84…、`MEM_BIST構成案.md`）：行 A0..A12、列 A0..A9、8バンク。**妥当** |
| DQ／DRAM幅 | 16／16 | x16チップ1個。**妥当** |
| CL／CWL | 6／5 | tCK 2.5〜3.3nsでCL6／CWL5が許容（同データシート）。400MHz（2.5ns）でも範囲内。**妥当**。CL5は2.5nsでは範囲外（3.0〜3.3ns） |
| Write Recovery | 8 | DDR3-800で最小6（15ns÷2.5ns）、8は許容範囲内。サンプルと同じ符号（1） |
| tRAS／tRC／tRCD／tRP／tRRD／tRTP／tWTR／tFAW | 50／75／20／20／15／15／15／60 ns | データシートの値よりも保守的（サンプルより長い）。**問題になりにくい** |
| tREFI／tRFC | 3.5µs／260ns | 規格7.8µs／110ns（1Gb）より保守的。リフレッシュ頻度が高いだけで、機能上は安全側 |
| Rtt Nom／Rtt Wr／OUTPUT DRV | 40Ω／OFF／LOW(40Ω) | サンプルのipcと同じ符号（3／0／0）。 |
| Memory Clock／PLL | 324（400では400）／PLL 27×12 または 27×59/4 | 400では実PLL 398.25MHz。サンプルも同じ。 |
- サンプルの `.ipc` の符号（CAS_LATENCY＝0、ROW_ADDR＝2、COL_ADDR＝1、DRAM_WIDTH＝2）は、旧ツールの選択肢の並びが新ツールと違う可能性があり、数値化できない。ただし **CAS_LATENCY＝0 が新ツールの並びどおりCL5なら、2.5ns（400MHz）ではデータシート外になる**ため、旧ツールの並びは新ツールと異なる（CL6を指す）と考えるのが自然（推定）。サンプルが行14本で設定している点は、`ddr_addr[13:0]` を持つ別構成の流用の可能性が高い。我々の設定が部品として誤っている証拠は見つからなかった。

## 3. IP生成オプションの網羅生成（`fpga/validation/mem-ip-option-sweep-2026-11-04.json`）
新ツールで、Memory Clock 400（1:4）に対しオプションを変えて生成し、ネットリストのDLL設定とIODELAY（遅延段数）を、サンプル（旧ツール）と比べた。

| 設定 | DLL `CODESCAL`／`SCAL_EN` | DQ用IODELAY | コマンド／CK用IODELAY |
|---|---|---|---|
| **サンプル（旧ツール、400MHz）** | "101"／**"true"** | 6 | **24個（40段）** |
| 新ツール既定（400／324MHz、Debug無効） | "111"／"false" | 5 | なし |
| Debug有効 P1=101、P2=6、P3=40、P4=40 | "101"／"false" | 6 | なし |
| Debug有効 P1=101、P2=0、P3=0、P4=0 | "101"／"false" | 0 | なし |
| Debug有効 P1=111、P2=5、P3=0、P4=0 | "111"／"false" | 5 | なし |
| Debug有効 P1=101、P2=6、P3=80、P4=80 | "101"／"false" | 6 | なし |
| Debug有効＋Debug Port有効（P=101／6／40／40） | "101"／"false" | 6 | なし |
| OUTPUT DRV HIGH | "111"／"false" | 5 | なし（`gwmc_param.v` の `OUTPUT_DRV` が "HIGH" になる） |
| Addr Cmd Mode 2T（既存の1T指定に重複して追記） | "111"／"false" | 5 | なし（`ADDR_CMD_MODE` は "1T" のまま。**重複キーの追記が採用されなかった可能性があり、2Tの影響は未評価**） |
| User Interface＝PHY | "111"／"false" | 5 | なし（セル数 4315、コントローラなし） |
| 1:2、200MHz（公式リファレンスの設定） | "101"／"false" | 0 | なし |
- **P1 ＝ DLL `CODESCAL`、P2 ＝ DQ用IODELAYの段数**（値がそのままネットリストに出る）。P3／P4とDebug Portは、ネットリストのIODELAYにもDLLにも影響しない。
- 新ツールの既定は、周波数・比率で変わる：1:4（324／400MHz）では（"111"、5）、1:2／200MHzでは（"101"、0）。公式リファレンスの `.ipc`（1:2／200MHz）は PARAMETER1＝5（＝"101"）、PARAMETER2〜4＝0 で、この既定と一致する。
- **サンプルのコマンド／CK用IODELAY（40段×24）と `SCAL_EN`＝true は、新ツールのどのオプションでも生成されない。** メインセッションの確認（公式リファレンスもコマンド系IODELAYなし）と合わせ、新ツールの方針（PHY内のWrite Levelingで合わせる）が旧ツールの固定遅延と異なる可能性がある（仮説）。
- 「2T」は、基準の設定で既に`Addr_Cmd_Mode 1T`を指定していたため、重複して追記した値が採用されなかった可能性がある。2Tの評価には、基準の指定を置き換えて生成し直す必要がある（未実施）。

## 4. 校正が通る可能性のある差の優先順位（仮説）
1. **DLLの`CODESCAL`と、DQ用IODELAYの段数**（"111"／5 → "101"／6）。サンプルが400MHzで使う値で、新ツールのDebugパラメータで設定できる。→ `clk400dp`（P1＝101、P2＝6）。
2. **P2のほかの値**：同じ"101"でP2＝0（公式リファレンスの既定）、"111"でP2＝6（CODESCALを既定のままDQ遅延だけ変える）。→ `clk400x_dp000`、`clk400x_dp1116`。
3. **OUTPUT DRV**：IPUG281が初期化失敗時の調整対象として挙げる。→ `clk400x_drvhigh`。
4. **コマンド／CK用IODELAYと`SCAL_EN`**：新ツールでは生成不能。旧IP（サンプル）を使うか、Gowin／Sipeedへの問い合わせ以外に再現手段がない。
5. 影響が小さいと見ているもの：PLL属性（サンプルと同一）、`clk`の27MHz（324MHzで動作）、リセット回り（同）、制約・SDC（clk400_asyncsdcで影響なしを確認）、ユーザーロジック（sampleipで無関係を確認）。

## 6. 未解決の矛盾（アドレス配置）
サンプルの `tester.v` は、アドレスのビット26（`27'h400_0000`）に別の値を書いて先頭が上書きされると「1G」と判定し、実機では「DDR Size: 1G」と出た。一方、`sampleip_map`（アドレスのビット26＝我々のバンク最上位）の128MiB全域テストはエイリアスなしで通った。ユーザーアドレスの並び（IPUG281は Rank＋Bank＋Row＋Column の順に記す）とビット26の意味を、両方が成り立つ形で説明できていない。→ 実機の再開後、`tester.v` の検出手順（アドレス0とビット26の2点を書き、先頭を読む）を再現する小さなジョブで確認する（未実施）。物理容量（1Gb）と配置の前提は未確認として扱う。
