# NPU DDR 実装・検証記録（2026-11-07、4E20）

## 到達点と範囲

INT8畳み込みタイルをDDR3から読み、FPGAで積和し、最終INT32タイルをDDR3に書き戻す経路を実装した。ホストがICブロックを順次指示し、中間積和はBRAMに保持する。これは畳み込みのDDR実行基盤の検証であり、YOLO全層の推論完了・精度・速度の証明ではない。非Conv層、量子化・逆量子化、グラフ実行と画面表示はホスト側と協調して検証を続ける。

既存のDDRピン、電気条件、MEMV1 bridge/adapter、固定した旧DDR IPは変更していない。機能別NPUビットストリームとしてUSERCODE/CAPSは`4E20`。Linux/MeOSには本NPUコマンドのホスト実装を追加しておらず、現段階の接続対象はESP-IDF側の開発実装である。要求の参照版はLinux `cfc9a6e`、MeOS `78274b4`、外部メモリ研究 `e84b59e`、ESP-IDF側は並行開発中のresume版。ピン仕様の変更はない。

## 実装

- `fpga/npu/rtl/conv_tile_engine.v`：符号付きINT8、1×1/3×3、stride 1/2、IC最大16・OC最大8・出力16×16。INT32オーバーフローは結果を無効化してエラーにする。全テンソルのBRAM常駐は不要。
- `fpga/npu/rtl/npu_ddr_tile_loader.v`：入力CHWのピッチ、負の原点のゼロパディング、非整列重みの読み集め、IC継続、最終INT32の行書戻し。範囲・重複・所有しない末尾の書込みを検査する。誤タグや校正喪失時はcancel/drainし、応答を回収できない場合はquarantineする。書込み済みの接頭部分のロールバックは行わない。
- `fpga/npu/rtl/npu_ddr_core.v`：ホストとloaderをtoggle arbiterで共有DDR経路に接続。書込み4KiB・読出し4KiBの共有ステージを使用。ホスト操作とConv操作を同時に受け付けない。
- 校正済み信号はSYSで2段同期後256サイクル待つ。メモリ利用可能性が落ちると動作状態とtoken bindingを無効化し、generationを進める。世代は物理resetのみで0に戻る。旧セッションの暗黙再開を防ぐ。
- `fpga/platform/dock/tab5_dock_npu_ddr_top.v`と`fpga/builds/dock/build_npu_ddr.tcl`で既存DDR wrapper・制約に統合。SYS 27MHz、USER 99.5625MHz、メモリ398.25MHz。Conv演算器はSYSで動作する。

## ソフト・RTL検証

| 検証 | 結果 | 根拠 |
|---|---|---|
| Conv単体 | 2156ブロック合格 | `fpga/build/conv-tile-fault-full/` |
| DDR loader＋独立NumPy INT64参照 | 数値45ケース＋異常系合格 | `fpga/build/ddr-tile-loader-final/` |
| 実MEMV1 bridge/adapter経由 | 同じ45ケース合格 | `fpga/build/ddr-tile-realadapter/` |
| 全coreのピンレベルLINK通信 | 64コマンド合格 | `fpga/build/npu-ddr-core-extended/` |

全core試験は実framer/arbiter/adapter/RAM/kernelと、APP_ROW_PAD=1を逆変換するDDRモデルを使用する。CRC付き2032B書込み・1024B読出し、16KiB境界、128MiB末尾、範囲外拒否、CRC不良・途中打切り書込みの無作用、IC16+3のConv全INT32一致とガード領域を確認した。ホスト要求中・Conv要求中の校正喪失、再binding後の旧部分積和拒否、新規再実行、ARM・物理resetも含む。シミュレーションはDDR PHYやケーブルの電気的品質を証明しない。

## Gowin配置配線とSTAの制限

Education 1.9.11.03で配置配線と`.fs`生成まで完了。使用量はLogic 10366/20736、Register 5779、BSRAM **38/46**、DSP **5/24**。現状は追加BRAMの余裕が8個であり、大きな機能の同居は再合成・計測が必要。

**無例外のSTAは未合格**。setup 1408、hold 107の違反が残る。同一クロック内TNSは0で、ツール報告FmaxはSYS 42.333MHz、USER 109.382MHzだが、これだけで全体をtiming qualifiedとは扱わない。

最悪側30経路の分類は、setupがvendor内部12・保持応答bundle11・保持要求bundle7、holdがvendor内部3・保持応答bundle26・最初の同期段1。recoveryはvendor reset境界25・vendor内部2・その他CDC3。詳細ノードとslackは`fpga/build/npu-ddr-v1/timing-classification.json`に保存した。保持bundleのプロトコルによる安定時間を根拠に個別制約を検討できるが、vendor reset境界は別途確認が必要。包括的な非同期clock除外は追加していない。

ビットストリームは`fpga/build/npu-ddr-v1/npu_ddr/impl/pnr/npu_ddr.fs`、SHA256は`39d1fb63e634475e51691facfcd3b6fd08685c1ff43221f8580e7b498c35250e`。8個の試験対象RTLのhashが配置配線snapshotと一致した。構成・未合格事項は同ディレクトリの`qualification.json`と`proof-source-match.json`に保存。vendor IPは固定hash `04ef287b2caf7779b8464c28f4e2176b35f24b181aab9c7509d8b3d9f734bed2`を記録し、無視対象のIPソースをGitに追加しない。

## 実機情報と次の判定

主担当からの2026-11-07報告では、4E20のDDR selftestは5208項目合格し、GPIOの公称1000ns、500ns、100ns設定でも通過した。これは主担当の実機試験結果であり、この記録担当はデバイス操作を実施していない。GPIO設定値は実効スループットや信号品質限界を示さない。正式な実機ログ・フル推論結果は主担当の検証記録で追記・照合する。

N128、その後S128の全推論を、SDからのアップロード後に主担当が検証中。現時点で本書から成功とは主張しない。大容量の次段階S544は、ベース必要メモリ **103,712,384B**、量子化ステージ追加 **5,588,992B**、単純合算 **109,301,376B**の計画値。128MiB（134,217,728B）との差は24,916,352Bだが、予約領域・アラインメント・同時生存・追加作業領域を含むallocator実測が必要。これはPSRAMを超えるモデルをDDRで実行するための容量計画であり、S544の全推論実績ではない。

実機の128MiB範囲/RMW/Convのgolden一致、全層raw出力比較、表示・推論/転送時間の分離計測を順に確定する。STAとPHYの制限を残した診断動作と、正式なタイミング保証は分けて記録する。
