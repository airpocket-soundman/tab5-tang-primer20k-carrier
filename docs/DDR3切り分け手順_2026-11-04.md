# DDR3コマンド停止の切り分け手順（2026-11-04）

対象：`be42c604`（USERCODE 0xB317）で、書込みコマンド7件を受理した後にコントローラがコマンドを取り出さない問題（read pointer 0、`send_wr`が一度も立たない、`refresh_request`が立ちっぱなし）。ブランチ `claude/track-p2-ddr3-variants`（基点 `claude/track-d-ddr3` `d1762c4`）。

**この資料の作成者は実機（Tab5 COM4、Dock、JTAG）に触れていない。** 下のイメージの合否、原因は、すべて未確定。実機試験はメインセッションだけが行う。

## 0. イメージ一覧とビルド状態

各イメージは基準 `be42c604` のソースに対して**1項目だけ**変える。ソースの生成は `python fpga/mem/tests/prepare_variant.py cs0|rst|refwait|all`（`fpga/build/mem-variant-<id>/rtl/` を作る。1箇所の置換が1回だけ一致しなければ失敗する）。ビルドは `MEM_VARIANT=<id>` を付けた `build.tcl`（4.のとおり）。

| ID | 変える項目 | 変更内容 | ビルド状態（本資料作成時点） |
|---|---|---|---|
| base | なし | `be42c604`（PAIRED_WRITE=1、待ち256、PLL 324MHz、`ddr_cs`はIP出力、リセット保持27000） | 保存済み（`fpga/validation/mem-paired-write-2026-11-04/mem_bist.fs.gz`） |
| (b) `cs0` | `ddr_cs` | ピンを定数0にし、IPの`O_ddr_cs_n`は未接続（Sipeedサンプルと同じ） | **ソース生成のみ。Gowin未導入のため未ビルド** |
| (c) `rst` | リセット／PLL lock | PLL lock後の1ms保持を外し `controller_reset_n = raw_reset_n && pll_lock` | **同上** |
| (d) `refwait` | リフレッシュ待ち | 校正後の待ちを256→60000 USERサイクル（約0.74ms、tREFI 3.5µsの約200回分）に | **同上** |
| (a) | メモリクロック | 324→400MHz | **未着手**（下の「(a)の注意」） |

### (a)の注意（実装前に分かっていること）
- IP（`generate_ip.tcl`）の `Memory_Clock` と `mem_pll.v`、`mem_bist.sdc` を同時に変える必要がある。IPは非整数周波数を拒否する（`MEM_BIST構成案.md`）。公式サンプルは27MHz×59/4=398.25MHzのPLLを使うので、IPを400、PLLを IDIV=3／FBDIV=58／ODIV=2（VCO 796.5MHz）にする案。ユーザークロックは約99.56MHz。
- **現イメージのUSER Fmaxは81.7MHz（81MHz指定で余裕+0.106ns）。約99.6MHzでの全STA通過は期待できない**（ビルドして確認するまで不明）。通らなければそのまま失敗として記録し、通ったように扱わない。
- IPを作り直すと `MemDDR3.vo` のSHA-256が変わる。`prepare_deep_taps.py` は 4d37c875… を固定で検査し、スケジューラ観測用のタップは自動生成ネット名（`n219_4`等）に依存する。再生成したVOでは、これらの検査と名前を確認し直す作業が要る（024f観測が出ない可能性もある）。
- ホスト側は `mem_protocol.h`（SYSQUERY 4/5 = 324/81）と `probe_mem_bist.py`（`values[:6]`、snapshot word30 = 81）が324／81を固定で検査している。(a)の実機試験前にホスト側の受理値を（324,81）に加えて新しい組合せにする変更が要る。**この変更は、(a)のイメージが実在し周波数が決まってから行う**（現時点では未実施）。
- 実機試験の優先度は、他のイメージが先（Gowinさえあれば同一フローで作れる、かつホスト変更が不要）。

## 1. 準備（メインセッション、実機の前）

1. 電源・実装の確認（**物理個体起因の切り分けで、イメージを替える前に行う**）：
   - Core上のDDR3まわりの電源。1.5V（VDDQ）、VREF（約0.75V）、VTT（約0.75V）をテスタ／オシロで測る。測定点は `docs/reference/tang-primer-20k/SOM-3961_Schematic.pdf` のDDR3ページで確認する。測れない場合は「未測定」と記録する。
   - CoreとDockの嵌合（ピンヘッダ全体が奥まで入っているか）、他のFPGAイメージがSRAMに載ったままでないか（電源を入れ直してから書込む）。
   - UD1の刻印（資料上は H5TQ1G63EFR-PBC）。個体の刻印は未確認なので、写真と文字を記録する。
2. ホストMEM probeファームは、ホストmain `6ad1ed6` から作った既存ビルド（ELF SHA-256 `f7c84fe7…`、`tab5_gpu_lab.bin` SHA-256 `7d417e35…`）がTab5に載っている（引継ぎ資料10章）。再ビルドが必要な場合のみ：
   ```powershell
   powershell -File tools\build_mem_probe.ps1 -BuildName mem-probe-<新しい名前>
   ```
   既存のビルドディレクトリは上書きされない（スクリプトが拒否する）。新しい名前を使う。ホスト側のコード変更は(b)(c)(d)では不要（ABI・SYSQUERY値は不変）。
3. FSの展開とSHA-256確認：各イメージは `fpga/validation/mem-variant-<id>-2026-11-04/` にgzipで保存する（ビルド後に追加。無い場合は未ビルド）。`gzip -dk` で展開し、`README.md` に書いたSHA-256と一致することを確認してから書込む。

## 2. FPGAをSRAMに書き込む（可逆。電源断で消える）

書込み前にTab5を `disarm`、描画中でないこと。`programmer_cli` は `fpga/build/tools/gowin-programmer-1.9.12.04/` 等（引継ぎ資料6章）。`<img>` は展開した `.fs`。

```
programmer_cli.exe --scan-cables
programmer_cli.exe --device GW2A-18C --operation_index 2 --cable-index 1 --frequency 2.5MHz --fsFile <img>.fs
programmer_cli.exe --device GW2A-18C --operation_index 73 --cable-index 1 --frequency 2.5MHz
programmer_cli.exe --device GW2A-18C --operation_index 74 --cable-index 1 --frequency 2.5MHz
```
- USERCODE（index 73）が各イメージの記録値と一致し、Status（index 74）が `0x6020` であること。一致しなければ以降に進まない。
- SPI flashには書かない（operation 2はSRAM）。書込み直後の「Error found!」は既知で、USERCODE・Statusが一致すれば読戻しは正しい（引継ぎ資料6章）。
- **1イメージごとに、前のイメージの影響を残さないためDockの電源を入れ直す**（FPGAの電源断でSRAMも消える。DDR3の内容も初期化後に再校正される）。

## 3. 試験手順（各イメージで同じ。1回の試行で止める）

作業ディレクトリはホストリポジトリ `D:/github/airpocket-soundman/tab5-fpga-gpu`。

### 段階1：読取り専用（`probe_mem_scheduler_diag.py`）
BISTは起動せず、設定・START・CANCEL・RECALも送らない。
```
python tools/probe_mem_scheduler_diag.py --execute --port COM4 --expected-elf-sha <ELFのSHA-256> --record <出力>.json
```
- `--execute` を付けない場合は計画の表示のみ（UARTに出ない）。
- 記録する値：capability `024f`、`calibrated`、`command_ready`、`data_ready`、`scheduler_init_done`、`pre_info_valid`、`refresh_request`、コマンドFIFOの状態。
- 参考：`be42c604` の段階1は、capability 024f、calibrated=1、command_ready=1、data_ready=1、scheduler_init_done=1、pre_info_valid=0で終了した（`fpga/validation/hw-ddr3-2026-11-04/stage1-024f.json`）。**新イメージで値が変わったかを比べる。**
- 段階1で`calibrated`が立たない、または`024f`が返らない場合は、そのイメージで停止し、段階2に進まない。

### 段階2：64ビートBIST（`probe_mem_bist.py`、**破壊的**）
段階1が上記を満たしたイメージだけで行う。DDR3の先頭1024B（base 0、64ビート）を書き換える。
```
python tools/probe_mem_bist.py --execute --port COM4 --base 0 --count 64 --expected-elf-sha <ELFのSHA-256> --output <出力>.json
```
- `--count` は128ビットのビート数（バイトではない）。再校正は自動では行われない。`--recalibrate` は明示した場合だけ。
- 合格：error 0、`verified_beats`=64、`mismatching_beats`=0。
- 失敗：受理コマンド数・受理書込みデータ数、コマンドFIFOの`write pointer`／`read pointer`／進行数、`send_wr`のhigh cycles、`refresh_request`、`pre_info_valid`を記録して**そこで止める**。再送・再試行・自動再校正はしない。続けて段階1と同じ読取り（`--record`）でも失敗後の状態を保存する。
- 合格後の段階3以降（パターン、境界、容量alias、連続転送、soak）は `docs/MEM_ペア書込み候補.md` 6章に従う。**1イメージで合格するまで、他のイメージは試さない。**

## 4. 試す順序

1. 電源・VREF／VTT・嵌合（1.）。測定値が異常ならイメージ切り分けより先に直す。
2. 基準 `be42c604` を同じ条件でもう1回、電源の入れ直しから試す（再現するか。**この回は段階2を実行する前に、段階1の値が前回と一致するかを確認する**）。
3. (d) `refwait` → (c) `rst` → (b) `cs0` の順（いずれもホスト変更不要。効果が最も小さい変更から。順序は目安で、1つ合格したら以降は止める）。
4. (a) 400MHz：イメージとホスト変更が揃ってから。
5. すべて同じ形（read pointer 0、`send_wr` 0）で失敗した場合は、イメージ内の要因ではなく物理個体（電源・VREF／VTT・実装・部品）か、IP設定とDRAM部品の不一致を疑う。**ただし、疑いの段階であり、確定ではない。**

各試験で次を `fpga/validation/` に残す（BIN／FS のSHA-256、USERCODE、ホストELF SHA-256、書込みログ、段階1・2のJSON、電源測定値または「未測定」）。失敗した試験を成功点として使わない。原因は、観測が揃うまで「未特定」と書く。

## 6. ビルド方法（Gowin環境がある場合）

前提：Gowin Education 1.9.11.03（`gw_sh`）、Python 3、OSS CAD Suite（iverilog／yosys）。いずれも本資料作成時点でこのPCには未導入だった（`gw_sh` が見つからない。Standard 1.9.12.04はライセンスが必要で`gw_sh`が失敗すると `DDR3準備調査_2026-11-04.md` に記録済み）。

```powershell
gw_sh fpga/mem/config/generate_ip.tcl                       # MemDDR3.vo（SHAが4d37c875…か確認）
python fpga/mem/tests/prepare_deep_taps.py
python fpga/mem/tests/run_tests.py --iverilog <iverilog.exe> --vvp <vvp.exe> --zig <zig.exe> --primitive-lib <gw2a/prim_sim.v>
python fpga/mem/tests/prepare_guarded.py
python fpga/mem/tests/prepare_variant.py all
$env:MEM_BIST_GUARDED='1'; $env:MEM_VARIANT='cs0'; gw_sh fpga/mem/config/build.tcl
```
`MEM_VARIANT` を設定すると、ソースは `fpga/build/mem-variant-<id>/rtl/`、出力は `fpga/build/mem-variant-<id>/out/` になる。STAは setup／hold／recovery／removal のネガティブ一覧が空であることを確認する（基準は setup +0.106、hold +0.234、recovery +1.364、removal +0.580ns）。FSのSHA-256とUSERCODEを記録する。
