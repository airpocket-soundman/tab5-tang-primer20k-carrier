# 頂点モデルのFPGA常駐（MODEL_* v1）

2026-11-04。ブランチ `claude/track-b-fpga`（基点 main `03eb39a`）。実験仕様。ピン・電圧・既存コマンド・`link_protocol.h` は変更していない。**実機（FPGA書込み・Tab5）では未検証**。RTLシミュレーションとホストCコーデック試験のみ合格。

## 目的と位置づけ

ポリゴンの時間の大半は、命令の往復と、毎フレームの頂点座標の再送にある。下の「既存の効果の整理」のとおり、一括送信（`TRI_BATCH`）とCSR振分けで短縮したが、640×360の高負荷ポリゴンはCPUの約5倍遅い（CPU 113.865ms／FPGA 555.140ms）。

本仕様は、頂点とインデックスをFPGAのブロックRAMへ**1回だけ送り**、毎フレームは姿勢（回転・並進・投影）の32バイトと、タイルごとの8バイトの描画要求だけにする。変換・投影・タイル判定をFPGA側で行い、既存の三角形エンジンへは `TRI_BATCH` と同じ「10個の設定命令＋DRAW」の形で渡す。エンジン・フラグメント・深度比較・top-left規則は変更しない。

読み取れること：
- 一括化で命令往復は大きく減ったが、**要求の本体（毎フレームの座標、HEAVYで約70.8KB）はそのまま**で、帯域を上げても比例して短縮しない。
- 「グローバルな投影済みリスト常駐」では640 HEAVYの記録が70,820 → 34,560バイトに減るだけで、座標は毎フレーム変わるため、ゼロ転送にはならない（ホスト側の設計メモの評価）。本仕様はこれを超えて、**変換自体をFPGAに移す**ことで毎フレームの要求を数十バイトにする。

## 受け入れの前提（互換性）

- ホスト現行の描画（`tab5-fpga-gpu-demo`）は、浮動小数点の sin／cos と投影の結果をQ12.4へ量子化してからFPGAへ送る。**この浮動小数点の変換を、本仕様の整数変換へ黙って置き換えることはできない**（ホストの設計メモ）。MODEL_*を使う場合は、CPU側も同じ整数変換（`fpga/host/triangle_model.h` の `model_project`）で描画し、同一の式で比較する。浮動小数点版との画素一致は主張しない。
- 既存のopcode・応答・`INFO` の値は変更しない。能力は `MODEL_CAPS`（0x48）の成功でのみ判断する。LINK／TRI_BATCHだけのイメージは未知opcodeとして status2 を返す。
- ESP-IDF以外（MeOS、Linux）には、この拡張を使うドライバが無い。能力問合せで有効なイメージにだけ使う設計で、他ホストへの影響はない。MeOS・Linux側の物理転送バックエンドは別作業。

## コマンド

opcodeは実験用の暫定値（`0x42`〜`0x44` は `TX_CAPTURE` が使用中のため避けた）。要求は既存の8バイトヘッダ（`a5 op seq 02 a b crc16`）。bit7のタグ付き応答は既存どおり。

| opcode | 名前 | ヘッダ引数 a／b | 本体 | 成功応答 r4／r5 |
|---|---|---|---|---|
| 0x48 | MODEL_CAPS | a=0：頂点上限、a=1：三角形上限。b=0 | なし | a=0：64／1（版）、a=1：96／0 |
| 0x49 | MODEL_LOAD | a=頂点数（1〜64）、b=三角形数（1〜96） | 頂点`6×a`バイト＋三角形`6×b`バイト＋CRC2 | a／b |
| 0x4a | MODEL_POSE | a=0、b=1（版） | 32バイト＋CRC2 | 有効頂点数／頂点数 |
| 0x4b | MODEL_DRAW | a=tile_x、b=tile_y（32px単位） | なし | 描画した三角形数／スキップ数 |

状態コード：0成功、1 CRC不良、2未対応、3引数不正、5未準備（モデル未ロードまたは未POSE）。ヘッダが不正（個数範囲外、版違い）なら本体を送らずに通常の8バイト応答で拒否する。

### MODEL_LOAD の本体

- 頂点：`x, y, z` を各 int16 リトルエンディアン（6バイト／頂点）。
- 三角形：`i0, i1, i2`（各1バイト、頂点インデックス）、予約1バイト（0）、`color` uint16 LE（6バイト／三角形）。
- CRC16/CCITT-FALSE（初期値 0xffff）。対象はヘッダ先頭6バイトと本体全体（既存 `TRI_BATCH` と同じ作り）。
- 範囲外のインデックスや予約バイトが0でない場合は、CRCが正しくても status3 で拒否する。
- **ロード開始時にモデルを無効にする**。CRC不良・引数不正で終わった場合も無効のまま（メモリは部分的に書換わっている可能性があるため）。成功すると「ロード済み・未POSE」になる。

### MODEL_POSE の本体

16個の int16 LE（32バイト）：回転3×3（行優先、Q2.14）、並進3（tx, ty, tz、モデル単位）、focal、center_x、center_y（Q12.4）、depth_shift（0〜15）。16以上は status3。

**変換（ビット単位で固定）。** 頂点 `(mx, my, mz)` に対し、

```text
cam_r  = floor((R[r][0]*mx + R[r][1]*my + R[r][2]*mz) / 2^14) + t[r]      (r = x, y, z)
有効   = cam_z >= 1
sx     = center_x + trunc(focal * cam_x / cam_z)      ゼロ方向への切捨て除算
sy     = center_y + trunc(focal * cam_y / cam_z)
有効   = 有効 && sx, sy が int16 に収まる
depth  = min(cam_z >> depth_shift, 65535)
```

- `floor` は算術右シフトと同じ（負の値は小さい方へ）。`trunc` はC言語の整数除算と同じ。
- 無効な頂点（カメラの後ろ、オーバーフロー）を含む三角形は、DRAWでスキップする（スキップ数に計上）。ニアクリップによる三角形の分割は行わない。
- 全頂点を変換して画面座標RAMへ書く。完了後に応答する。POSE開始時に「POSE済み」を解除し、CRC不良・未ロード（status5）・引数不正（status3）では解除したまま。

### MODEL_DRAW

指定タイル（32×32画素、原点 `tile_x*512, tile_y*512` のQ12.4単位）について、三角形をモデル順に処理する。

1. いずれかの頂点が無効 → スキップ（計上）。
2. タイル相対座標 `sx − tile_x*512`、`sy − tile_y*512` が int16 に収まらない → スキップ（計上）。
3. 保守的な境界箱テスト：3頂点すべて `x<0`、または `x>511`、または `y<0`、または `y>511` なら、**このタイルの画素中心（最小8、最大504）を覆えない**ので何も出さない（計上しない）。
4. それ以外は、`AX, AY, BX, BY, CX, CY, ZA, ZB, ZC, COLOR` の10個の設定命令（0x21〜0x2a）と DRAW（0x2c）を既存エンジンへ順に発行する。深度比較・同値の扱い・クリップは既存のまま。

CLEARと読出し（`TILE_READ` 0x3b）は従来どおりホストが明示的に行う。DRAW前に必ずCLEARすること。DRAW中のエンジンエラーは、その statusで応答を打ち切る（部分描画のタイルは表示しない）。タイムアウトやARM解除はバッチと同じく中断し、タイルを無効にする。

3では、スキップした三角形が画素を一つも変えないので、全三角形を送る場合と**同じ画素**になる（試験で確認）。

### 帯域の見積もり

640×360（20×12タイル）の高負荷フレームの要求バイト数（設計値、実測ではない）。

| 方式 | 要求バイト／フレーム | 備考 |
|---|---|---|
| 従来（`TRI_BATCH`＋CSR） | 約70.8KB（ホスト記録の値）＋バッチ見出し | 座標を毎フレーム送信 |

## 未検証・今後

- **実機未検証**：FPGAへの書込み、Tab5からの実通信、LCD表示、実測の時間内訳。MODEL_*を含むビットストリームの配置配線・タイミング・資源使用率。

- 頂点法線・ライティング、複数モデル、DDR3への拡張は別作業。

## 実機で確認してほしい手順（親の作業）

1. `MODEL_ENABLE=1` を指定したtop（例：整形返信系 `tab5_dock_triangle54_filtered_top` を複製し `.MODEL_ENABLE(1)` を追加）でビルドし、配置配線・タイミング・資源を確認する。
2. 書込み後、`MODEL_CAPS` が成功することを確認する（LINK／batchのみのイメージでは status2 になる）。
3. 立方体（8頂点・12三角形）をLOAD→POSE→タイルごとにCLEAR→DRAW→TILE_READで読み戻し、ホストで同じ整数変換から生成した期待値と全画素比較する。
4. 640×360の全タイル（240）で全画素比較し、1フレームの時間内訳（POSE、DRAW、TILE_READ）を従来方式と比較する。
5. 失敗時は再送や自動的な従来方式への切替えをせず、停止して記録する。
