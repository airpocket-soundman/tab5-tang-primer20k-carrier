# Optional complete-tile streaming readback (2026-11-03)

Design compatibility reviewed before implementation. This is an optional Dock diagnostic extension; it changes no pins, power, existing commands, training prefix, or existing INFO values. Hardware performance remains unverified until the new image is tested.

Reviewed host references: ESP-IDF original `tab5-fpga-gpu` README/Project_B at `d4d89e308b4a8aa799199b20e7d47c96b536e3fd`; actual development checkout `tab5-fpga-gpu-demo` README, Project_B, `main/fpga_backend.cpp`, `main/dock_gpu.cpp`, and DMA/build validation notes at `f8e978f3127e15200942305dc6b5f2aa8bc4f937` plus current working changes. Linux README, `docs/DEVELOPMENT_GOALS.md`, actual `linux/dts/easystick-stamp-p4.dts`, and communication-source search at `cfc9a6ecf7daa4c5e3decbe3885b22c2bd2f4cd1`; MeOS README, `docs/FPGA_CARRIER_REQUIREMENTS.md`, and communication-source search at `26c8082961b1152901475fb56bbb2e8be192a4da`; external-memory research plan `docs/Project_A_P4_Linux_FPGA_Virtual_MMU.md` at `e4aa69d09b2643d6f62fe686ef0f3284b109c541`. Linux/MeOS have no TRI_ROW/common row-validator implementation found in the reviewed C/H/DTS sources; complete-tile support is unimplemented there. Their existing low-speed LINK behavior is unaffected. Host adoption requires an explicit capability query and updated common codec, not a transparent change to old ROW reads. ESP-IDF integration is being updated in the development checkout; its final carrier pin is recorded by the host integration commit.

- `0x3c TILE_CAPS`: zero arguments; result `0x0103`: version1, bit0 color, bit1 depth. Invalid arguments status3. Other images return existing unknown-command status2. Existing TRI_INFO2020, FRACTAL_INFO0107 and LINK_CAPS0108 stay unchanged.
- `0x3b TILE_READ`: a=0, b=plane (0 color,1 depth). Requires initialized tile; otherwise status5. Invalid arguments status3. Success result bytes `{0,plane}`. Error replies remain ordinary8-byte frames.
- Success body: normal8-byte header including its CRC; 2048 payload bytes, 32 rows ×32 words in row-major order, each16-bit word little-endian; then CRC16/CCITT-FALSE over header bytes0..5 followed by the entire payload. Total2058 bytes. Tagbit7 adds existing8×c3 outside both CRCs, giving2066 wire bytes. DMA may capture body+16=2074 bytes; these extra capture bytes are idle transport margin, not additional protocol bytes. Require exactly one contiguous CRC-valid body, never reconstruct missing bytes.

RAM is streamed from the existing synchronous color/depth arrays without a full response copy. The link blocks commands/writes while READY holds the response; its synchronized clock advances the byte index and CRC once per accepted physical rising edge. Header/prefix time permits initial prefetch; each next word must settle before the next host sample. At27MHz and5MHz response clock, timing must be validated by RTL phase tests and routed timing; no higher frequency is implied. ARM/reset immediately remove output drive as before.
