# Dock応答クロックのRTL評価

2026-11-03。現行の27MHz sys_clkで動くLINK同期回路を、デジタルRTLモデルで評価した。
配線・ジャンパ・PCBの波形、電圧、反射、クロストーク、メタステーブル、ジッタはモデル化していない。
本結果を実機の安全な通信速度やケーブルの上限として使わない。

要求は従来どおりsetup/HIGH/LOW各1us以上で送り、応答だけ5/8/10/20MHzへ変更する。
ホストは物理CLKをHIGHへ切り替える直前に、その時点の旧データをサンプリングする。
sys_clkは1ps精度で周期37,037ps（公称27MHz）。最初の応答サンプルをsys_clk立上がりから
0/5/10/15/20/25/30/35nsずらす。固定の片道遅延を0/5/10nsの3条件とし、
送信CLK/DIR/dataと受信data/READYへ同じ値を仮定する。これらの遅延値は測定値ではない。
タグ付きID16byteと、CLEAR1234後のタグ付きROW82byteについて全byteと応答完了を照合した。

| 応答クロック | 合格 / 条件数 |
|---|---:|
| 5MHz | 48 / 48 |
| 8MHz | 32 / 48 |
| 10MHz | 0 / 48 |
| 20MHz | 0 / 48 |

8MHzは仮定した片道遅延0/5nsで全条件が一致し、10nsでは全条件が不一致だった。
5MHzは全位相・仮定遅延で一致することを基準条件として自動チェックする。
高周波数での失敗はテスト自体の失敗扱いにせず、どの条件で応答の順番が崩れたか記録する。

現行回路は外部CLKを3段へ取り込み、同期した立上がりをsys_clkで判定して応答を進める。
この経路では物理CLKの立上がりから応答更新までおおむね2〜3 sys_clk周期を要し、
次のホストサンプルまでに出力と往復遅延が収まる必要がある。さらに短いHIGH/LOWでは
同期回路が外部パルス自体を取り逃す。PCB配線を改善しても、このデジタル同期経路の制約は残る。
より高速な物理リンクには、専用の外部クロック同期I/OやFIFO、CDC・タイミング制約を含む設計変更が必要。
このテストはそのような新フロントエンドを実装・検証したものではない。

実行は`fpga/link/tests/run_response_frequency.py --iverilog PATH --vvp PATH`。
192条件とソースハッシュは[response-frequency-model-2026-11-03.json](../fpga/validation/response-frequency-model-2026-11-03.json)を参照。
FPGA RTL、ピン、電源、コマンド仕様は変更していない。実機のCRC/画素照合と別の結果として扱う。
