# 残り5シーン（Wire・Particles・Galaxy・Fire・Flow）の汎用SIMD演算器への移植設計

2026-11-04、トラックL（`claude/track-l-scenes`）。**実機・RTL・合成・配置配線には触れていない。** 以下の数値はすべて、本リポジトリの研究用ISAシミュレータ（`fpga/reference/scene_isa*.py`）上の命令数・メモリアクセス数で、クロック数・fps・FPGA資源量ではない。

## 1. 方針と結論

方針（ユーザー要求）: **シーンごとの専用opcode・専用回路を入れず、GFX全般に使える汎用GPUにする。** そこで各シーンを共通の計算プリミティブへ分解し、汎用SIMD演算器（`fpga/gfx/compute/`、別セッションで開発中・メインチェックアウトで未コミット。ISAは加減乗算、Q12乗算、符号付き比較、bit演算、shift、LOAD/STORE、条件分岐。本作業では読むだけで編集せず、`import`もしていない）上のプログラムとして書いた。

結論（すべてCPU整数参照と全画素一致を確認。§6）:

| シーン | 基本ISAのみ | 拡張要望ISA | 主な不足 |
|---|---|---|---|
| Particles | 書ける（20.3命令/粒子） | 14.5命令/粒子 | 即値形式、ブロードキャストload |
| Wire | 書ける | 命令数-35% | 符号なし比較、等値、選択、即値 |
| Fire | 書ける（g0とビット一致。173.5命令/画素） | 98.5命令/画素 | 任意shiftの64bit積、レジスタ数 |
| Flow | 理論上は書ける（除算をソフト展開、約16倍） | 実用域 | **DIV**、ISQRT、ブロードキャストload、レジスタ数 |
| Galaxy | **書けない**（同一画素への加算が競合） | 書ける | **ATOMADD**（メモリ原子加算） |

専用回路にしなくても5シーンとも表現でき、`fire_pixel.v`（既存の専用回路）と同じオラクル `fire_g0.py` に汎用プログラムが全画素ビット一致した。ただし**汎用プログラムは専用パイプラインより1〜2桁遅い**（Fireは1画素あたり98.5〜173.5命令。4レーンなら約25〜43クロック/画素の命令数。専用回路との実測比較は未実施）。性能面の採否は、実RTLの実サイクル測定と合成結果が出てから判断する（§7）。

### 3.1 各シーンのカーネル構成

- **Fire**：画素1要素=1レーンの直線プログラム1本（オクターブ数分を展開）。出力はRGB565を1画素1wordでSTORE。
- **Particles**：粒子1要素=1レーン。ハッシュ→角度・半径→sin/cos表→座標→3×3スプラット9回STORE。
- **Galaxy**：(1) 星1要素=1レーンで位置を計算し ATOMADD（packed R|G<<10|B<<20）。(2) 画素1要素=1レーンの解決パス（accと静的背景+中心グローを加算→各チャネルを255で飽和→RGB565、accを自己クリア）。
- **Wire**：(1) 立方体1要素=1レーンで8頂点の変換（頂点バッファへSTORE）。(2) 辺1要素=1レーン（立方体あたり16レーン、うち4つは無効）でBresenham。
- **Flow**：(1) 減衰（全画素）→ (2) 粒子更新（2サブステップのRK2、障害物への射影、範囲外の再出現、線描画、頭の点、状態書戻し）→ (3) トレイルを表示面へコピー（全画素）→ (4) 障害物円の上書き（128×80の矩形、無効マスクつき）。

## 5. g1整数定義とfloat版の違い（画素一致しない点）

- 共通: 座標は整数/固定小数点（Q4／Q12）、三角関数は4096点Q12 sin表（`cos=sin(i+1024)`）、パレットは256点のLUT（`n&255`。float版は`n*9%224`等の剰余）、乱数は粒子番号等のstateless hash（float版の逐次LCGは並列化不能のため）。
- **Fire**: 差なし。`fire_g0.py`（Q16、g0）そのもの。g0自体がfloat版の`fire()`と画素一致しない（ノイズhash・係数が異なる）ことは既存の記載どおり。
- **Particles**: 角度=(hash&0xFFFF)>>4 ＋ frame×125>>4（0.012rad/frame≒7.8インデックス/frame）、半径=20＋((hash>>16)×69>>15)。x半径は×1.75（float版1.7）。座標が必ず画面内に入るため範囲検査を省略（理由は半径の上限157.6px）。
- **Galaxy**: 星表（半径・初期角・Kepler角速度・色種別・追加グロー）は**初期化時にホストが`sqrt/exp`で作る整数表**（毎フレームのプログラムにはsqrt/expは入らない）。float版は画素ごとに量子化し直しながら加算するが、g1はpacked 10bitフィールドで蓄積し、最後に一度だけ飽和（0以上の加算は順序に依らないので結果は同等だが、10bitフィールドの桁あふれ＝同一画素に約6星以上は未対策）。中心グロー・背景はホスト作成の静的画像。
- **Wire**: 立方体中心はホスト表、回転は§3.1の計算、1/depthは3072点の逆数表（`depth>>3`で引く）。float版の`int()`（0へ切り捨て）ではなく算術右shift（床）。範囲検査あり。
- **Flow**: 位置Q12、速度場の`factor=R²/rr²`を`k=(R²<<12)/rr`と`q=((dx²-dy²)>>9<<12)/(rr>>9)`の2回のDIVに分解、渦4本の位置・強度は**フレームごとにホストが計算**してPARAMに置く、障害物中心は整数(269,180)、色は粒子番号&3の4色。

## 6. 検証方法と結果

CPU整数参照は、シミュレータとは別に素のPython整数で書いた（Fireは既存の`fire_g0.py`）。**全画素**を比較している：

- Fire 640×360（4オクターブ）: 基本ISA版・拡張版とも0画素不一致。
- Particles 512／2048／8192、Galaxy 1024／4096／16384、Wire 16／64／144（辺のループを含む）: 全画素一致。
- Flow 512（12フレーム）、2048（2フレーム）、8192（1フレーム）: 画素と粒子状態（PX/PY）が一致。再出現・障害物射影・渦経路を通ったこと（例: 8192粒子で再出現27、障害物射影216、渦評価19,072）をカバレッジとして記録。
- 基本ISAに展開したマクロ（DIV、ISQRT、MULSH16、LTU、ABS、MIN、MAX、SHR、EQ、OR）を、乱数入力2048件で拡張命令版とPython式の双方と照合（`micro_tests`）。

**書込みの競合順序について。** 同一画素へ別々のレーンが書く場合、結果は書込み順で決まる。ISAの契約（群内はレーン番号順、群は逐次）に従い、参照も「群→（ステップ）→レーン」順で書いている。したがって**競合画素の出力はレーン数に依存する**。Wire／Particles／Flowの参照はレーン数を引数に取り、4レーンで確認した（1・2レーンでは未確認）。GPUとしては、同一画素への複数書込みの順序を保証するか（レーン直列は現契約）、順序非依存な表現（Galaxyの原子加算、深度比較）にするかを決める必要がある。

## 7. 足りないISA機能（`compute-simd-ext` への要望）

**根拠の数値は静的命令数（拡張フルONからその機能だけ外したときの増分、ループは1反復分）と、実行時メモリ数。** 優先度は、必要性（それがないと書けない）→効果の大きさの順。

| 優先 | 要望 | 根拠 |
|---|---|---|
| 必須 | **ATOMADD** `[a+imm] += r[d]`（レーン直列でよい） | Galaxyが書けない。LOAD→ADD→STOREでは、LOAD命令が全レーン分終わってからSTORE命令が走るため、同一群の2レーンが同じ画素を指すと一方の加算が失われる。 |
| 必須 | **DIV**（符号付き32bit除算）または逆数命令 | Flow粒子カーネル：基本ISAで10,550命令中8,872（84%）が除算のソフト展開。速度場だけで1粒子フレームあたり28回（障害物射影でさらに最大4回）。 |
| 高 | **ブロードキャスト（uniform）load／スカラ定数レジスタ** | 全レーン共通のframeや渦パラメータを、レーンごとに別々にLOADしている。Flow粒子は13/16、Fireは1/1、Particlesは1/4のLOADがこれ。群あたり1要求にすればLOAD数は1/4（4レーン）〜1/L。 |
| 高 | **レジスタ数の拡張（32本）またはスピル機構** | 同時生存の最大が27（Fire拡張）〜57（Flow粒子）で13本を大幅に超過。スケジューリングで縮めても足りるかは未検証。 |
| 高 | **任意shift付き64bit積（MULQS `d,a,b,#sh`）またはMULH** | Fire：177/394命令（拡張フル）。基本ISAでは16bit limb分割で1回約15命令（Q16の補間とsmoothstepで多用）。MULQ（Q12固定）ではQ16のg0を書けない。 |
| 高 | **即値形式のレジスタ演算**（ADDI／ANDI／SHLI／SARI／SHRI／MULI／LTI） | 即値形式がないと命令数が+6%（Fire）〜+28%（Particles）。かつ定数をレジスタに置く必要がなくなりレジスタ圧も下がる。 |
| 中 | **SHR（論理右shift）** | ハッシュ（`x>>15`等）：Fireで36命令、Particlesで7命令。基本ではSAR＋AND(mask)の2命令＋定数レジスタ。 |
| 中 | **LTU（符号なし比較）** | 画面範囲検査`unsigned(x)<W`が1命令に。Wire辺カーネル8、Flow粒子12命令。 |
| 中 | **EQ／NE** | Bresenhamの終了判定。基本ではSUB＋NEG＋OR＋shift。Wire辺8、Flow粒子16命令。 |
| 中 | **SEL**（`c? a : b`）、**MIN／MAX／ABS** | 線の傾き符号、飽和。SELはWire辺6・Flow12、MIN/MAXはFireのclampなど。 |
| 低 | **OR** | 今回は互いに素なbit幅のため`ADD`で代用でき、効果0。ビット合成が必要な将来用途向け。 |
| 低 | **ISQRT** | Flowの障害物射影のみ（115命令、該当レーンは約1%）。除算が入れば逆数＋近似でも代替可。 |

演算命令以外の要望（ISAではなくメモリ側・演算器構成）：

1. **16bit書込み（half-word／write mask）**：フレームバッファはRGB565だが、今回は1画素1wordで書いた。16bit書込みなら画面メモリの書込み量が半分になる。
2. **ブロックコピー・フィル**（DMAまたはadapter）：Flowの「トレイル→表示面コピー」は全画素のLOAD→STOREで3命令/画素（691,200群命令/フレーム）使う。画面クリアも同様。演算器でなくメモリ側の操作として切り出せる。
3. **LOAD/STOREのbaseアドレス**：immが16bitで、フレームバッファのアドレス（今回は131072以降）に届かない。Wireの画素書込みで毎反復`ADD`が1命令増える。基底レジスタ（セグメント）か、広いimmが欲しい。
4. **競合STOREの順序契約の明文化**（§6）。
5. **発散の抑制**：Bresenhamループはレーン稼働率0.81（Wire）、Flow粒子は0.76。群内で線長が揃うように、辺／粒子をソートするか、ループを群単位で再整列するバケット機構は後段の課題。

DSLで効いていない最適化（ISA要望ではなく、次の作業）：ANY分岐による稀な経路のスキップ（Flowの障害物射影は全群で毎回実行している。実際に該当する群は約5%）、画素アドレスのインクリメンタル更新（Bresenham）、頂点の共通部分の巻上げ。
