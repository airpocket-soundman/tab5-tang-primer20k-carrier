# PoC目的への独立評価とD1分岐の実修正

日付：2026-10-24。変更前：`f47f28fa714dfb23843b7516e887ca90acdd0f14`。この評価の変更後は固定コミット `047538febbbf98b8758caa1441b386347c2afe14`。当時のmanifestも同コミットから参照する。最新の電源・パラレル通信修正と発注準備は [PoC発注準備](PoC発注準備_パラレル通信と電源_2026-10-24.md) を参照。

## 結論

**720p60のHDMIを短いケーブル・限定モニタで試す少数PoCとして、較正済みの全Core 3D解析を発注前の必須条件にする必要はない。一方、現状をLinux/GPU共通キャリア全体の製作合格とは判断しない。** 通信の実装、電源断時の信号隔離、実装部品・実物との機構照合が未完了だからである。HDMIの受動伝送推定の合否だけで、この基板の本来の目的は判定できない。

先行作業の「再配置に失敗したのでD1Nの11.5mm分岐を残す」という判断には同意しなかった。配線そのものと隙間の寸法を調べ、**R30/R31を0402に変更してESD後の配線間へ移し、P/Nとも0.585mmの表面分岐へ修正した。** 主差動配線、ESD銅ストラップ、Tab5 GPIO、Coreピン割当は変更していない。

## 2. 自分で確認し、変更したこと

### D1の分岐を残す必要はなかった

ESD後のD2N/D1P間とD1N/D0P間には、中心線間1.17mmの隙間がある。標準0402ランドの高さ0.64mmなら、幅0.2mmの主配線に対する片側の銅間隔は約0.165mmとなり、設計ルール0.127mmを満たす。0603では同じ置き方が困難だった。

R30を(110.3,16.75)、R31を(110.3,18.25)へ横向きに配置。信号パッドから同じ面の主配線へ0.585mmで分岐し、各GNDパッドから0.69mmの配線で0.6/0.3mmの貫通ビアへ接続した。ビアをはんだランド外に置き、穴埋めビアを不要にした。信号分岐のビア4本を除去した。0402の499Ω実装品番は発注時に選定が必要で、未確認のLCSC番号は記入していない。

粗い格子の自動配線では最終配置の隙間を通せなかった。`shorten_d1_bias.py` で主配線を維持した局所修正を行い、`make_pcb.py` にも「従来位置で配線後に最終配置へ変更する」工程を組み込んだ。全体再生成も実行し113ネット配線・DRCゼロを確認した。GNDビアをランド外へ逃がした最終局所修正も、変更前コミットのPCBから再現してDRCゼロを確認した。採用PCBには、無関係な配線を変えない局所修正版を使用した。

### 同じモデルを使った前後比較

モデル式・Core100Ω・ESD差動0.35pF等を固定して比較したため、以下の差は今回の配置・分岐変更による。値は推定で、測定ではない。

| 指標 | 変更前 | 変更後 |
|---|---:|---:|
| D1分岐 P/N | 6.574 / 11.494mm | 0.585 / 0.585mm |
| D1 SDD11最悪、～1.5GHz | −12.863dB | 約−17.3dB |
| 全4ペアのSDD11最悪、同帯域 | −12.863dB | −16.061dB、D2 |
| 全4ペアのSDD21最悪、740MHz計算点 | 約−0.880dB | 約−0.880dB |
| Core Z×ESD容量の9条件で−10dB自主目標を外れる数 | 2 | 1 |
| 残る最悪条件 | Core85Ω・ESD0.5pF、D1：約−7.944dB | 同条件、D2：約−9.376dB |

D1のSCD21が数値床まで下がるのは、左右対称としたモデル内の結果である。実部品の容量差、Core内スキュー、ランド・ビア・近傍配線の結合等を含めてモード変換がゼロになった証明ではない。D0の9.1mm分岐等も残るため、「すべての499Ω分岐が数mm以下になった」とは言わない。

### 検査と実データの対応

- 最終PCBのDRC：違反0、未配線0。ESDランド検査127項目、8線の銅導通・期待ピン、全配線の分類・幅・ビア方針を再確認した。
- ESDストラップを各1本除く8ケースで、対象線だけの不連続を検出した。
- 既存のESD・分類回帰24件を更新基板で再実行した。
- 新たなD1検査は実PCBの短い信号分岐と近傍GNDビアを確認する。正常、信号分岐除去、近傍GNDビア除去、抵抗GNDの誤接続の4ケースで期待通り判定した。
- 回路図とBOMも0402へ変更した。生成器と採用PCBの変更箇所が一致するようにした。

## 3. 2Dと3Dの扱いは、どこまで妥当か

**不一致を理由に3Dを誤りと決めて廃止することは妥当でない。較正未達の3Dを、今回の少数PoCの合否には使わず保留することは妥当である。**

既存 `openems_lib.py` は全周MUR境界と垂直lumped portを使用し、`pml_cells` 引数は境界へ反映していない。差動ペアを単線の励振・測定から評価する場合は、ポート基準、差動換算、終端条件の一致を別途確かめる必要がある。[openEMS公式のポート説明](https://docs.openems.de/en/latest/concepts/ports.html)も、複数導体の差動線路でlumped portの励振場が適さない場合を説明している。これは不一致の原因候補であり、原因特定済みという意味ではない。公式ページはオンラインで確認したが、HTMLのローカル保存はHTTP403で失敗したため、取得成功とは記録していない（`docs/reference/openems/sources.json`）。

今回の主差動配線はF.Cuなので「全層を表面線路で近似」という制限が主配線の全区間を誤った層で扱うことを意味するわけではない。ただし残る内層分岐、ビア（今回のGND帰路を含む）、パッド遷移、接点、Coreの偶奇モードは十分に同定されていない。2Dを正解とした3D調整もしない。

次に3Dを採用する条件は、同一断面の単線・均一差動対で、両端ポートの基準面、差動/単線インピーダンス、メッシュ細分化、終端・境界、残留エネルギーを揃え、自己収束を確認すること。全Core再構築より先にこの小さい問題を解く。既存スクリプトが指定するopenEMS実行環境はこのPCの指定パスに存在せず、今回は新たな3D計算を完了していない。

720p60は742.5Mbps/線で、通常1080p60の1485Mbpsとは要求が異なる。640×480で表示確認後、720p60へ進める。一方、低解像度でも高速エッジの局所反射が消えるわけではなく、反射の観察帯域をNyquist一点へ縮めない。自主目標−10dBをHDMI認証の合格値とは呼ばない。

## 4. 目的に対して未満足な点と、こちらで修正できる範囲

| 項目 | 私の判断 | 修正可能性・進め方 |
|---|---|---|
| D1の長い非対称分岐 | 改善すべきで、放置理由は不十分だった | **今回、PCB・生成器・回路図・BOM・解析まで修正済み** |
| Core CLKの説明 | SODIMM80→K13/IOT36Aは一般I/O。GCLKT_1はK14。従来コメントは誤り | **コメント訂正済み**。ピン変更を即断する根拠はない。現行GPUの受信wrapperはsys_clkで取り込む例で、専用CLK入力の有無だけで成立を決められない。40MHzを達成したとは扱わず、実際のRTL・制約・STAで判断する |
| 片側電源断・独立FPGA電源スイッチ | **未合格**。15本の直結33Ω線に電源断時の隔離がない。Hi-Z指示や33ΩはIoff保証の代わりにならない | 回路・PCBへの隔離素子追加は対応可能。ただし8bit双方向とCLK/DIR/READY/AUXの方向、両電源の検出、既定OEをまとめて設計し直す必要がある。今回のHDMI局所修正で解決した扱いにしない |
| 電源保護・実装品番 | TVSが選定前、複数部品もgeneric。12～24V全域の安全性は未確認 | 12V等へ試験入力を限定し、選定TVSの最大クランプと降圧IC・入力C定格を照合する作業は対応可能。未選定のまま24V可とは判定しない |
| 物理通信と性能 | Linux/GPUとも実配線の通信は未確認 | プロファイル・制約・試験RTLや低速CRC試験の準備は可能。実機なしに双方向通信、DMA、13.8MB/s、DDR3全域アクセスを合格にはできない |
| HDMI送信RTL | D2は赤、符号化後10bit全体の極性反転が必要。受動モデルだけでは送信器を確認できない | RTL・シミュレーションの作成は可能だが、このキャリアには完成した対象トップがない。専用の送信トップ、制約、合成/STA、実機表示が必要 |
| 実装・機構 | コネクタ向き、汎用スイッチ、ESDランド、0402品番を注文データで確認する余地が残る | CAD/資料照合は可能。現物との嵌合・手持ちTab5との干渉の最終確認は現物が必要 |

33Ωへ理想的に約3Vが加われば抵抗だけからは約90mAという桁になる。実電流は内部保護や電源回路にも依存するため、この値を実測電流とは扱わないが、33Ωを無電源入力の保護保証にできないことは明確である。

**製作の判断**：HDMIの3D未完了だけで少数試作を止める必要はない。まず、独立電源断を含む通常操作まで許す試作にするなら、信号隔離を設計してから発注する。隔離を省いた電源常時同時供給の限定実験にする場合も、起動・停止中の端子電圧/電流確認が必要で、独立電源スイッチを自由に操作できる製品状態とは区別する。今回の変更はこの残件を隠して製作承認を出すためのものではない。
