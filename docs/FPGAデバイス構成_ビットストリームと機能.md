# FPGAデバイス構成：ビットストリームと機能

2026-10-28、計画。RTL・合成・実測はない。ホスト（ESP-IDF、MeOS、NOMMU Linux）はどれも全機能を使う前提とする。分担は[リポジトリ分担と参照ルール](リポジトリ分担と参照ルール.md)。

## 資源の前提

GW2A-LV18PG256（Tang Primer 20K Core）：LUT4 20,736、FF 15,552、BSRAM 46個・828Kbit（約103KB）、18×18乗算器48個（9×9/18×18/36×36対応）、PLL 4個（DS102E Table 1-1、Sipeed Datasheet V1.0）。Core上にDDR3 128MB、SPI NOR Flash 32Mbit（MSPI端子M9/L10/R10/P10）。

## ビットストリーム

| 名称 | 内容 | HDMI | RAMdisk |
|---|---|---|---|
| LINK | リンク試験（v0/v1）、DDR3 BIST、誤り・帯域カウンタ | なし | なし |
| GFX | 共通基盤＋fill/copy/blit/glyph、三角形ラスタライズ、Zバッファ、フラクタル等の計算描画 | **既定で搭載** | 既定で搭載 |
| NPU | 共通基盤＋INT8 MAC配列（汎用：構成A）、またはモデル専用（構成B/C） | なし | 既定で搭載 |
| MEM | 共通基盤＋ブロック単位DDR3格納、copy/fill、CRC | なし | 主機能 |

共通基盤＝リンク物理層、プロトコル処理、DDR3コントローラ、READ/WRITE、監視。各機能に加え、どのビットストリームも共通のID／能力問合せに答える。

既定は計測前の第一案である。各機能の単独版も同時にビルドし、下記の判定で共存を見直す。GFXとNPUは乗算器・BSRAM・DDR3帯域を取り合うため同時搭載しない。

### 共存の判定

- RAMdisk：回路は共通基盤のREAD/WRITEとほぼ同じ。DDR3領域を固定で分け、アクセラレータ実行中はRAMdisk転送を止められるようにする。FPGA DDR3は明示的に読み書きする外部ストレージであり、LinuxメインRAMの透過増設ではない。
- HDMI：rPLL 1、OSER10×4、ラインバッファ用BSRAM数個、スキャンアウトによるDDR3読出し（RGB565で640×480@60約36.9MB/s、1280×720@60約110.6MB/s）、高速クロックのタイミング制約。
- 同条件で単独版とオプション付き版を比べ、資源使用率、Fmax、性能（GFX：fill/copy MB/s、三角形数/秒、フレーム時間。NPU：層ごとの遅延・FPS）、リンク実効帯域を測る。性能が5〜10%以上低下、タイミング未達、またはMAC数・タイル寸法・並列度の削減が必要になる場合は分ける。閾値は初回計測後に確定する。

## GFXの表示経路

1. HDMI：FPGAがDDR3から直接スキャンアウト。パラレルリンクの帯域を使わない。
2. Tab5内蔵液晶：FPGAがDDR3に描画→PARLIO RX＋DMAでP4のバッファへ読み戻し→P4既存のMIPI-DSIドライバで表示。拡大・回転はP4のPPAを使う。FPGAから液晶への直接配線はない。

| 条件 | 必要帯域 | 8bit×40MHz理論40MB/sとの関係 |
|---|---|---|
| 1280×720 RGB565 30fps全画面 | 約55.3MB/s | 超過 |
| 640×360 RGB565 30fps全画面 | 約13.8MB/s | 理論上は範囲内（目標値） |
| 変更領域のみ | 内容依存 | GUIでの基本方式 |

両経路を同時に使うとDDR3読出しを取り合うため、GFX＋HDMIの判定ではHDMI有効時の液晶読戻し速度も測る。FPGAが有利になるのは、P4での描画時間がFPGA描画＋読戻し＋コマンド転送の合計より長い場合（フラクタル、DDR3常駐モデルの多数ポリゴン等）。単純な2D処理はP4のCPU/PPAで足りる見込み。いずれも未実測。

## NPUの構成

| 構成 | 重みの置き場所 | 制御 | 対象 |
|---|---|---|---|
| A 汎用 | DDR3。ホストからupload | 層ごとのジョブをホストが投入 | 任意のモデル（対応演算の範囲内） |
| B モデル専用シーケンサ | DDR3。電源投入時にFPGAがCoreのSPI Flash（またはmicroSD）から展開 | 層順序・形状・タイル寸法・量子化パラメータを回路に固定。ホストは入力upload・開始・出力downloadのみ | WholeBody25 Nなどの中規模モデル |
| C 重み内蔵 | ビットストリーム内（BSRAM ROM初期値、LUT定数） | 層ごとのストリーミングパイプライン。定数乗算のシフト加算化、零重みの省略 | BSRAMに収まる小規模モデル |

- WholeBody25 N 128×160：初期化テンソル2,419,064 bytes（FP32、定数を含む）、Conv 186個・61,063,640 MAC（tab5-fpga-gpu `docs/model-audit/wholebody25-n-128x160.json`）。INT8重みは単純換算で約0.6MBでBSRAMに収まらないため構成Bで扱う。
- 構成Cは特徴マップのバッファにもBSRAMを使うため、INT8重みは数万パラメータ程度と見込む（未合成の見積り）。4bit/2bit量子化は精度評価を必須とする。大規模モデルの先頭数層だけを構成Cとし、残りを構成Bで処理する併用も検討する。
- 構成Bの未確認事項：ビットストリーム書込み後のFlash空き領域、ユーザー回路からMSPI端子を読む設定、重みイメージの形式・CRC・書込み手順。
- 比較：同一モデル・同一入力でP4 CPU実装（esp-dl等）、構成A、構成B/C。前処理・転送・FPGA計算・後処理・表示を分けて測り、資源使用率、Fmax、精度も記録する。モデル評価（ONNX監査、量子化精度）はtab5-fpga-gpuで行う。
- モデルごとに別ビットストリーム。構成Cは重み変更に再合成が必要。構成BはFlash上の重みイメージ差替えで同じ層構造の重み更新に対応する。DSP数とDDR3帯域の上限は構成によらず同じ。
