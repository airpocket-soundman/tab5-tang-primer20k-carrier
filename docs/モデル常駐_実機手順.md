### B. 54MHz系（実機の主力）

- OSS版 `triangle54model`（`build_oss.py triangle54model`）は**54MHz目標に不合格**（最大 約43.6MHz）。参考として既存の `triangle54fast`（MODELなし）も同じ環境で不合格（約44.7MHz）。つまり不合格はMODEL追加が原因ではなく、OSS flowが54MHzを満たさない既存の状態で、MODELによる低下は約1MHz。資源はLUT4 7,807（37%）、BSRAM 9。このためOSSの54MHz像は実機に使わない。
- **ベンダー版（基準線 `85bac224` と同じ流れ）は2026-11-04にGowin EDA Education V1.9.11.03（gw_sh）で作成済み。** トップ `tab5_dock_triangle54_filtered_model_top`（`MODEL_ENABLE=1`）。基準線のCDC例外SDCはソースSHA一致が前提のため（`link_bringup_filtered.v`が変わったので`source drift`で停止した）、次の2段で作り直した：
  1. `gw_sh fpga/builds/dock/build_filtered_model_stage1.tcl`（CDC例外なし。hold違反29はmetadata非同期first-stageのみ＝基準線の1段目と同じ性質）
  2. `python fpga/tools/qualify_metadata_cdc.py --sdf <stage1 SDF> --output fpga/validation/filtered-model-cdc-proof-2026-11-04/structure.json` → `generate_metadata_cdc_constraints.py`（`constraints/dock/triangle54filtered_model_cdc.sdc`、例外はstage0 D側30本ちょうど）→ `gw_sh fpga/builds/dock/build_filtered_model.tcl`
  - 結果（`fpga/validation/filtered-model-vendor-2026-11-04/manifest.json`、全STA・SHA入り）：STA setup/hold違反0（パス29,662、エンドポイント9,342）。最小slack setup +1.554、hold +0.198、recovery +2.505、removal +0.895ns。metadata stage0→1は30/30本（setup +17.198、hold +0.539）。Fmax：core54 60.597（基準線69.593より低い）、conditioned54 81.064、sampler216 341.427MHz。Logic 27%、Register 21%、BSRAM 8/46、DSP 14.5/24。
  - **FS SHA-256 `81232e415bea555d74885cde893144d6b3aa3bb9d4063fad281b64a723b42e17`、USERCODE `0x00009678`（基準線 `85bac224…` とは別物）。** 書込み・実機動作は未実施。CDC例外集合はこのネットリストで再証明したが、ピアレビューは未実施。ベンダー版エンジン（`triangle_tile_vendor.v`）でのRTL試験は未実施（RTL試験は`triangle_tile.v`）。

## 実機での試験手順（メイン作業）

1. 書込み前にTab5を`disarm`、ホストを`stop`。基準線のFPGAは電源断で消える（SRAMのみ）。
2. 作ったイメージを `programmer_cli`（`--operation_index 2 --cable-index 1`）で書込み、USERCODEとStatus（0x6020）を確認（既存手順どおり）。イメージのSHA-256とUSERCODEを記録する。
3. Tab5ファームを `claude/track-k-model-host` からビルドして書込み。
4. まずGPIO接続の低速イメージ（A）で：`link action=model enabled=true` → `arm` → `step`。`status`で`model_negotiated`・`model_resident`、`model_used`、`model_*_count`を確認。
5. `tools/compare_dock_demo.py` に `--model on --scenes 1 --loads 0 1 2 --frames 17 --repeats 2`（通信オプションは使うイメージに合わせる。基準線（B）なら基準線の例から `--triangle-batch on --tile-bins on` を除き `--model on` を足す）。合格条件：全画面一致、`wire_accounting.passed`、`model_skipped_triangles=0`。
6. 失敗は再送・従来方式への切替をせず停止して記録する。`MODEL_CAPS`がstatus2なら、イメージが`MODEL_ENABLE=0`である。
7. 一致後に1フレームの時間内訳（`model_load_ms`、`model_pose_ms`、`model_draw_ms`、`tile_read`）を従来方式（`--triangle-batch on`）と比較。POSEをタイルごとに再送するため、仕様の見積もり（約2KB／フレーム）より要求バイト数は多い。性能向上は実測するまで主張しない。

## 未検証・残課題

- 実機でのMODEL_CAPS／LOAD／POSE／DRAW、CPUとの全画素一致、時間。
- ベンダー版54MHzイメージは作成・STA合格まで（上記）。実機での動作は未検証。OSS版の54MHzは不合格。
- ホストファームのESP-IDF v5.5.2ビルドは成功（下記）。実機動作は未検証。
- 深度の向き（上記）。ポーズ再送を減らす設計（インスタンスごとに全タイルへ1回、または複数姿勢の保持）。

### 手順（Tab5・Dockには試験担当のメインセッションだけが触れる）
1. 既存手順でTab5を`stop`・`disarm`。`.fs.gz`を展開し、基準線と同じ`programmer_cli`で書込み、USERCODE=`0x00009678`とStatus（0x6020）を確認（SHAを記録）。
2. ファームをesptoolで書込み（上記3ファイル、0x2000/0x8000/0x10000）。
3. 基準線の再現（まず、MODELを使わない既存確認）：`docs/triangle-batch-host.md`（ホストリポジトリ）の基準線コマンドで`--triangle-batch on --empty-tiles on --tile-bins on`が従来どおり通ること。新しいイメージでの回帰確認（`MODEL_ENABLE=1`でも既存コマンドは不変のはず）。
4. モデル試験（立方体 LOAD→POSE→DRAW をCPU整数参照と全画素比較）。基準線の通信設定のまま`--triangle-batch on --tile-bins on`を`--model on`に替える（併用は拒否される）：

```
python tools/compare_dock_demo.py --port COM4 --half-ns 25 --setup-ns 25 --guard-ns 2000 --dma-rx-hz 20000000 --dma-scope bulk --readout tile --rx-mode continuous --rx-sample-edge negative --stream-profile scaled_1024x4 --tx-mode persistent_dma --tx-scope batch --tx-route fixed --tx-hz 5000000 --tx-phase positive --model on --empty-tiles on --scenes 1 --loads 0 1 2 --frames 17 --repeats 2 --echo-count 513 --output <out>.json
```
5. 合格条件：全画面RGB565一致、`wire_accounting.passed`（LOAD 130B／POSE 42B の要求バイト数照合）、`model_skipped_triangles=0`、`model_negotiated`・`model_resident`真。最初の失敗で停止し、再送や従来方式への切替はしない。`MODEL_CAPS`がstatus 2なら`MODEL_ENABLE=0`のイメージが載っている。
6. `FPGA.state.model_{load,pose,draw}_ms`と従来方式の時間を比較（POSEのタイル毎再送により、バイト数は仕様の見積もりより多い）。
7. 注意：深度の向きにより立方体の裏面が表に出る（CPUと同じなので比較は成立。見た目の隠面処理は未解決）。`--rx-sample-edge negative`は基準線構成（brief指定）。基準線のコマンド例にはこのフラグが無いので、もし通らなければ省略版との差として記録する。
