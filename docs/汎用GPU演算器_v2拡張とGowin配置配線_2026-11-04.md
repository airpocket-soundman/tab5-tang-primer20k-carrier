## 2. v2のISA追加（opcode 27〜45）

形式は従来のまま（opcode[31:26], pred[25], dst[24:21], a[20:17], b[16:13]/imm16[15:0]）。不正opcodeは46以上。

| opcode | 命令 | 意味 |
|---|---|---|
| 27 ADDI / 28 MULI / 29 LTI | d,a,simm16 | 加算・乗算（下位32bit）・符号付き比較(0/1) |
| 30 ANDI | d,a,imm16 | `r[a] & zero_ext(imm16)` |
| 31 SHLI / 32 SARI / 33 SHRI | d,a,imm[4:0] | 左／算術右／論理右shift |
| 34 LUI | d,imm16 | `imm16 << 16`（下位0）。LUI+ADDIで32bit定数 |
| 35 SHR | d,a,b | 論理右shift（bの下位5bit） |
| 36 LTU / 37 EQ / 38 NE | d,a,b | 符号なし比較／等値／不等値（0/1） |
| 39 OR | d,a,b | bit OR |
| 40 SEL | d,a,b | `r[d]≠0 ? r[a] : r[b]`（条件は書込み前のr[d]） |
| 41 MULSH | d,a,b,sh | `(r[a]*r[b]) >>> sh` の下位32bit。shは命令の下位6bit(0..63)。MULHは32、Q16積は16 |
| 42 DIV / 43 REM | d,a,b | 符号付き32bit、0方向への切捨て。x/0=-1、x%0=x、INT_MIN/-1=INT_MIN・余り0（RISC-V規約）。レーン直列の復元除算で1レーンあたり約33クロック |
| 44 ATOMADD | d,[a+imm16] | wordインデックス。読出し→`+r[d]`→書戻しをレーン順に1レーンずつ行う（別レーンの同一アドレスも失われない）。戻り値なし。メモリ要求は read, write の2本 |
| 45 LDU | d,[a+imm16] | ブロードキャストload。**レーン0のr[a]**でアドレスを作り1要求だけ発行、結果を有効な全レーンのr[d]へ。有効レーンが無ければ要求なし |

飽和はしない（wrap32）。共通規則（述語、レーン順直列、エラーコード）は従来どおり。ATOMADD/LDUはwordアドレスで、LDB系のbyteアドレスとは別。

### 2.1 任意要素数dispatch

入力ポート `element_count`（0=従来動作＝1グループ・全レーン有効）。`element_count=N>0` のとき、ハードが `ceil(N/LANES)` 個のグループを順に実行する。グループごとにレジスタを初期化（r1 = `base + 累積lane数 + lane`）し、同じ`entry`から再開する。最後のグループで `id` が範囲外のレーンは**無効**：何も実行せず、メモリ要求を出さず、`ANY`の投票にも加わらない。プログラム側のr15は触らない（ハードのvalidマスク）。`instruction_limit`と`instructions`は全グループ通算。`groups`出力でグループ数を取得。エラーはそこで全体を停止（以降のグループは実行しない）。各グループ開始に16クロックのレジスタ初期化が入る。

### 2.2 書込み競合の順序契約（明文化）

群内はレーン番号順、群間は実行順。同一アドレスへの複数STOREは**最後に実行されたレーンが勝つ**。したがって競合画素の結果はレーン数に依存する。レーン数に依存させたくない蓄積はATOMADD、順序非依存な選択はMIN/MAX、で表現すること。

## 3. メモリadapterとburst設計

### 3.1 `rtl/compute_mem_adapter.v`（実装済み）

演算器のmem/rspインターフェースとバックエンド（DDR/BRAMのwordインターフェース）の間に置く。

- **領域検査**：`REGIONS`個の `[base, limit)`（word）と読み/書き許可。外れたら**バックエンドへ出さず**即`rsp_error`（`violations`加算）。
- **timeout**：`timeout_cycles`（0=無効）経過してもバックエンドが応答しなければ`rsp_error`（`timeouts`加算）。受付済みならその要求は**orphan**になり、遅れて来た応答は破棄。orphanが残る間は新しい要求を受け付けない（順序保証）。バックエンドがbe_readyを出さないままtimeoutした場合は要求を取り下げる。
- **job境界drain**：`flush`で、保持中の応答を捨て、実行中の要求はorphan化する。ホストはジョブ起動前に`flush`を1クロック入れる。古い応答が次ジョブに混入しない。
- 限界：orphanに永久に応答しないバックエンドはリセットまでadapterを塞ぐ（試験でそのとおりstallを確認し、coreとadapterとバックエンドの同時resetで復帰）。バックエンドのhold-until-accept規約はtimeout取下げ時のみ破る。tag/IDは持たない（1要求ずつ）。
- 試験（`tests/tb_system.v`、2レーン）：normal／領域外STORE／バックエンドエラー(レーン0・1)／遅延応答でのtimeout＋次ジョブ(late response破棄)／永久無応答（stall→reset→再実行）の7シナリオを、ジョブA→Bの2連続実行でメモリ全体まで照合。

### 3.2 burst / coalescing 設計（**未実装・設計のみ**）

現状は1要求=1word、レーン直列。DDR3はBL8（128bit×…）が最小単位に近く、1wordずつだと帯域が大きく無駄になる。

1. **要求の拡張**：`mem_len`（1/2/4語）を追加。同一命令でレーンのアドレスが連続（`addr[l+1]=addr[l]+1`）かつ先頭がアライン、かつ全レーン有効なら、1つのburst要求に結合する。条件に合わなければ現行の直列にフォールバック。
2. **書込み**：wmaskは語ごと。連続STORE（RGB565のSTH連続、ATOMADDは対象外）を結合。
3. **応答**：burstは`mem_len`語を連続してrspで返す。演算器側はレーンごとのスキャッタを順に受ける。
4. **adapterでの結合（演算器を変えない案）**：adapter内の小さな書込みバッファで隣接STOREを結合する案も可能だが、読出しの順序保証（read-after-write）が複雑になるため、まず演算器側の明示burstを推奨。
5. **期待効果の根拠なし**：効果は未計測。DDR3 PHY・実バックエンドが無いオフライン環境では帯域を測れない。実機DDR3測定後に採否を判断する。
6. **ブロックコピー/フィル**：演算器の命令ではなく、adapterに置くDMA（src,dst,長さ）が妥当。Flowのトレイルコピー（全画素 LOAD→STORE）などが対象。未実装。

## 4. Gowin EDA 1.9.11.03 による配置配線・STA（実測）

ツール：`D:/Gowin/edu-x/Gowin_V1.9.11.03_Education_x64/IDE/bin/gw_sh.exe`（Education版）。デバイス `GW2A-LV18PG256C8/I7`（device version C）。STAの遅延モデルは setup=Slow 0.95V 85℃ C8/I7、hold=Fast 1.05V 0℃。

ハーネス（重要な限界）：コアのポートが多くPG256に出せないため、`tests/pnr_top.v`（入力を1本のシフトレジスタ、出力を全bitのパリティ1本に縮約）で包んだ。ラッパのFF（約400）を含む。実機のトップ・実ピン・PLLではない。クロックは`clk`ピンH11、制約は`create_clock`のみ（入出力遅延なし）。27MHzはDockの発振器相当、54MHzは2倍想定を制約値として置いただけで、PLLは構成していない。各1回の実行で、seed探索はしていない。

|---|---|---|---|---|---|---|---|
| v2 1レーン | 3810 (18%) | 3510/300 | 1061 | 1 | 2(1) | **Fmax 36.8MHz、違反0** | **Fmax 43.0MHz、setup違反128端点(TNS -381.7ns)** |
| v2 2レーン | 7580 (37%) | 7113/467 | 2160 | 1 | 4(2) | **Fmax 31.1MHz、違反0** | **Fmax 39.2MHz、setup違反2146端点(TNS -10503ns)** |

- 27MHzでは1/2レーンとも収まる。54MHzは**未達**。クリティカルパスは命令メモリ(BSRAM出力)→デコード→オペランド選択→ALU→レジスタ書込みの組合せ経路（論理段13〜15）。Gowinの最適化は制約が厳しいほど努力するため、27MHz実行側のFmax（36.8/31.1）は、54MHz実行側の値（43.0/39.2）より低く出ている。**達成可能Fmaxの目安は両者のうち良い方（1レーン約43MHz、2レーン約39MHz）程度**で、これ以上は実行ごとのばらつきで未確定。
- ホールド違反は0。実機ピン遅延・入出力制約・温度/電圧マージンは未評価。
- 4レーンは今回実行していない。
- 比較のためのv1（byte/halfword追加まで）：Gowin合成で1レーン3458、2レーン5957 LUT+ALU（54MHz制約でFmax 54.0 / 46.0MHz）。v2は命令追加で約+10〜27%。

経緯（正直な記録）：v2の最初のRTL（レジスタファイルのFFごとに複数の書込み源とグループ初期化の全レジスタ同期クリア）は、Gowin合成で1レーン13688（67%）、**2レーンは26594でデバイス上限20736を超え収容不能**だった（ログ `fpga/validation/compute-simd-gowin/v2-before-regfile-rework-2lane-does-not-fit.log.txt`）。原因はレジスタファイルの書込み経路。書込みを「レーンごと1ポート＋共有インデックス」に統一し、グループ開始を16クロックのCLEARシーケンスにして同期クリアをなくした後の値が上表（約3.5分の1に縮小）。この手直し後に同じ試験を再実行し合格している。

保存物：`fpga/validation/compute-simd-gowin/<構成>/`（`pnr-report.txt`、`timing-report.html`、`.cst/.sdc/run.tcl`）。ビットストリームは生成されたが保存せず、書込みもしていない。yosys/nextpnrによる前回の試行（v1）は[拡張ISA設計](汎用GPU演算器_拡張ISA設計_2026-11-04.md)の§4。
