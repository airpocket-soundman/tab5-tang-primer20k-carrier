Claude開発計画と進捗

2026年11月4日（日本時間）。Claude会話記録の計画・担当依頼と、回収済み18ブランチのソース・試験記録を照合した。

進んだ点：フィルタ＋一括送信の統合候補を実機で確認し、性能内訳と失敗条件を整理した。モデル常駐RTL、CRC高速化、キャリア制約生成、Fire部品などの実装も追加された。
未達：20MHz超の安定通信、DDR3読み書き、常駐モデルの実機動作、残り5シーン、ポリゴンのCPU超え、最終アプリ。作業数を完了率に換算すると実機未検証を過大評価するため、段階ごとに示す。

Claudeが立てた計画

当初の10項目を、次の並行トラックへ組み替えていた。計画提示は11月4日05:36、使用量制限による停止報告は06:29（会話UTCから日本時間に変換）。

当初の区分進め方
A：計測と基盤比較条件を固定 → 残るDMA固定費を削減。初期化1回化だけで完了としない。
B：命令側の効率化一括送信 → BRAMにモデル保持 → 共通演算 → 全8シーン。小モデルはDDRを待たない。
C：通信周波数25MHz以上を時間枠付きで検証。往復削減と並行し、周波数調査で全体を止めない。
D：メモリDDR3単体を他と独立して検証 → 動作後に蓄積・二重バッファ。
統合・仕上げプロトコル/ホスト影響を記録、Gowinタイミング照合、検証済み成果をmainへ統合、最終デモ・レポート。

途中から担当名A〜Pへ細分化し、CRC、エッジ診断、モデルのホスト統合、中間周波数、位相、NPU見積もり、DDR別候補を追加した。物理機器は親セッションが操作し、子担当はオフライン作業という分担だった。計画・停止報告の抜粋と担当依頼の見出し。

高速化で分かったこと

Track Fの同一条件によるDMA比較では、コピー削減は全画素一致を維持したが、改善は約1〜2%で対照のばらつきに近い。TXリセットのpolicy2は最初のバッチで失敗し、policy0へ戻している。単純にリセットを消す方針では成功していない。

ポリゴン高負荷の描画約568msの内訳はTX77ms、READY待ち136ms、RX121ms、方向切替11ms、その他ホスト約223ms。ホスト項目のcodec91ms、prepare51ms、yield20ms、assembly15msは内訳の一部で、追加で総時間へ加算しない。CRCとPSRAM処理は改善対象だが、CRC単独が全体最大の原因と確定したわけではない。

新CRCはPC試験とビルドまで。PCでの約4.9倍をP4や描画全体の倍率に使えない。新しい基板で何倍になるかも、外部IOタイミングと高周波数の実測がないため未算定。

  2. Kのコンパイル失敗、Mのlease試験失敗を解消し、既存の全画素比較を再確認する。
  3. IのCRCベンチと重複CRC省略をP4上で比較。PSRAMクリア・組立ての時間も分離する。
  4. J/Nの診断をRTL・CDC・配置配線で確認してから、Mと組み合わせて20〜25MHz帯を1変数ずつ測る。
