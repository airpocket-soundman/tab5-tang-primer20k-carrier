# リポジトリ分担と参照ルール

2026-10-28 制定。ユーザー指示により、キャリア基板とFPGAデバイス（全ビットストリーム）の仕様・実装を本リポジトリで一元管理し、ホストOSの各リポジトリはそれを参照してホスト側を開発する方式に改めた。

## 変更の理由

ESP-IDF、MeOS、NOMMU LinuxのいずれもGFX、NPU、HDMI、RAMdiskの全機能を使う。FPGA側は複数ホストが共有する1つのデバイスであり、ピン・プロトコル・RTLを用途別リポジトリに分散させると、基板改版やコマンド変更のたびに食い違いが生じる。

## 役割

| リポジトリ | 管理するもの | 管理しないもの |
|---|---|---|
| **tab5-tang-primer20k-carrier（本リポジトリ）** | 基板設計、共通ハード仕様、ピン割当と.cst/.sdc（キャリア用・Dock用）、リンクプロトコル、FPGAソース（共通基盤、LINK、GFX、NPU、HDMI、RAMdisk）、ビットストリーム構成、コマンド仕様と使い方、FPGA側のテスト・参照モデル、ホスト共通のプロトコルcodec（C参照実装、予定） | 各OSのドライバ、アプリ、OSビルド |
| tab5-linux-fpga | NOMMU Linux本体、FPGA通信ドライバ、Device Tree、ユーザ空間ツール | FPGAソース |
| tab5-meos-fpga | MeOSのFPGAドライバ（HAL/LL PARLIO＋GDMA）、GUI統合 | FPGAソース |
| tab5-fpga-gpu | ESP-IDFのホスト実装、GPU LABベンチマーク、モデル評価（ONNX監査、量子化評価） | FPGAソース（既存RTL部品は移管対象） |
| esp32p4-linux-fpga-memory | Linux外部メモリ研究の計画、評価方法、測定結果 | FPGAソース |

## 参照ルール

1. ホスト側リポジトリは、従うデバイス仕様の版（本リポジトリのコミットSHAまたはタグ）を記録する。仕様コピーを収録する場合は参照用スナップショットと明記し、SHAを併記する。
2. ホストは起動時にID／能力問合せ命令で、ビットストリーム種別・版・有効機能を確認してから機能を使う（命令の定義はv1で確定する）。
3. 本リポジトリで仕様・コマンド・ピンを変更した場合は、影響するホスト側リポジトリへの反映の要否を確認し、反映した版を本書または該当仕様に記録する。
4. DMA、割り込み、待ち処理などOS固有の実装は各ホストで行う。フレーム形式、CRC、コマンドのエンコードは本リポジトリの定義に従う。

| 各リポジトリ収録の共通ハード仕様コピー | 本書の方針で更新していない。スナップショットとして扱う |
