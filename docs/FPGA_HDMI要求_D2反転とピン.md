# FPGA側のHDMI(TMDS)要求：ピン対応とD2の極性反転

作成：2026-10-24（第2レポート監査 A5）。RTL／CST（Gowin制約）を作る担当への要求。基板の接続は `kicad/core_pin_assignment.csv` と `kicad/sim/check_continuity.py` が検査する。

## 1. ピン対応（Core SODIMMピン ↔ HDMI Type-A）

| TMDS信号 | ネット名 | Core SODIMMピン | Coreの端子名 | HDMIコネクタ(J5)ピン | 備考 |
|---|---|---|---|---|---|
| D2+ | HDMI_D2P | **56** | TX5_N | 1 | **P/N入替**（下記） |
| D2− | HDMI_D2N | **58** | TX5_P | 3 | **P/N入替** |
| D1+ | HDMI_D1P | 68 | TX3_P | 4 | |
| D1− | HDMI_D1N | 70 | TX3_N | 6 | |
| D0+ | HDMI_D0P | 130 | TX2_P | 7 | |
| D0− | HDMI_D0N | 132 | TX2_N | 9 | |
| CK+ | HDMI_CKP | 140 | TX1_P | 10 | |
| CK− | HDMI_CKN | 142 | TX1_N | 12 | |

TX4は、公式のCore配線長表でN側が1.9mm短いため使用していない。

## 2. D2の極性反転（意図した設計）

D2（赤データ）はCore側のピン配置の都合で、**HDMIのD2+がCoreのTX5_Nピン、D2−がTX5_Pピンに接続**されている（基板配線上のP/N入替）。FPGAは次のいずれかで補償する。

- TMDSエンコード後、シリアライザ（OSER10/OSER8系）へ渡す前の**10ビット符号語（またはシリアルビット列）の全ビットを反転**する。RGBの画素値を反転するのではない。
- または、TX5の差動出力バッファの極性を反転できる機能があればそれを使う（Gowin GW2Aの出力バッファでは、IO論理レベルの反転ではなく、**シリアルビットの反転**で補償するのが確実）。
- **D2のみ**。D1・D0・クロック（CK）は反転しない。クロックの反転は不可（位相が変わりDC成分・同期に影響する）。

確認方法：極性補償忘れは、不正なTMDS符号、表示欠落、同期・リンク不良などとして現れる可能性があり、単純な色反転とは限らない。色だけで診断せず、エンコーダ出力・シリアル化・物理P/Nの対応を確認する。

## 3. CST（制約）の書き方の方針

- 差動ペアは、PINを `*_P` と `*_N` に分けるのではなく、**Coreのピン表の端子名を基準**に、ネット名から機械的に生成する。TX5はP/Nの割当てがHDMI信号と逆であることをコメントに残す。
- 電圧：HDMI用TX1/2/3/5のバンクは3.3V（真のLVDS出力を使わず、TMDS 3.3V互換のI/O標準を使う場合は仕様を別途確認）。
- 最終ネットリストから作るピン対応表（P4 GPIO・SODIMM・FPGA端子・バンク電圧）は、MeOS側の要求（`FPGA_CARRIER_REQUIREMENTS.md`）の項目として別途確定する（本書の範囲外）。

## 4. 検査

`check_continuity.py` は、上表のSODIMMピンとHDMIコネクタピンへ各信号が実際に接続されていることを（P/Nの見た目の上下ではなく）ピン番号で検査し、不一致なら終了コード1で失敗する。

## 5. RGBと符号語の検証要求（R3-03対応）

基準は収録したSipeed公式 `docs/reference/tang-primer-20k/official-hdmi/video_top.v` の `O_tmds_data_p[2:0] = {r,g,b}`。端子名の数字と色の対応を固定する。

| 画素入力 | エンコーダ | TMDSチャネル | Coreの物理差動出力 | HDMIコネクタ | 符号語の極性補償 |
|---|---|---|---|---|---|
| R | red | D2 | TX5（基板上でP/N入替） | 1(+),3(-) | 10bit全体を反転 |
| G | green | D1 | TX3 | 4(+),6(-) | なし |
| B | blue | D0 | TX2 | 7(+),9(-) | なし |
| ピクセルクロック | clock | CK | TX1 | 10(+),12(-) | なし |

RTL実装時には次を自動検証する。

1. 黒・白・赤・緑・青の単色とカラーバーを与える。参照エンコーダの色入力と各チャネルの接続を比較し、画素値を補償のために反転していないことを確認する。
2. 映像有効期間は、D2の10bit出力が参照符号語の全ビット反転、D1/D0は参照符号語そのものであることを確認する。シリアルのビット順・DDRのエッジも検査する。
3. ブランキング／制御期間でも同じD2極性補償を適用する。データ期間だけを反転して制御符号を反転し忘れる実装を拒否する。
4. 物理接続のP/N入替を模擬した受信側で、D2の符号語が参照へ戻り、D1/D0/CKに補償が加わらないことを確認する。
5. 補償を意図的に外した負の試験が失敗することを確認する。実機の色の見た目だけをテストの合否にしない。
