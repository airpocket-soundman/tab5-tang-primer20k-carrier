## 4. 残る指摘と完了条件

### A1【高・発注前】ESDの信号経路をPCB銅配線で連続させる

`gen/design.py` はU4/U5の1→10、2→9、4→7、5→6を内部通過させる接続のまま。C293965/DOWO資料は反対側端子をNCとしており、文書上の訂正では解消しない。

**完了条件：** 選定メーカー・型番・端子表・フットプリントを一致させ、各TMDS線を銅で連続配線＋ESDシャント接続にするか、導通保証された別部品へ変更。部品内部の素通しを仮定せず、入力からHDMI端子まで8線の接続を確認し、DRC/ERCとネットリストも再確認する。

### A2【高・発注前】抵抗枝の短縮とCKN枝の抽出漏れを修正する

今回、**コミット済み入力だけ**から `order_segments(tc.segs(...))` を検査したところ、`HDMI_CKN_C` は38区間・平面合計61.357mmで、隣接区間の**26か所が0.06mm超の不連続**だった。他の23ネットではこの検査の不連続は0だった。

**ここでいう不連続は、解析用に並べた区間リスト上の座標の飛びを指す。PCBの回路が26か所切断されているという意味ではない。** 本来別に扱う抵抗枝が混在し、一本の主経路として正しく抽出できていないというモデル化の不備である。PCB DRCは未配線0。ESDのNC端子による導通懸念（A1）は、これと別の問題として扱う。

原因は、CKNの抵抗枝が `stub_tracks.json` に未収録のままで、枝を含む区間集合を並べ替えていること。`order_segments()` は到達できなかった区間を末尾へ無条件追加するため、検出・停止しない。さらに `profile()` はP線をサンプリングし、N線の近傍距離を参照するだけなので、CKNの余分な枝全体の電気的影響を表現できない。

**完了条件：** 抵抗を分岐点近傍、目安1～2mm・少なくとも数mm程度へ寄せ、P/N対称にする。主経路と抵抗までの枝をPCB接続から別々に抽出し、8本すべての枝長を記録する。枝を除外する主経路の判定と、枝の負荷を回路モデルへ入れることは別作業。未到達区間はエラーにし、無条件追加で隠さない。

今回の「他23ネットで不連続0」は、この入力・この距離検査に限る。最小x始点と近接だけで接続する方式が、層替えや将来の再配線でも常に正しいという認定ではない。対象パッドと層接続を端点にして確認する。

### A3【中・発注判断資料】長さ・スキューを一つの定義へ統一する

`tmds_summary.json` のD0長53.245mmに対し、`tmds_sparam.json` の区間合計は58.245mmで**5.000mmの差**がある。他のペアでも同様。前者はルータ出力の `pair_lengths.json` で合計を上書きし、後者は抽出した銅区間を積算するためである。現行レポートはこれらを併記し、スキュー0.00mmも固定記述している。

**完了条件：** パッド中心/パッド端、部品内部、ビア垂直長、Coreを含む/含まない、枝除外を明記し、実PCBからP/N各経路を計算する。ルータの設計値と実配線確認値を分ける。約0.135mmという前回のCK差だけを理由に再蛇行する必要はないが、「実配線4組とも厳密0.00mm」を確認済みとはしない。

これらは数値の捏造を示すものではなく、モデルの範囲と監査可能性を改善する指摘である。

## 5. 開発セッションでの推奨作業順

1. **回路・配線を修正**：A1の導通、A2の抵抗配置を先に解決。較正途中の3D解析を先に完成させる必要はない。
2. **実PCBから再抽出**：全8線の端点、主経路、枝、ビア/層を確認。不連続・未到達区間があれば止める。長さをルータ値で上書きしない。
3. **簡易チャネルを再計算**：499Ωの有限負荷、短い終端枝、採用ESD容量の妥当な仮定を入れる。Core100Ω・38.4mmは基準ケースとし、85/115Ω等は保証範囲ではない感度ケースとして扱う。720pの実速度と観察周波数を分ける。
4. **記録を一体化**：PCB・部品定義・解析入力・結果・レポートを同じ変更版へ揃え、検証した仮定、残すリスク、低速フォールバックを記載。
5. 電源・逆給電・機構・コネクタ向き等の基本確認後、**少数試作へ進む**。実機は低速テストパターン→720p60、短いケーブル・指定モニタで30分程度。PARLIOは別に低速ID/CRCから段階評価する。

新しい数値に厳しい一律基準を追加して試作を止める意図はない。**接続上の欠陥と大きい未モデル化部分を直し、720pを狙う合理的な根拠を作ること**が今回の発注前条件である。
