# Dock三角形タイル走査の最適化

2026-11-03。GPU LAB接続後の実機比較で、三角形ごとに32×32全画素を
走査する処理が残っていたため、走査範囲を頂点のバウンディングボックスへ限定する。
これは三角形GFX内の演算時間の改善であり、通信ピン、電源、opcode、CRC、
パラメータ、画素包含・Zバッファの数値規則を変更しない。

各頂点のsigned16bit Q12.4座標について、x/yの最小値・最大値を算術右シフト4で
負の無限大方向へ整数化する。範囲を0..31へクリップしてから5bitアドレスへ狭める。
最大座標側を含む保守的な範囲なので、境界外の候補が残る場合もあるが、
最終的な画素包含判定には従来のtop-left規則をそのまま使用する。
範囲外の三角形は描画画素0を返す。退化三角形は最初の候補の退化判定後に終了する。
CLEAR・全パラメータ設定の要否、timeout/ARM解除による無効化の条件は維持する。

独立した従来の全タイルPython参照と、Dockピン経由RTLを照合した。
負座標、部分画素、画面外、画面端、signed16bitの両端、逆向き、退化を含む32三角形で
色・深度65,536画素、2,432通信が一致した。
RTLへ実際に投入された候補数の上限もチェックし、32三角形の合計上限は1,166候補だった。
従来の全画素走査なら同じ32三角形に32,768候補を投入する。
この削減数はPC試験の候補数であり、描画速度の実機倍率ではない。

既存の単画素三角形10,334通信、行読戻し410通信、フラクタル413通信の回帰試験も成功した。
実機書込み、合成・配置配線、描画時間の比較は親の統合検証記録へ記載する。
ソースハッシュとPC試験結果は[triangle-bbox-rtl-2026-11-03.json](../fpga/validation/triangle-bbox-rtl-2026-11-03.json)を参照。

```powershell
python fpga/gfx/tests/run_triangle_bbox.py --iverilog PATH_TO_IVERILOG --vvp PATH_TO_VVP
```

ホスト要求・参照版と全OSへの適合性は[フラクタルタイル仕様](Dockフラクタルタイル仕様.md)を継承する。
ESP-IDFで同じ命令を送れる。MeOS/Linuxに新しいホスト実装の反映は不要で、
三角形命令自体の未対応は従来どおり残る。
