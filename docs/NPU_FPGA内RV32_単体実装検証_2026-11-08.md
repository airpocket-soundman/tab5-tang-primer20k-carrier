# FPGA内RV32実行部：単体実装と検証（2026-11-08）

Transformerの非MAC演算、量子化、実行順制御をFPGA内のRV32IMCソフトコアで動かし、既存INT8 Conv/MatMul回路を利用する実装候補。Tab5で非MAC計算する従来方式とは異なるが、全演算を専用の並列回路に展開する方式でもない。**本書の到達点は部品の実装・RTL試験・単体合成。実機の全モデル完走、数値適合、速度優位、全chip資源・STA合格はまだ示さない。**

[固定証跡](../fpga/validation/npu-local-cpu-2026-11-08/README.md)と[SHA一覧](../fpga/validation/npu-local-cpu-2026-11-08/SHA256SUMS.json)。共通ホスト要件の確認は[全ホスト監査](NPU_AUTONOMOUS_HOST_REVIEW_2026-11-08.md)、外部wireは[Autonomous V1](NPU_AUTONOMOUS_V1.md)を参照する。この部品だけで外部opcodeや全OSドライバを確定しない。

## 実装

- `npu_local_cpu_subsystem.v`：実PicoRV32IMC、MMIO descriptor/状態/進捗、blocking COMMAND、FINISH前flushと停止。
- `npu_rv32_ddr_cache.v`：MEMV1 held-toggle/tagged DDR接続。1KiB I-cache＋1KiB write-back D-cacheを512×32 single-port BSRAM1個へ配置し、tagはdistributed RAMに置く。MMIOと演算器が同時にstagingを使用しない。
- `npu_local_rv32_regs.v`：公式PICORV32_REGS hook用distributed register file。公式vendorを直接変更しない。
- `prepare_local_cpu.py`：公式ソースSHAを確認し、macro prefix/undefだけを付けた合成用ソースとprovenanceを生成する。

公式[PicoRV32](https://github.com/YosysHQ/picorv32)のcommit `ef203c2b0a3fb793280f5114941416c425c5b461`、ISCライセンス。独自の命令CPUを新規設計したという意味ではない。記憶資源の指定はGowin公式[SUG550](https://cdn.gowinsemi.com.cn/SUG550E.pdf)の`registers`/`distributed_ram`/`block_ram`を照合した。

## 制御・所有権

CSRは内部CPU用で、0x10000000に配置する。STATUS bit0 READY、1 BUSY、2 DONE、3 ERROR、4 QUARANTINED、5 RESULT_VALID、6 MEMORY_READY。COMMAND+4へ1=Tile/2=Matrix、ACK+8、ABORT+12、error+0x10、epoch+0x18、node/stage/app_error/FINISHを+0x20/+0x24/+0x28/+0x2c、descriptorは+0x40の13word。

COMMANDのstoreは、D-cache dirty flush/invalidate、実演算と最終DDR ACK、post-invalidateが終わるまでCPUへ完了を返さない。従って演算中にCPUが別のDDR命令を発行する必要はない。**Tile ACKは完了ラッチだけを解除し、loader.clearを出さない。** IC中間blockはDONE=1/RESULT_VALID=0が正常で、次のblockへ累積値を残す。

CPU codeはDDR0x05000000で開始する。0x07ff0000以降のmailboxはuncached/write-through。FINISH1/2以外は拒否し、実行エラーが残る成功要求は失敗扱いにする。FINISHはdirty flush後にCPUを停止し、safe_to_releaseはCPU停止・DDR outstandingなし・演算器idle・quarantineなしの場合だけ真になる。初期run_enable=0でも新規STARTを許す。abort/CPU trapはCPUを停止してもDDR bridgeを生かし、相関の取れる完了をdrainする。tag不一致やcalibration loss等でquarantineしたら、coordinated resetなしに所有者を切り替えない。

共通stagingを借りるホスト/CPU mergerは既存tagged arbiterを再利用する。source request toggleを単純にmuxしない。これは親の全core統合に必要な契約で、単体合成結果だけで統合済みと扱わない。

## 検証結果

実PicoRV32IMC＋実cache/MMIO＋コンパイル済みRV32 firmwareをIcarusで実行した。DDRとMACは明示したtest doubleで、MACは独立INT32計算。通常smokeはTile8値＋Matrix6値の14値。IC17追加版はIC16 nonfinal→IC1 finalを含む20値とDDR guardに合格した。非finalでDDRを公開せず、ACKで部分和を消さないことも確認した。初期safe_to_releaseを使うSTART前提も試験した。

9異常系はbad tag、timeoutとdrain、abort、calibration loss、bad memory status、native応答と同時abort、MAC watchdog、illegal instruction、最終mailbox write failure。いずれも成功FINISHや再送を生成しない。相関の取れるdrain後の失敗は停止して所有者を解放でき、不明な完了はquarantineのまま保持した。FPGA実機、USER-clock DDR PHY、実MAC RTLとの統合の合格ではない。

## 全chip資源超過後の選択（同日追記）

親の初回全chip合成は22035/20736 Logicで不適合だったため、hardware matrix sequencerを外す候補へ変更した。CPU部品の`ENABLE_MATRIX=0`ではREADYがtile側だけに依存し、COMMAND2は明示拒否、matrix制御出力は定数化して除去できる。firmware v8/chainv3は同じK16/M256/N8 tile展開をFPGA内CPUで行う。MAC自体は従来の実回路で、CPU計算へ置換しない。

この候補の実Pico単体試験は、matrix_start_ready=0、ELFの実.bssへ0xA5、epoch37→38、2回のRUNで14値/20値を確認した。9異常系も同profileで合格。rootの全core・実MAC・PNR・実機は別記録であり、本書の5824 Logicはoptional parameter追加前のmatrix-capable単体保存点。正確な当時source snapshotを残し、tile-only全chipの測定値へ読み替えない。
