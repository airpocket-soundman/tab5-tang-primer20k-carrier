# NPU 4E22：入力データ整列版の実機検証（2026-11-07）

4E22は正極性TX DMAの5MHz通信とDeiT-tiny全12ブロックの実機試験に合格した。入力DATAを受信CLKと同じ段数で同期する修正を、新しいtopでのみ有効にした版である。配線・プロトコル・CAPS4E20は変更していない。STAは未認定であり、全NN演算がFPGA内で完結したという結果でもない。

## 固定した実装と復帰経路

- USERCODE `00004E22`、CAPS `4E20`、SRAM書込みのみ。FPGA Flashは変更していない。書込み・実機試験は主担当が実施した。
- FS SHA256: `f3a8703cccc55711ae484db685f0805f2b8f0ca2cc87fc3a74355d6e03b0eade`。
- [保存したビットストリーム・checkpoint](../fpga/validation/npu-ddr-4e22-2026-11-07/checkpoint.json)、[全ファイルSHA256](../fpga/validation/npu-ddr-4e22-2026-11-07/SHA256SUMS.json)。
- `REQUEST_DATA_PIPELINE` の既定値は0のまま。新しいaligned topだけ1を指定し、旧4E21 topの動作を保存した。[固定ソース](../fpga/validation/npu-ddr-4e22-2026-11-07/source_snapshot/)とbuild TCL/SDCを保存した。
- 外部DDR IP/PLLは[SHA記録](../fpga/validation/npu-ddr-4e22-2026-11-07/external-source-hashes.json)のみ保存し、vendor IP、netlist、巨大な試験vectors/vvpは追加していない。buildには同一の外部ファイルが必要となる。
- 4E21復帰用FSは `fpga/build/npu-ddr-8oc-v1/npu_ddr/impl/pnr/npu_ddr.fs`、SHA256 `a9bdae1126f7ffdba349d14293271addbeb4901cee3019bb2315383bf650c05c`。本作業では変更していない。

## 5MHz全モデル結果と性能の範囲

[実機result.json](../fpga/validation/npu-ddr-4e22-2026-11-07/physical/fullmodel-5m/result.json)と[生FP32出力](../fpga/validation/npu-ddr-4e22-2026-11-07/physical/fullmodel-5m/FPGA_DDR.f32)を保存した。ホストELFは `0295a2b322694b59a49521bac28c0fb61fa72f70b69b2fe6fea684cbf32c24b2`、optimization profile15、正極性TX DMA要求5,000,000Hzである。出力SHA256は `ee03e13dffb253c886318761969da2fd3de6ae40f41e10ca0eeb24544525240b`、max/mean absolute errorは0、phase sumsも一致した。

| 計測 | 値 |
|---|---:|
| 推論 | 217.004227秒 |
| 全体 | 241.926695秒 |
| TX DMA累積 | 18,655要求、24,943,726 wire bytes、8.701451秒、unit allocation 1 |
| 上記DMAの実効値 | 約2.867MB/s（wire bytes / DMA計測時間。アプリ全体の速度ではない） |
| graph側TX / RX / READY待ち | 34.687749 /127.017456 /35.583276秒 |

5MHzはDMA設定値であり、測定器による信号品質・ジッタ・最高周波数保証ではない。今回RX経路は高速化していない。cycle counter samplingは無効なので、result内のkernel/DDR cycles=0を演算時間ゼロと解釈しない。以前の2MHz全モデル217〜219秒程度と比べても、TX高速化だけで推論時間全体は大幅には下がっていない。設定・モデル・profileを固定した追加A/Bなしに差分を入力整列だけへ帰属させない。

現在のFPGA担当は全MatMulのINT8演算であり、P4がLayerNorm、Softmax、GELU、量子化・配置・その他演算を処理する。正解基準は同じP4の独立CPU整数参照で、以前のPC nativeとの数値不一致を取り消していない。[最終目標の常駐重み・FPGA内連続推論計画](NPU_常駐重みと連続推論計画_2026-11-07.md)に従い、今後は中間テンソルをP4へ出さず、画像入力と結果出力だけにする。

ピン・電源・wire commandの変更はない。ESP-IDF側の実測成功をLinux/MeOSの物理実装合格へ読み替えない。全ホストの要求・未実装部分は上記連続推論計画の参照版に記録している。
