# 大きなYOLO系モデルをFPGAのDDR3常駐で動かす見積もり（2026-11-04）

**本書の数値はすべて「見積もり」であり、実機・合成・配置配線で実証したものではない。** 実機（Tab5、Dock、JTAG）には触れていない。ファイルのダウンロードもしていない。計算は [estimate_yolo_ddr3.py](../fpga/npu/estimate_yolo_ddr3.py)、出力は [estimate_yolo_output_2026-11-04.txt](../fpga/npu/estimate_yolo_output_2026-11-04.txt)、単体試験は `python -m unittest discover -s fpga/npu/tests -p "test_estimate_yolo.py"`。既存の見積もり（[NPU実現性見積もり_2026-11-04.md](NPU実現性見積もり_2026-11-04.md)）の続きで、P4側の実測（esp-dl Issue #339）やGW2A-18の資源はそちらを引き継ぐ。

## 1. 目的と結論（暫定）

目的：Tab5のPSRAM（32MB）には入らないが、FPGAのDDR3（128MB）には入る大きなYOLO系モデルを、遅くてもよいので動かす。重みはDDR3常駐、通信は入力画像と結果のみ（20MHz×8bit≒20MB/s前提）。

- **容量デモとしては成立し得る**：YOLOv8l（INT8重み約42MiB）とx（約65MiB）はP4のPSRAMに重み＋活性が載らない（必要約44〜79MiB）が、DDR3 128MiBには載る。mは境界（26〜32MiB）で不確実。
- **速度では、P4が動くモデル（n/s）ではFPGAは「同等〜やや有利」止まりで、大差で勝てるとは言えない**。l/xはP4が動かないので比較対象がなく、「動くこと自体」が価値。
- 見積もり1枚あたり（通信込み、320×320 / 640×640）：l 7〜17秒 / 27〜64秒、x 10〜29秒 / 42〜113秒（計算最良〜DDR3 BIST実測換算の範囲。詳細は§4）。
- **DDR3は現状BIST実測で理論値の約3〜6%**（§3）。このままだと大型モデルはDDR3律速になり、計算最良の1.3〜2.7倍程度に悪化する。DDR3コントローラの帯域改善が最大の課題。
- 最大の未確認：DDR3の実運用（リフレッシュ・連続バースト・アダプタ）、INT8の全層量子化精度、DSP 9×9分割（未検証）、合成でのLUT収容。

## 2. モデル諸元（計算）

層構成をultralyticsのyolov8.yaml（深さ/幅倍率 n:0.33/0.25、s:0.33/0.5、m:0.67/0.75、l:1/1、x:1/1.25、最大ch 1024/1024/768/512/512）から再構成して数えた（BN融合後のconv重み＋バイアス、クラス数80）。公表値（記憶ベース、出典照合は未実施）との差は、パラメータ数・MACとも1%以内で、単体試験でも照合している。

| モデル | param（計算／公表） | INT8重み | GMAC 640 | GMAC 320 | 最大活性 640（MiB, 範囲） | 最大活性 320（MiB） |
|---|---|---:|---:|---:|---:|---:|
| n | 3.15M／3.2M | 3.0MiB | 4.37 | 1.09 | 2.7 | 0.7 |
| s | 11.16M／11.2M | 10.6MiB | 14.3 | 3.58 | 4.7〜4.9 | 1.2 |
| m | 25.89M／25.9M | 24.7MiB | 39.5 | 9.87 | 7.0〜7.3 | 1.8 |
| l | 43.67M／43.7M | 41.6MiB | 82.6 | 20.6 | 10.9 | 2.7 |
| x | 68.20M／68.2M | 65.0MiB | 128.9 | 32.2 | 13.7 | 3.4 |

最大活性の定義：下限＝1演算の入力＋出力の最大（C2fのcv2はconcat済み入力を含む）、上限＝下限＋その時点で保持するスキップ接続（P3/P4/SPPF出力、ネック出力）。いずれもINT8、1バイト/要素。上限は今回の層構成ではnでは差が出ず、s/mで数%。ただし実装次第（concat用コピー、ダブルバッファ、再量子化前のINT32一時領域）で増える。範囲は±2割程度の不確実さがあると見るべき。

入力は640で1.23MB、320で307KB。出力は復号後（box4＋cls80）で640が約706KB、320が約176KB（DFL前の生出力ならその144/84倍弱）。

## 3. DDR3帯域：理論値とBIST実測を区別する

| 区分 | 値 | 根拠 |
|---|---|---|
| 理論値 | 約1.593GB/s | USER 99.5625MHz × 16B/ビート（128bit）。実機で出る値ではない |
| BIST実測換算 | 約51〜103MB/s（理論の3〜6%） | 約31サイクル/ビート/相。**「相」の数え方（1ビート＝1相か）が未確認**のため、1相＝1ビートで51MB/s、2倍まで幅を取った |
| 目標（仮定） | 理論の30〜60%（480〜960MB/s） | 連続バースト・バンクインタリーブ・リフレッシュ最適化後の**目標**。実証なし |

BIST実測は、現状の簡易制御器の値でありDDR3チップの限界ではない。ただし現状値のまま使うなら、下記の通りモデルの重みを1回読むだけで秒単位になる（x：65MiB÷51〜103MB/s＝約0.7〜1.3秒）。

## 4. 持続MAC/sと1枚あたりレイテンシ

### 4.1 前提（FPGA）

- 計算：レーン数×クロック×稼働率。レーンは96（DSP 9×9分割、**未検証**）または48（18×18）、クロック27/54MHz（OSSフローの実績）、稼働率0.3〜0.6（**仮定**）。持続MAC/sは 最悪0.39 〜 最良3.1GMAC/s。これはP4の最良実測4.4GMAC/sを下回る。
- DDR3トラフィック：各層について「重み1回＋入力を重みブロック数だけ再読込」または「空間タイルごとに重み再読込」の小さい方（モデル化はスクリプト参照）。入出力がオンチップ（活性バッファ）に収まる層は活性往復なし。重みバッファ24〜48KiB、活性バッファ32〜48KiB（BSRAM合計約103.5KiBのうち）、悪い側は転送量1.25倍とした。**BSRAMタイリングが最大の不確実性**で、範囲は「良〜悪」の2点にすぎない。
- 計算とメモリは、最良・目標では完全に重なる（max）、他は重ならない（和）とした。
- 通信：入力＋復号後出力を20MB/sで転送（640で約97ms、320で約24ms）。実リンクの実効値は未測定。

### 4.3 P4単体との比較

P4の推定は、速い側＝YOLOv8n実測の高側（1.66GMAC/s）、遅い側＝nは0.67GMAC/s、重み4MiB超のモデルはPSRAM帯域律速層の下限0.14GMAC/s（Issue #339で重み144KB超の層が138〜204MMAC/s）。nの320は実測が492〜1211msで、本表の0.66〜1.6sと整合的。それ以外は**WholeBody25と同じくYOLOv8s/m/l/xのP4実測は取得できなかった／未実施**で、外挿にすぎない。

| モデル・解像度 | P4に載るか（重み＋活性、32MiB中） | P4推定 | FPGA推定（理論〜BIST実測下） | 判定 |
|---|---|---|---|---|
| n 320 | 載る（約4MiB） | 0.66〜1.6s（実測492〜1211ms） | 0.38〜0.75s | FPGA同等〜やや有利。ただし通信・計算とも未実証 |
| n 640 | 載る（約6MiB） | 2.6〜6.5s | 1.5〜2.9s | 同上 |
| s 320 | 載る（約12MiB） | 2.2〜26s | 1.2〜2.7s | FPGA有利の可能性（P4の重み律速次第） |
| s 640 | 載る（約15MiB） | 8.6〜103s | 4.7〜10s | 同上 |
| m 320 | ぎりぎり（26.4〜26.5MiB） | 5.9〜71s | 3.2〜7.6s | P4は他の用途のPSRAMを使うと載らない |
| m 640 | ぎりぎり（31.7〜31.9MiB） | 24〜280s | 13〜29s | 同上、実質P4は不可 |
| l 320/640 | **載らない**（44〜53MiB） | （動かない） | 6.7〜17s／27〜113s | **容量デモの領域** |

## 5. 勝てない領域（正直な評価）

1. **ピーク計算では負ける**：FPGAの持続は最良でも3.1GMAC/s、P4の3×3 conv最良実測は4.4GMAC/s。重みがキャッシュに収まるモデル（nの小さい層など）ではP4が速い可能性がある。
2. **nの320は実質互角**：FPGAの優位は1.3〜3倍程度の見積もり幅（0.38〜0.75s vs 0.49〜1.2s）に埋もれる。通信やDDR3が想定を外すと逆転する。速度目的なら小モデルは最初からP4で動かす方がよい。
3. **DDR3が現状のBIST水準のままなら、s以上でFPGAの利点は大きく減る**。メモリ律速になり、実測換算（下側）でxの640は約1.2〜2分以上。
4. **精度**：INT8全層量子化は大型モデルで精度劣化の度合いが未確認。キャリブレーション用データの扱いと、再量子化（既存`int8_requantize`）の誤差を検証する必要がある。
5. **エネルギー／熱**：未検討（未確認）。DDR3常時アクセスの消費電力は未測定。
6. **後処理**：NMSやDFL復号をP4側かFPGA側かで分担する。FPGAに置けば出力は小さくなるが追加実装が要る。置かないなら640で生出力1MB超を20MB/sで転送（約50ms以上）。数値は小さいので優先度は低い。
7. FPGA DDR3は透過的なメインRAM増設ではない。P4はDDR3を直接アドレスできず、あくまで「DDR3常駐の重みを使うオフロード先」である。

## 6. 必要なハードウェア機能（既存部品との差分）

既存部品：`int8_mac_lane`（約295セル）、`int8_requantize`（約2,361セル）、`int8_dot_job`（約2,892セル）。いずれもドット積ジョブ単位であり、conv全体の実行器ではない。

| 機能 | 既存部品との差分 | 規模感・注意（見積もり） |
|---|---|---|
| 畳み込み実行器 | `int8_mac_lane`を並べた複数レーン＋出力チャンネル並列＋積和木＋バイアス。1×1、3×3、stride1/2を扱う制御 | 新規。DSP 48〜96を使い切るため、重み供給（バス幅）が律速になる可能性 |
| タイリング／im2col | 新規。空間タイルとチャンネルブロックのDMA、ハロー（3×3の境界）、BSRAM配置のスケジューラ | **最大の新規規模**。層ごとの記述子（ジョブリスト）をP4から投入する方式が現実的 |
| SiLU／活性 | 新規。INT8ではSiLUをLUT化（256エントリ、1BSRAM以内）。再量子化後に適用 | 小。精度は量子化規約次第 |
| 再量子化 | `int8_requantize`を流用。ただし約2,361セルは複製不可のため**共有・時分割**。レーンあたりでなく出力ストリームあたり1個 | 既存の差分は、チャンネル毎スケール（per-channel）と複数出力の時分割 |
| アップサンプル（2倍最近傍） | 新規。読み出しアドレス生成のみで実装でき、メモリ書き戻し不要にもできる | 小 |
| Concat | 新規。出力をチャンネル方向の別オフセットへ書くアドレス割当で、コピーは不要にできる（メモリ配置を設計時に決める） | 小。ただしスケール（量子化パラメータ）が異なる入力の整合が必要 |
| MaxPool（SPPF） | 新規。5×5 stride1を3段 | 小 |
| DDR3アダプタ | **既存のDDR3 BISTから、読み書き要求インタフェース（バースト、アドレス、ストローブ）への拡張**。優先調停（重み／活性／出力）、先読みFIFO | 中。現状のBIST性能（約31サイクル/ビート/相）の改善が前提（§3） |
| LINK／ジョブ制御 | 既存のLINKで入力画像・記述子・重みの書き込み、結果読み出し。重みの初期ロード（65MiBをDDR3へ）は初回1回で、20MB/sなら約3秒＋書き込み性能次第 | 中 |

LUTの余裕は未確認（GW2A-18はLUT4 20,736）。LINK、DDR3コントローラ、記述子制御、上記を同居させる見込みは**合成で確かめるまで不明**。

## 7. マイルストーン案と合格基準

| 段階 | 内容 | 合格基準 |
|---|---|---|
| M0 前提確定 | DDR3 BISTの「相」の定義確認、実効帯域の再測定。DSP 9×9分割の合成確認。INT8モデルの量子化規約（スケール、ゼロ点、層別）を文書化 | DDR3の持続読み書きMB/sが数値で出る（理論の何%か）。DSPレーン数の合成上限が確定 |
| M1 小モデル一致 | 重みをBSRAM内に置く小さなconv層（例：YOLOv8nの1つのC2fまたは小さなテスト用ネット）を、conv実行器＋再量子化＋SiLUで実行 | **ビット一致**（参照モデルのINT8出力と全要素一致）。RTLシミュレーションと実機の双方。1層→C2f→n全体の順 |
| M2 DDR3常駐 | 重みと活性をDDR3から読み、YOLOv8n 320を全層実行 | 参照実装とビット一致、または検出結果（box、クラス）が一致。FPGA時間を実測し、見積もり（§4）との乖離を記録。DDR3実効帯域の記録 |
| M3 s/m の性能計測 | 同じ実行器でs、mを実行し、P4のesp-dl実測（同モデル）と比較 | **P4の実測とFPGAの実測を並べる**。n/sでFPGAがP4を下回るなら、速度ではなく容量の路線に絞る旨を記録 |
| M4 大モデルの容量デモ | l、xをDDR3に常駐し、1枚の画像で検出結果を返す | 重み65MiBをDDR3へ書き、読み戻しの一致を確認。xの320×320で結果が参照実装と一致（または許容差内）。**所要時間は許容（数十秒〜分）**。P4単体では動かないことを併記 |

各段階で、使った版（ホストOS側リポジトリ、ビットストリーム）、見積もりとの差、未確定事項を記録し、全ホスト（ESP-IDF、MeOS、NOMMU Linux）から使えるコマンド仕様を確定してから先に進む。

## 8. 未確認事項

- DDR3 BISTの「約31サイクル/ビート/相」の「相」の定義（本書は51〜103MB/sの幅で扱った）。DDR3は現状未動作／BIST止まりで、アダプタ経由の実測は無い。
- DSP 9×9分割（96レーン）の合成・動作。LUT収容。54MHzでの積和木のタイミング。
- 稼働率0.3〜0.6、BSRAMバッファ割当（重み24〜48KiB、活性32〜48KiB）は仮定。タイリングの実際の転送量は設計次第。
- 公表パラメータ・FLOPs値は記憶ベースで出典照合が未実施。計算値と1%以内で一致しており、計算側の信頼度は高いが、公表値そのものの確認は未了。
- P4でのYOLOv8s/m/l/xの実測は取得できなかった／未実施（外挿）。esp-dlが対象モデルのエクスポートに対応するかも未確認。
- 実リンク（20MHz×8bit≒20MB/s）の実効値、NPU用の入出力転送の実測は無い。
- 量子化後の精度（mAP）、消費電力・発熱。
- ホスト側リポジトリ（tab5-linux-fpga、tab5-meos-fpga、tab5-fpga-gpu）の関連資料は本作業では再確認していない（オフライン、見積もり拡張のみ）。仕様確定前に確認が必要。
