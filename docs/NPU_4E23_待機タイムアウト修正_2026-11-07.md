# NPU 4E23：空の受信待機でセッションを破壊しない修正（2026-11-07）

4E22以前のNPU endpointは、空の受信待機でもTIMEOUT（通常27MHz×27,000,000サイクル、約1秒）ごとにconv_abortとcancel toggleを発行する。既存loaderはIDLE中のabortもfault8にするため、常駐重みの初回推論後に表示・結果取得などで間隔を置くと、次回推論の前にloaderが故障状態になる。旧RTLと実loaderをつないだ試験でこの現象を再現した。

4E23候補は、新しいSYS/core/top/buildファイルだけを追加する。既存4E22のソースと復帰FSは変更しない。USERCODEは4E23、wire CAPSは4E20のままで、ピン・電源・コマンド・量子化・NN数値演算は変えない。実機確認は主担当が別途実施する。

## 修正条件

`healthy_idle = state==RX && index==0 && !conv_busy && !arbiter_active` のときだけ、idleカウンタを0へ戻し、timeout分岐を通さず通常のRX処理を実行する。これにより最初の受信エッジと期限が重なっても、最初のバイトを捨てない。単にtimeout値を延ばしたり、全timeoutを無効にしたりしていない。

途中まで受信したpacket、未読response、MEMWAIT、CONVWAIT、loaderまたはarbiterの実行中処理では、従来のtimeout/abort/cancelを維持する。校正喪失時のgeneration/session token無効化も維持する。すでにfaultになったloaderを自動回復する変更ではない。

追加ファイルは `npu_ddr_sys_idle_guard.v`、`npu_ddr_core_8oc_idle_guard.v`、`tab5_dock_npu_ddr_8oc_idle_guard_top.v`、`build_npu_ddr_8oc_idle_guard.tcl`。既存4E22と同じDATA2FF整列を有効にする。新規build出力は `fpga/build/npu-ddr-8oc-idle-guard-v1`、外部DDR IP・PLL・制約・無例外SDCは既存4E22と同じである。

## RTL検証

`python fpga/npu/tests/run_ddr_idle_guard.py` はTIMEOUT32に縮め、旧・修正版endpointへ実8OC loaderを接続して検査する。

- 旧版：160サイクル待機で周期abortとloader fault8を再現。
- 修正版：同じ待機でabort0、loader正常。期限値と最初のA5バイトが重なった場合もRX indexが進むことを検査。
- 途中packet、MEMWAIT、CONVWAIT、active arbiter、未読CAPS responseは引き続きtimeout。MEMWAIT/CONVWAITは対象状態を直接設定して検査する。
- ARM解除時にREADY/OEが解除される。

`python fpga/npu/tests/run_ddr_idle_guard_core.py` は実core/arbiter/bridge/adapter/loaderとmock native DDRを使う。既存64コマンドに加え、LINK_TIMEOUT700,000に対して1,400,100 SYSクロック（2期限超）の空待機を挟み、loader/arbiterが故障せず、bound tokenの両16bitとDDR write/readを維持する4コマンドを追加した。計68コマンドに合格した。CRC、128MiB境界、Conv ICブロック、校正喪失、reset、ARM、再生防止の既存試験も含む。

core試験では新モジュール名だけをbuildコピー上で既存TB名へ正規化する。元ソースSHAとコピーSHAを保存し、演算やtimeout条件は変更しない。最初の68コマンド試験は既定の27,000,000 timeoutに対して待機が短かったため、待機修正の証拠には使わない。明示700,000版の `npu-ddr-idle-guard-core-v2` を採用する。

[検証アーカイブ](../fpga/validation/npu-ddr-4e23-2026-11-07/checkpoint.json)に原本ソース、build TCL/SDC、RTL試験、合成・配置配線レポートとSHAを保存する。無例外STAの未解決違反を、論理試験や単体Fmaxによって合格へ読み替えない。実機試験前の候補であり、常駐重み再利用の成功は実機の複数フレーム確認後に別記する。

今回の変更は[常駐重みとFPGA内連続推論計画](NPU_常駐重みと連続推論計画_2026-11-07.md)のセッション保持を支える修正である。全NN演算をFPGAへ移したものではない。全ホストの参照版・未実装範囲は同計画を参照し、ESP-IDF実機結果をLinux/MeOSの物理認定とは扱わない。
