# DDR3：方針決定（旧IPを固定した外部部品として採用、再生成IPは期限つきで検証して、見込みがなければペンディング）（2026-11-05）

ユーザーの指示（2026-11-05）：**DDR3の利用を最優先で解決する。自前で再生成したIPは、今やっていることをある程度検証し、いくつかのバリエーションを試して、それでも解決の見込みが立たなければ、一旦ペンディングにする。その間は動くIPを使う。**（「深追いしない」は「何もしない」ではない。）

## 決定

1. **動くIP（Sipeedの公開サンプルに含まれる旧IP、GowinSynthesis 1.9.8.05、400MHz）を、固定した外部ベンダー部品として使う。** 自前のロジック（BIST、mailbox、LINK、今後のアダプタ）は、その上に載せる。
2. **新ツールで再生成したIPの調査（校正が400MHzで完了しない問題）は、期限と打切り条件を決めて並行して続ける。** ビルド済みの変種（`clk400dp`、`clk400x_dp000`、`clk400x_dp1116`、`clk400x_drvhigh`）を、段階1だけ（`calibrated` が真になるか）で実機試験する。打切り条件：この4変種と、マニュアル照合で出てくる追加のバリエーション（数個）を試して、どれも校正が通らなければ、**ペンディング**にして、旧IPで進める。1つでも校正が通れば、段階2（BIST）以降に進む。
3. 旧IPはGowin製の暗号化生成物で、**再配布条件が未確認**。リポジトリにはコミットしない。取得は固定コミット＋SHA検証付きの手順（`docs/DDR3_旧IP保管と再現手順_2026-11-04.md`）。製品や公開物に入れる前に、Gowinのライセンスの確認が必要。

## 実機の根拠（このPC、2026-11-05）

イメージ `sampleip_map_t4`（FS `39ff4409…`、USERCODE 0x0233、PIPELINE=4、STAの違反0。ただし診断用の非同期SDC下の結果で、最悪setup +0.024ns と薄い）と、MEM probeファーム（ホスト `claude/track-p-ddr3-clk400-host`、ELF `8ae2d3ff…`）：

| 段階 | 結果 |
|---|---|
| 段階1（読取り専用） | 校正済み、`command_ready`・`data_ready` 真、`sys_flags` 905 |
| パターン10本（seed 0／FFFFFFFF／AAAAAAAA／55555555／歩行1×6、各1KB） | すべて合格 |
| 境界6本（列→バンク、バンク→行、行ビット、最終ビート） | すべて合格 |
| 規模4本（64ビート〜128MiB全域） | すべて合格 |
| 全域・複数seed 8本 | すべて合格 |
| soak（10分） | 実施中（結果は別途記録） |

- 通ったのは**ビットストリームの電源投入後1回目の校正**に対する試験。冷起動の繰返しと温度条件は未実施。
- 物理容量（1Gbit）と、サンプルの「ビット26で容量判定」との整合は未解決（`DDR3_Gowin公式資料との照合…` 6章）。128MiB全域のBISTはエイリアスなしで通っている。

## 次（DDR3の利用）

1. v1プロトコル（`MEMV1_CAPS／STATUS／RD／WR／CRC32` 等）とメモリアダプタを、旧IPの上に実装する（`DDR3_統合方針メモ_v1案`）。
2. 帯域測定エンジン（`mem_bw`）を実機に載せ、DDR3内部の帯域を測る。
3. ホスト（ESP-IDF）から、LINK経由で上限付きチャンクのREAD／WRITEを行い、CRCで照合する。
4. その上でNPU（大型YOLOの重みをDDR3に置く企画。`企画メモ_大型YOLOをDDR3常駐で動かす_2026-11-05.md`）。
