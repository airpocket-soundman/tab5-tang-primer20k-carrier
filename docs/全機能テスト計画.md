# 全機能テスト計画

更新日：2026-10-28。対象はLINK、GFX、NPU、MEMと各ホスト。機能一覧、必要条件と試験IDの正本は [feature_matrix.json](../fpga/validation/feature_matrix.json)。一覧の`readiness`は機能全体の実装段階であり、個別テストの合否ではない。`ready`は必要な機能実装が揃った状態、`partial`は要素または診断版、`planned`は未実装の計画。合成・実機試験の成功を意味しない。

## 実行と記録

PCの試験を `python fpga/tools/test_features.py` で実行する。`--rtl` はIcarusによるRTL試験、`--synth` は要素RTLの合成、`--build` はDock LINK/GFXの合成・配置配線・packを追加する。実行環境、ソース、ツール、生成物と結果を記録し、実行していない試験は未実施として扱う。要素合成は配置配線やIO、実機ビットストリームを検証しない。GFXの合成後機能シミュレーションは限定試験モデルで通過済みであり、[範囲と根拠](../fpga/simulation/README.md)を参照。ベンダーモデルや物理タイミングの検証ではない。

```powershell
python fpga/tools/dock_dev.py setup
python fpga/tools/test_features.py --list
python fpga/tools/test_features.py --rtl --synth --build
```

最新の結果は`fpga/build/feature-tests/latest.json`、各実行の結果・ログは同じディレクトリの`runs/`へ保存する。`completed`は選択したPC試験の完了を表し、全企画の完成ではない。機能ごとの`verification`が`partial`または`not_ready`なら残件がある。`--require-complete`は全機能の全チェック通過を要求するため、未実装・実機未確認がある現状では終了コード2となる。Cコンパイラはcc／gcc、またはインストール済みZigを使用する。必要なら`--cc <コンパイラ実体>`を指定する。スキップした試験は合格扱いしない。

`hardware.*` は必要な将来試験の識別子であり、自動実行を意味しない。物理試験は配線・電源・競合を確認した後に別途実施し、対象ボード、GPIO、OS、プロファイル、bitstream SHA、設定、結果と未測定項目を記録する。ARMはホストGPIO操作とFPGA SW0を区別し、途中失敗からの復旧も確かめる。

## 試験順序と判定

1. LINK v0：固定長フレーム、全echo／反転、CRC不正、sequence、タイムアウト、出力解除をPC／RTLで確認。Dockの配線・電圧が確認できた後、全ホストの実通信をそれぞれ測定する。
2. Dock GFX：CLEAR後の非対称図形について全1024画素をoracleと比較し、ESP-IDFでは受信画素をLCDへ送った結果と目視表示を分けて記録する。原点・範囲外・未初期化・中断を確認する。これは内部2KiB画像RAMの診断で、DDR3描画を示さない。
3. 三角形：coverage、depth、fragmentの各RTL／参照モデルと要素合成を先に確認する。統合後は境界、縮退、向き、深度遮蔽、画素・深度をCPU参照と比較する。2D線、copy／blit／glyph、汎用計算描画、shaderは命令と実装が必要。
4. DDR3：コントローラの初期化・BIST、全域・境界・ランダム読書き、CRC、帯域を順に検証する。MEM／RAMdiskはブロック整合性、領域分離、電源断時の扱いを定義して検証する。Linuxからのアクセスは明示的なデータ退避・復元であり、CPUの透過的なRAM増設ではない。
5. NPU：MAC、requant、dotのPC／RTL／要素合成を確認し、統合後に構成A（汎用DDR3重み）、B（モデル専用シーケンサ）、C（重み内蔵）をそれぞれ検証する。同一モデル・同一入力・同一前後処理でCPUと出力、量子化精度、転送、計算、後処理、表示時間を比較する。INT8と候補の4／2bitに対する精度許容値はモデルと評価データを選んで確定する。
6. HDMIは配線・保護と映像タイミングの確認後にテストする。GFX／NPU／MEMとHDMIやRAMdiskの共存は、単独版と同条件で資源、Fmax、帯域と速度を測定して判断する。
7. PARLIO DMAは方向切替、CRC、期限、キャンセル、キャッシュ・DMA条件をOS別に確認する。速度は目標値と実測値を分ける。

## ホストの現状と参照版

参照時の各リポジトリのHEADと読んだファイルのSHA-256はmatrixの`references`に記録した。ローカル未コミット変更もそのファイルハッシュで識別する。古いHEADだけをもって変更済み内容の再現性を主張しない。

- ESP-IDF：独立診断ファームにGPIO転送、GFX全画素照合とLCD表示要求がある。GPU LABのFPGA backendは未実装。Dock実機での確認は別途必要。
- MeOS：ローカル作業ツリーにDock GPIOとGFXの実装およびfixtureがある。IO owner、待ち、キャンセルと解放を実機で確認する。PARLIOはFreeRTOS依存のESP-IDF実装をそのまま前提にせずMeOS側で実装する。
- Linux：Tab5 DTSと汎用GPIOツールは存在するが、確認したツリーにFPGA物理transportはない。GPIO所有権、他周辺機器との競合、期限付き待ちと取消を設計する。
- 外部メモリ研究：明示的な外部メモリAPI／演算オフロードの要求を照合。研究計画だけでLinux本体の実装確認を代替しない。

本計画は新しいピン、電源、プロトコルやデバイスコマンドを確定しない。仕様変更時は各ホストの要求と影響を再照合し、採用した版を記録する。
