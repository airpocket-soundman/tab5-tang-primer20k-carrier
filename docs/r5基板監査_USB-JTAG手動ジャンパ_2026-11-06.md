## 0. 対象と方針

- 対象: `origin/codex/dock-jumper-gfx` の `spark/usb-jtag-r5/`（コミット 3fced0b、2026-11-04、work in progress）。KiCad 10.0.6 の設計。
- 比較元: r4 Full（`origin/main` の `spark/single-sided-r4/full/`）。
- 方針（ユーザー指示）: **r4からの変化分を中心に監査し、確定済みのr4の内容は極力変えない。** 提案は「r4を変えない最小変更」を優先し、r4に手を入れる案は別枠にした。
- 範囲: ①r4との差分 ②公式Dock／Core回路図との接続照合 ③Core実装領域とジャンパ（JP2〜4）の物理干渉 ④LCSC調達性とJLCPCBのbasic/extended ⑤電源モードの安全性。
- 実機・電気シミュレーション・KiCadのDRC/ERC再実行は行っていない。**r5自身が報告するDRC 0／ERCエラー0／607本照合は、ログの記載を確認しただけで、再現していない。**

## 2. r4との差分（部品）

`bom-r5.csv`（151部品）とr4の `bom.csv`（117部品）を参照名で比較した。

- **変更1:** J2、USB-C。r4は電源専用6ピンのGCT USB4125（C5246813）、r5は16ピンのHRO TYPE-C-31-M-12（データ対応）。
- **追加35:**

  | 種別 | 参照名 | 数 |
  |---|---|---|
  | 0603コンデンサ | C85〜C97（100n×11、27p×2、4.7u×1。C96が4.7u、C86/C87が27p） | 13 |
  | 0603抵抗 | R73,R74,R81〜R90（100k/12k 1%/10k/33R/1M） | 12 |
  | ESD | D10,D11（PESD5V0U1BL、SOD882） | 2 |
  | MOSFET | Q7,Q8（2N7002、r4で使用済み） | 2 |
  | IC | U17（FT232HL、LQFP-48）、U19（SN74LVC125APWR、TSSOP-14） | 2 |
  | 水晶 | Y1（FA-238、3.2×2.5mm） | 1 |
  | ピンヘッダ | JP2,JP3,JP4（1×3） | 3 |

- 上記以外の115部品は、値・LCSC番号・フットプリントが一致した（DNPの表記が空欄→`False`に変わっただけ）。**r4の内容は、部品レベルで保たれている。**

PCBの変更（READMEの記載）は、降圧出力のBUCK_5Vへの分離、USB周りの再配置、DNPパッド付近のGND復帰ビア追加、CC1/CFG3配線の0.06mmずつの回避です。**r4の銅箔を触る変更は、USB-C／CH224K周辺に限られる**ことを、設計者が示しています。

### r4保全ハッシュの確認

`preserved-r4.json` は、r4の1234ファイルのSHA256を保持している。ここでは、その値が現在の `origin/main` と一致するかを確認した。

結果: **1234件すべて一致**（不一致0、欠落0）。比較先は、r5の基準コミット（20a7dc5）と、現在の `origin/main` の両方。つまり、**r4のファイルはr5で変更されていない**（r5はr4を複製して独立設計しており、r4自体は保全されている）。ただし、これが示すのは「r4のファイルが無事」であり、「r5の基板がr4と同じ内容」ではない。r5の基板（`tab5-fpga-carrier-r5.kicad_pcb`）は別ファイルで、上記のPCB変更を含む。

## 3. 接続の照合（公式資料）

### 3.1 Core公式回路図（SOM-3961）

保存されたゴールドフィンガー拡大図（`reference/core-jtag-goldfinger.png`）を読んだ。

| SODIMM端子 | 公式信号網 | FPGAボール | r5の割当 |
|---|---|---|---|
| 143 | B8_IOR25B_JTAG_TMS | B8 | TMS ✔ |
| 147 | C6_IOR25A_JTAG_TDO | C6 | TDO ✔ |
| 149 | A7_IOR26A_JTAG_TCK | A7 | TCK ✔ |
| 153 | A6_IOR26B_JTAG_TDI | A6 | TDI ✔ |

137と141は、公式図でNC（×印）。r4でNCだった4本をJTAGへ割り当てたr5の説明と一致する。

### 3.2 公式Dock（Dock 3713/3714）

- DockはBL702（デバッガ）のJTAG（`BL702_JTAG_TCK/TDO/TDI/TMS`）を、**同じFPGAの信号網**（A7/C6/A6/B8）へ接続している。つまり、r5はFT232Hで同じ役割を担う構成であり、設計思想は公式に沿っている。
- Dockの注記: 「Remove the RN2 to use External JTAG」。**外部JTAGを使うときは、BL702側の直列抵抗（RN2）を外す**、という意味。r5ではBL702相当をFT232Hに置き換えているので問題ないが、**公式Dockを併用しない**前提である（Dockとr5を同時に接続しない）。
- 「BANK2 VOLTAGE is locked to 3V3(JTAG IO)」。JTAG IOは3.3V固定。r5は「周辺3.3V側のバッファ」で受ける設計で、レベルは合う（実機未確認）。
- CoreにはCore自身のJTAGヘッダー（TMS/TDO/TCK/TDI、RX、TX、5V0）があり、Core内の33Ω×4（RN）を経由してFPGAへつながる。**r5のSODIMM経由とCoreヘッダーは同じFPGA端子を共有する。** READMEは「同時駆動は禁止」と書いているが、**回路で防いでいるわけではない。**

### 3.3 リポジトリ内の参照CSVの誤り（低）

`docs/reference/tang-primer-20k/core_sodimm_pinmap.csv` は、143（`D10_IOL17A`）、147（`D11_IOL22A`）、149（`A9_IOL27A`）などと記録していて、**公式回路図と食い違う**。141/145/151/155の「ball_label」列にB8/C6/A7/A6が入っていることから、行がずれた抽出誤りと見られる（153だけは正しい）。r5のREADMEは公式図に基づいていて正しいので、**r5には影響しない**が、他の資料が、このCSVを根拠にしないよう、修正か注記を勧める。

## 4. 調達性：LCSCとJLCPCB（basic / extended）

### 4.1 方法と注意

- JLCPCBの `partdetail/<Cxxxx>` ページで、型番・パッケージ・分類（Basic/Extended）・実装種別を1件ずつ確認した。LCSCの在庫数と価格は、検索結果の抜粋であり、**確定値ではない**。注文前に再確認が必要。
- **私が最初に挙げた記憶ベースの番号のうち、FT232HL（C8321はSTM32）とSN74LVC125A（C7484はSN74AHCT1G125）は誤りだった**。以下の番号は全て、ページで型番を確認した。
- r4で既に使っている部品の分類は、r4の `procurement-check.json`（2026-10-26の取得）に基づく。
- JLCPCBでは、extendedの部品種が増えるごとに、部品ロード費がかかる（種類数で課金）。このため、「ユニーク種数」を数える。

### 4.3 extendedを増やさない最小変更案

ユーザー方針（r4を極力変えない）に合わせ、**回路・配線を変えない部品の選び直し**を先に挙げる。

1. **水晶を `X322512MSB4SI`（YXC、C9002）に変更。** JLCPCBで**Basic・SMT実装**、12MHz、3225の4ピン、**20pF負荷、±20ppm**（確認済み）。
   - 同じ3.2×2.5mmの4ピンなので、**パターン変更は不要**と見込まれる（ただしランド寸法をKiCadで要確認）。
   - 負荷容量が18pF→20pFに変わるため、**C86/C87を27pF→33pF（C1663、Basic、確認済み）へ**。式: 負荷CL ≈ (33×33)/(33+33)+Cstray ≈ 16.5pF + 浮遊容量（約3〜5pF）→ 19.5〜21.5pF。**Cstrayは実機基板で未測定**なので、水晶の周波数偏差は実測で確認する。
   - 効果: 水晶（C5700075）と27pF（C1656）の2種のextendedが、どちらもbasicに置き換わる。**FT232Hの水晶許容は±30ppmなので、±20ppmは適合**（FTDIの資料で最終確認のこと）。
2. **ピンヘッダJP2〜4は、JLCPCBで実装せず手はんだにする。** r4のJ6〜J8のように、LCSC番号なし・手はんだの扱いにする。ショートプラグ（3個）は別購入。これで、extended（wave soldering）の種別が増えない。
3. **ESDは、まず現状の候補（UMW C3001955）で確定し、同等性を確認。** 代替の案として、r4で既に使う `RCLAMP0524P`（C293965、extended）を再利用すると、種別が増えない。ただし、4ラインのアレイでパターンが変わるため、**r4を変えない方針には反する**。判断は設計者に任せる。
4. **U19（SN74LVC125APWR）は、extendedのまま。** r4のSN74CB3Q3245（C470961）で代替できる可能性があるが、バス・スイッチは**駆動力と隔離の性質が違う**ため、置換は回路の再検討が要る。本監査では、置換を勧めない。

## 5. Core実装領域とジャンパの干渉

### 5.1 計算方法

`tab5-fpga-carrier-r5.kicad_pcb` から、フットプリントの位置・回転・パッド・コートヤードを抽出して、座標変換した。

- J4（Core用SODIMMソケット `XDAP-4042044-20401`）: 位置 (81.24, 40.6)、回転 −90°。
- Core基板（Sipeed公式寸法、Core_3690_Dimensions）: 67.6mm × 30mm。
- 変換の結果、Coreは**J4から+x方向（右）へ伸びる**。実装領域の想定: x = 76.2〜106.2mm、y = 6.8〜74.4mm。J4のコートヤードは x = 75.9〜103.2mm、y = 4.8〜76.4mm。

### 5.2 結果

| 対象 | 位置（mm） | Core領域との関係 |
|---|---|---|
| JP2 | x 38.15〜39.85、y 25.15〜31.93 | 左へ **36.4mm** 離れている |
| JP3 | x 42.15〜43.85 | 左へ **32.4mm** |
| JP4 | x 46.15〜47.85 | 左へ **28.4mm** |
| J6, J7（PMOD、DNP） | x 111.65〜 | Core右端から **5.45mm**（DNP部品。実装時も干渉なし） |
| J8（GPIO、DNP） | x 120.65〜 | **14.45mm** |
| U17（FT232HL） | x 22.1〜31.9 | 左側。干渉なし |
| U19（LVC125A） | x 40.4〜47.6 | 左側。干渉なし |

**JP2〜4とCore基板は干渉しない。** ジャンパは、ボード左側（x 38〜48）にあり、CoreはSODIMMから右へ伸びる。

### 5.3 Core下に入る部品（r4から不変）

Core領域（x 76.2〜106.2、y 6.8〜74.4）の下にある部品は、0402/0603の C12〜C19、R28、R29、R32〜R35 のみ（r4から変化なし）。いずれも高さ約1mm以下で、SODIMMの標準高さ（5.2mmの変種）の下に収まる。**Core下側の部品の高さは、公式資料の実測値ではなく、一般的な値からの見積り。**

### 5.4 ジャンパの取り回し（操作性）

- 3個の1×3ヘッダは、4mmピッチで並ぶ（x = 39、43、47）。ショートプラグ（約2.5mm幅）は入るが、**指で3つを同時に動かすには狭い**。作業性は実物で要確認。
- 各ヘッダの向き（縦）と、JP4が右端でU19との間が約7mm空いている点は、問題ない。
- **Tab5との干渉:** Tab5はJ3（裏面）へ接続する。JP2〜4は表面（F.Cu）なので、Tab5が基板の下に来る構成なら干渉しない。筐体・Tab5の外形との干渉は、**筐体データがなく、未確認**。

## 6. 電源モードの安全性

README・`electrical-review.json` の表で、理想値としては、全ジャンパが揃っていれば正しい（RUN: Core約5V／Tab5約11.5V、PROGRAM: Core 5V／Tab5 0V）。

### 6.1 問題のある組合せ

- 設計者が既に明記した例: **JP2=PROGRAM、JP4=RUN、PD給電 → Core 12V（安全でない）。** USB VBUSをCoreの+5Vへつなぐ（JP2 PROGRAM）一方で、PD要求を12V（JP4 RUN）にすると、PDアダプタ（またはPD対応ポート）が12Vを出し、**Coreの5Vレールへ12Vが入る**。
- 他の混在（私の机上確認、未検証）:
  - **JP2=RUN、JP4=PROGRAM:** PDは5V要求。TPS5430の入力が約5Vなので、出力が規定の5Vを維持できない恐れがある（TPS5430は最低入力の規定がある。データシートで最終確認を）。Coreの電圧低下は起き得るが、過電圧にはならない。
  - **JP3=RUN（Tab5へVIN）、他がPROGRAM:** Tab5のHVINへ5Vが入る。Tab5の仕様では不足する可能性があるが、破壊的ではなさそう（Tab5の仕様未確認）。

### 6.2 提案（r4を変えない順）

1. **文書・シルク・付属物で対応（変更なし）:** シルクに「全て同じ位置」「通電中は動かさない」を明記。ショートプラグを3個ではなく、**色違いにして、プラグ位置をそろえる目印**をつける。組立指示にも、12V危険を最初に書く。
2. **PROGRAM時にPD給電を使わない運用ルール:** READMEの記載を、「PROGRAMではPDアダプタを接続しない」まで拡げる。
3. **回路で防ぐ案（r4の変更を伴う、判断は設計者）:** JP2のpin3（VBUS）の経路に、過電圧クランプや、12Vで切れる保護を入れる。設計者は「自動切り替え案（191部品）を取りやめ、安価な手動にした」ため、保護の追加は方針と相反する。**リスクを許容する判断を、設計記録に残す**ことだけは強く勧める。

### 6.3 その他

- 「USBとバレルを両方抜き、残留電圧が下がってから切替」は、**電圧が下がったことを人が確認する手段がない**。LEDなど、残留電圧を示す表示の有無は未確認。
- Core 5V±10%、0.5A（公式）に対して、USB 500mAの合計では、デバッガ込みの電力が不足する。READMEは、**1.5A以上広告のPC側USB-C**を前提にしている。広告電流を回路で検出しない設計（READMEに明記）。**この制約は、利用者の説明書に必須。**

## 7. FPGA／ホスト側から見た注意

- 専用JTAG 4本（B8/C6/A7/A6）は、**ビットストリームのGPIOに使わない**。このリポジトリのFPGA制約（`.cst`）に、これらのピンを使っていないことを確認する必要がある。私はまだ、現行の `.cst` との突き合わせを行っていない。
- PROGRAMではTab5が停止する（Tab5は無給電）。FPGA書き込み中のLINK／GFX試験はできない。
- ホスト（ESP-IDF、MeOS、Linux）への反映は未実施。ホスト通信ピンはr4から変わらないので、プロトコル変更は不要というr5の判断は、**ピンの面ではもっともだが、電源・書き込み手順の追記は、r5リリース時に必要**。
- 同一FPGA端子を、Core上のJTAGヘッダーと共有する。**ホストの試験環境（Dock併用など）と、同時接続しない運用**を、文書に残す。
