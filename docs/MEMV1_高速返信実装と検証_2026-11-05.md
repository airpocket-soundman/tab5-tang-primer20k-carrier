# MEMV1高速返信の実装とオフライン検証（2026-11-05）

基点はキャリア `48f91f1`（第2版引き継ぎ）。作業ブランチは `codex/memv1-fastreply`。mainへのマージはしていない。本書はFPGA側の変更とオフライン証拠を扱う。実機の合否は別の実機記録を参照する。

## 実装

`mem_v1_top`／`mem_v1_core`／`memv1_sys`に既定OFFの`FAST_REPLY_ENABLE`を追加した。既定版は従来のSYS同期返信を維持する。高速候補は216MHzの追加PLLと既存`reply_clock_filter`を使い、条件を満たす返信クロックで`memv1_reply_raw`を進める。ピン、電源、opcode、ヘッダ、タグ、CRC規則は変更していない。

- RDの最大256ビート／4KiB、CRC32、ヘッダだけの成功・エラー応答、タグあり／なしを同じserializerで扱う。
- USER書込みの読出しバッファは、高速候補ではconditioned reply clockで同期読出しする。ヘッダ中にword0を保持しword1を先読みし、16byte境界で次の128bit語へ切り替える。
- SYSでmetadataを固定した後、2SYS周期以上待ってofferする。metadataは返信終了／取消しまで固定する。進行toggleをSYSで2段同期し、長い返信中のLINK timeoutを更新する。
- raw DIR／ARM／reset／filter fault／serializer error／doneはOE・READYを直ちに遮断する。SYSの状態更新はdone／started／progress／error／filter faultの2段同期を使う。
- samplerのreset／lock低下はSYSが取り逃す1ns pulseでもラッチし、途中の返信をbyte0から再提示しない。sampler resetの解除は216MHzで2段同期する。
- 応答作成時のgenerationを固定し、途中のgeneration変化で送信を破棄する。inflight校正喪失がgen++と同じedgeで作成するSTALE応答には、新しいgenerationを固定する。

要求側は従来どおりSYS27MHzの3段同期である。**返信だけの高速化で、WR5MHzの成立を保証する変更ではない。**

## RTL検証

`fpga/validation/memv1-fastreply-regression-2026-11-05.json`は高速経路の既存全回帰。192参照ベクトルに加え、取消し、DDR無進行timeout、inflight校正喪失→STALE、遅延完了、実行中reset、BIST共存を含む209checksを実行する。

`fpga/validation/memv1-fastreply-offline-2026-11-05.json`は追加の周波数試験。RX 5／8／10／16／20MHzそれぞれに、SYS位相と出力遅延を組み合わせた3条件 `(0ns,0ns)`／`(12ns,3ns)`／`(24ns,6ns)`、計15点である。位相と遅延の独立全直積ではない。TXは2MHz、host採取はraw CLK立上り。各点で次を確認する。

- 高エントロピー4KiB WR→RD、タグ付き4KiB RD、CRC32とbound CRC、非ゼロstatusの短応答。
- CLK停止中の応答保持、途中DIR取消し、ARMによる即時OE遮断と復帰。
- READY後の校正喪失によるgeneration abort、sampler resetの500ns／1ns pulseと新しい要求での復帰。

`tb_memv1_fast_fault.v`は、過密CLKによるfilter faultでOE／READYが遮断し、自動再開せず新要求で復帰すること、およびinflight校正喪失とgen++の同edgeでSTALEが正しく返ることを独立に検証する。

合格した採取位置をP4のNEG／POS設定全体の合格とは扱わない。`memv1-fastreply-limitations-2026-11-05.json`には、TX5MHzでWR4KiBがCRC_ERROR、20MHzでhost採取をraw立上り+25nsへずらすと短応答から不一致、という失敗条件を保存する。最初の失敗後の再試行・fallbackはしない。


## 合成とタイミング制約

Gowin Education 1.9.11.03、GW2A-LV18PG256C8/I7、既存の398.25MHz DDR PLL設定を使う。旧Sipeed IPはSHA検証してGit管理外に置き、FSもGitへ入れない。

```powershell
python fpga/mem/tests/prepare_memv1.py --fast-reply --ip-src D:/esp/sipeed/TangPrimer-20K-example/DDR-test/LicheeTang20K_DDR_Test/src/ddr3_memory_interface/ddr3_memory_interface.v
$env:MEMV1_FAST_REPLY='1'
& D:/Gowin/edu-x/Gowin_V1.9.11.03_Education_x64/IDE/bin/gw_sh.exe fpga/mem/config/build_memv1.tcl
python fpga/mem/tests/record_fastreply.py --output fpga/validation/memv1-fastreply-pnr-2026-11-05.json
```

生成先は`fpga/build/memv1-fast/`。通常版は従来の`fpga/build/memv1/`で、`--fast-reply`を付けず、環境変数`MEMV1_FAST_REPLY=0`でビルドする。

新しい返信経路を隠さないため、高速版では継承SDCのblanket `set_clock_groups`を、従来のSYS／memory／USER間だけの明示的なclock-pair false pathへ置換した。metadata束は`set_max_delay 37ns`と限定hold例外を設定する。5つのmetadata familyそれぞれのreportを必須とし、全体のworst pathだけで被覆を判断しない。samplerへ入るactivityとSYSへ戻る5つの状態観測は、**各同期初段Dの6pinだけ**を例外にする。同期後段は通常STAを残す。

最終USERCODE、FS SHA-256、資源、setup／hold違反数、familyごとの報告path数とslack、RTL／ビルド入力のSHA一致は`memv1-fastreply-pnr-2026-11-05.json`に記録する。元のDDR診断向けclock-pair例外は残っており、DDR内部の全CDC／外部IOの往復遅延を含む完全なタイミング認定ではない。
