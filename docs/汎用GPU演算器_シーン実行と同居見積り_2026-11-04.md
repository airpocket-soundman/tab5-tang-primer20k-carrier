# 汎用GPU演算器：5シーン実行（RTL）と同居見積り

2026-11-04。ブランチ `claude/compute-simd`（mainへ未マージ）。実機・Dock・JTAGには触れていない。先行：[v2拡張とGowin配置配線](汎用GPU演算器_v2拡張とGowin配置配線_2026-11-04.md)。

## 1. 54MHz未達の原因と対策（Gowin STA）

v2の最悪パスは、命令メモリ(BSRAM)出力 → オペランド選択(16:1 mux、ファンアウト約477) → DSP乗算(約3.8ns) → MULSH/MULQの可変シフト → 書込み選択 → レジスタ、を1クロックで通す経路（論理14段、データ遅延約25ns）。対策：パイプラインを FETCH → RD(オペランド・述語をレジスタ化) → MULST(積をレジスタ化) → EXEC の4段にした。命令あたり2クロック増える（性能は下がる）。

| 構成 | 制約 | Fmax | setup違反 | LUT+ALU | FF |
|---|---|---|---|---|---|
| 1レーン | 54MHz | 54.82MHz | 0 | 3668 (18%) | 1158 |
| 2レーン | 54MHz | 54.06MHz | 0 | 7435 (36%) | 2354 |
| 2レーン | 72MHz | 65.99MHz | 1280端点 | 7435 | 2354 |

2レーン54MHzの余裕は+0.06MHzで、1回の実行（seed探索なし）。入出力制約なし、PLLなし、配置配線専用ラッパ（`tests/pnr_top.v`）での結果。72MHzでの最悪パスは b レジスタ → 比較/加減算のキャリーチェーン → 結果選択 → レジスタ。次の段（比較・加減算の分割）が必要。記録：`fpga/validation/compute-simd-gowin/pipelined_*`。回帰（630条件+adapter 7シナリオ）は維持。

## 2. 5シーンの実行結果

方法：`claude/track-l-scenes`（`99728c7`）のDSLプログラム（`fpga/reference/scene_isa*.py`、byte同一のコピー）を、`fpga/gfx/compute/scenes/backend.py` で v2 ISA の機械語へコンパイルする。DSLの仮想レジスタは r2〜r13（12本）に割当て、足りない分は要素ごとのメモリ領域（`SPILL_BASE + id*スロット数 + slot`、`[r14+slot]`）へ退避する。定数はレジスタに保持せず使用時に再生成し、ループ先頭ではレジスタ内容を全てメモリへ書き戻す（キャッシュ空）。述語下の再定義は、既存値があればそのレジスタへ、無ければ0で初期化してから書く。照合は3段：①DSLのnumpyシミュレータ、②`model.py`でのコンパイル済み実行、③`compute_simd`のVerilog RTL（`tests/tb_compute_simd.v`、全メモリ・全レジスタ・メモリ要求列を比較）。CPU整数参照がある範囲はそれとも比較。

**全て不一致0**（`fpga/validation/compute-simd-scenes-2026-11-04.json`）。ただし規模は縮小しており、**640×360の全画面ではない**。RTLのメモリは理想（応答遅延数クロック、受付停止なし、DDR3なし）。

### 2.1 track-l からの追加要望と回答

要望の優先順（track-l 受領）と今回の判断：
1. レジスタ不足：ローカルメモリ（BSRAM）+ LLOAD/LSTORE が第一案。今回のバックエンドは外部メモリへ退避しており、BSRAMがあれば退避を1〜2クロックにできる。**未実装**。
2. 基底レジスタ：未実装。LUI+ADDIで代替（今回のバックエンドは `r14` を退避ポインタに固定使用）。
3. CLEAR省略フラグ：未実装。現状グループごとに16クロック。Particlesの実測ではRTL 1グループ約505サイクルのうちCLEARは16（約3%）で、4段パイプライン化後は支配的ではない（命令数だけで見た場合の比重は大きい）。`ジョブフラグ(no_clear)`は効果が小さいため優先度を下げる。
4. ORI/XORI/LTUI：未実装。
5. DIV並列化：未実装。**x/0の規約は v2: DIV=-1、REM=a**（track-lのシミュレータが今 a を返す箇所は本ISAに合わせて修正が必要）。
6. DMA、7. ISQRT：未実装。

確認事項への回答：
- **PK565**：入力 `0x00RRGGBB` の各成分上位ビット（R=[23:19], G=[15:10], B=[7:3]）をそのまま詰める（切捨て、丸めなし）。出力は16bitゼロ拡張。入力のbit[31:24]は無視。**UP565**はビット複製（`r5<<3|r5>>2`、`g6<<2|g6>>4`）で `0x00RRGGBB` に戻す。
- **SAT8**：符号付き32bitを [0,255] にクランプ（負→0、255超→255）。丸めなし。
- SELの条件は書込み前の `r[d]`（dst兼用）。バックエンドは条件を先に `ADD d,c,r0` でコピーしてからSELしており、+1命令。

## 3. 資源使用率と同居見積り（LINK／GFX／DDR3）

方針（`docs/FPGAデバイス構成_ビットストリームと機能.md`）は、異なる機能の同時搭載は資源・性能の計測で問題がない組合せだけ、GFXとNPUは乗算器・BSRAM・DDR3帯域を取り合うため同時搭載しない。

デバイス：GW2A-18（LUT4 20,736、FF 15,552、BSRAM 46、DSPブロック24）。

| 要素 | 資源 | 出典・状態 |
|---|---|---|
| compute 1レーン | LUT+ALU 3668、FF 1158、BSRAM 1、DSP 2 | Gowin gw_sh、ラッパ込み（ラッパのFF約360を含む） |
| compute 2レーン | LUT+ALU 7435(36%)、FF 2354、BSRAM 1、DSP 4 | 同上 |
| 既存 LINK+GFX（fastreply, 54MHz） | LUT4 5343、DFF 2141、BSRAM 2、MULT18X18 21 | `fpga/validation/artifacts/gfx-fastreply-2026-11-04.json`（別ツール・別ビルドの集計で、Gowin gw_shの数え方と同一ではない） |
| DDR3コントローラ（Gowin IP） | **本リポジトリに実測なし** | 未測定のため見積りに含められない |
| HDMI、メモリadapter、CDC | 未測定 | adapterはLUT数百規模の見込み（未合成） |

見積り（保守的、加算のみ）：
- compute 2レーン + 既存LINK+GFX全体 = 7435 + 5343 = **12,778 LUT（62%）**。computeはGFXの代替で、GFXの描画回路は載せないので、実際の合計はこれより小さくなる見込み（LINK+共通基盤の分離値が無いため差し引けず、上限として扱う）。
- 残り（20,736 − 12,778）= 約7,958 LUT をDDR3コントローラ・HDMI・adapterで使える計算。DDR3 IPの実測が無いため**収まるかどうかは未確定**。
- 乗算器：compute 2レーンでDSP 4/24。GFXが使う21個のMULT18X18と併載すると合算で足りるが、GFXの代替であれば競合しない。NPUとは取り合うため従来どおり同時搭載しない。
- BSRAM：命令メモリ1。ローカルメモリ（スピル用）を載せるなら1レーン数KBで数個。余裕はある。
- クロック：2レーンは単独ラッパでぎりぎり54MHz（余裕0.06MHz）。DDR3・LINKと同居すると配置が混むため、**54MHz維持は未検証で危うい**。27MHzなら余裕がある。コンピュートクロックとDDR3コントローラクロックの境界にCDCが必要（現adapterは単一クロック前提）。
- 帯域：現在の演算器は1要求ずつ、adapter込みで1語あたり数クロック。54MHzなら概算で最大10M語/秒（約40MB/s）級で、burst/coalescing未実装のため、DDR3の帯域を使い切れない。画面全体（640×360の1語/画素）の処理は、Galaxy解決の実測（650,240要求、9.6Mサイクル/窓）のように、フレーム単位では桁違いに遅い。実フレームレートは未算出。

**結論**：LUT・DSP・BSRAMだけを見れば、computeを1/2レーンでGFX相当の位置づけで載せる余地はある（上限見積りで62%、DDR3前）。しかし(a) DDR3コントローラ・HDMIの実測値が無い、(b) 54MHz維持が同居で未検証、(c) CDC未実装、(d) 帯域はburst化とローカルメモリ前の水準、のため、**同居可能とはまだ言えない**。次に必要な測定は、LINK+共通基盤+compute+DDR3 IPを一つのトップで合成・配置配線し、LUT・FF・DSP・Fmaxを取ること。計画の判定表（資源・性能の計測）に従い、それまでは「単独のCOMPUTEビットストリーム」または「GFX置換」として扱う。
