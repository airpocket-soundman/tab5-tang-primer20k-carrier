# 汎用GPU演算器 拡張ISA・実行モデル設計

2026-11-04。ブランチ `claude/compute-simd`（mainへ未マージ）。実機・Dock・JTAG・COM4には一切触れていない。

方針（ユーザー指示）：フラクタル等の専用APIをFPGAに入れず、**グラフィック全般に使える汎用GPU**にする。Julia等は「この演算器で動かすプログラム」の一つであり、専用opcodeや専用回路は追加しない。ベース（v0）は[compute README](../fpga/gfx/compute/README.md)、[オフライン開発記録](汎用GPU演算器_オフライン開発_2026-11-04.md)。

## 1. v0の評価（不足）

| 領域 | v0の状態 | GFX汎用性への影響 |
|---|---|---|
| メモリ | 32bit word単位・1要求ずつ直列、レーン順 | 画素(8/16bit)アクセス不能、フレームバッファ書込みで隣接画素を壊す、帯域不足 |
| ALU | 加減乗・Q12乗算・比較・AND/XOR・shiftのみ | 最小/最大/絶対値/クランプ、画素変換が数命令の手書きになる |
| 除算・逆数 | なし | 透視除算、正規化、1/z、ライティングが書けない |
| 型変換 | なし（整数/Q12のみ） | float16/int/Q12/画素形式の変換が定式化されていない |
| 分岐発散 | 全レーン共有PC、述語r15をプログラムが手書き | ネスト条件のマスク保存・復帰が高コスト、バグ源 |
| 起動 | group_base+レーン数の固定幅、末尾はプログラム側マスク | 任意要素数のdispatch不可 |
| ローカルメモリ | なし（レジスタ16本のみ） | タイル/LUT/係数の再利用不可、外部メモリ往復 |

## 2. 拡張ISA案

32bit命令形式（opcode[31:26]、pred[25]、dst[24:21]、a[20:17]、b[16:13]/imm16[15:0]）は維持。opcode空間は6bit=64のうちv1で0..26を使用、27..63が予約（不正opcode=error1）。

### 2.1 v1（今回RTL・参照実行器・試験に実装）

| opcode | 命令 | 意味 |
|---|---|---|
| 15/16 | MIN / MAX d,a,b | signed最小/最大 |
| 17 | ABS d,a | 絶対値（INT_MINはwrapしてINT_MINのまま） |
| 18 | SAT8 d,a | signedを[0,255]へクランプ（画素成分） |
| 19 | PK565 d,a | `0x00RRGGBB`→RGB565（各成分の上位bit、16bitゼロ拡張） |
| 20 | UP565 d,a | RGB565→`0x00RRGGBB`（5/6bitをbit複製で8bitへ。0x1f→0xff） |
| 21/22 | LDB / LDBS d,[a+imm] | **byteアドレス**で1byte読込み、ゼロ/符号拡張 |
| 23/24 | LDH / LDHS d,[a+imm] | byteアドレス・2byteアライン、ゼロ/符号拡張 |
| 25 | STB d,[a+imm] | r[d]の下位8bitを1byteへ書込む（write mask） |
| 26 | STH d,[a+imm] | r[d]の下位16bitを2byteへ書込む（write mask） |

メモリ規則：
- 既存 LOAD/STORE は従来どおり **wordインデックス**（互換維持）。LDB〜STH は **byteアドレス** `(r[a]+simm16) mod 2^32`。
- メモリポートに `mem_wmask[3:0]` を追加。`mem_word_addr` は常にwordインデックス（byte命令は `byteaddr>>2`）。書込みの `mem_wmask`：STORE=4'hF、STB=`1<<addr[1:0]`、STH=addr[1]?4'b1100:4'b0011。読出しは0。リトルエンディアン。
- STB/STHの `mem_wdata` は値をレーンへ複製した値（STB: `{4{v[7:0]}}`、STH: `{2{v[15:0]}}`）で、アダプタはmaskの立ったbyteだけを書く。LDB/LDH系はワード全体を読み、演算器側でbyte選択・拡張する。
- LDH/LDHS/STHのアドレスbit0=1（アライン違反）は、**有効レーンのいずれか**に該当すればメモリ要求を一切出さずerror 6で停止（述語で無効のレーンは検査しない）。範囲外アドレス・応答エラーは従来どおりerror 4。
- 新errorコード：6=halfwordアライン違反。1..5は不変。
- アダプタ（DDR等）への要件：write mask対応が必須（DDR3のデータmask/byte enable）。mask非対応のメモリ（読み書き修飾ができないもの）は read-modify-write をアダプタ側が担う。

### 2.2 v2以降の提案（未実装、優先順）

1. **ローカルメモリ（スクラッチパッド）**：BSRAM1〜数個（例 2KB〜8KB）をレーン共有の `LLOAD/LSTORE`（word/half/byte）で。外部メモリ往復なしにタイル、LUT（sin/テクスチャ/ガンマ）、係数を再利用。GW2A-18のBSRAMは46個。
2. **burst・coalescing**：同一命令内の連続レーンアドレスを検出し1つのburst要求（長さ=LANES語）に結合。`mem_len`を追加し、非連続は現行の直列にフォールバック。DDR3 BL8（128bit×…）との整合は別途アダプタ設計。
3. **除算・逆数**：`RCPQ d,a`（Q12の1/x、反復法または小LUT+Newton）と `DIVQ d,a,b`。多サイクル（レーンごと直列）で、`busy`中は命令完了を待つ。除算0の結果は飽和値、符号付き。専用乗算器2個(MULT36X36)の再利用を優先し、LUT消費を抑える。
4. **型変換**：`I2Q/Q2I`（整数↔Q12）、`CVT_F16`（float16↔Q12）。浮動小数点ALUの本格実装（fp16 add/mul）は資源計測後に判断。Q12固定小数のみでも2D/簡易3Dは成立する。
5. **画素形式の拡充**：`PK8888/UP8888`（4成分の詰め/展開）、`PK332`、アルファブレンド用の `LERP8 d,a,b`（`a+(b-a)*t>>8`）、`MULH8`（8bit×8bit正規化乗算）。
6. **分岐発散**：プログラムの手書きmaskを、`IF a`/`ELSE`/`ENDIF`（マスクスタック、深さ4〜8、スタックはレーンごとのビット列）で置換。pred用r15は引き続き使え、`ANY`による全レーン不活性時のスキップも維持。独立PC・自動再合流はコスト過大のため採らない。
7. **任意要素数dispatch**：起動引数に `count` を追加し、`id=group_base+lane` が `count` 以上のレーンは起動時にr15相当の初期マスクで無効化。1ジョブでの `gridsize` と `groupsize` を分離し、ホストがループ起動する現行方式と両立。ジョブ内ループ（`group_base`自動加算）は別途。
8. **tag/abort/timeout**：現状アダプタ任せ。ジョブID、タグ付き応答、abortでin-flight応答を排出する手順を、LINK統合時に仕様化する。

### 2.3 実行モデル

- **SIMD**：共有PC・共有命令メモリ、レーンごとに16×32bitレジスタ。メモリ命令は有効レーンをレーン順に直列実行（v1）。v2のburst/コアレスで並列化。
- **述語**：pred=1の命令は、命令開始前のr15≠0のレーンだけ実行。メモリ要求・アライン検査も無効レーンは対象外。
- **ジョブ**：停止中にプログラム書込み→`entry/group_base/instruction_limit`で起動→HALTまたはerrorで`done`。プログラムはジョブ間で保持、リセットで失効。
- **汎用性の確認方法**：同一RTLでJuliaカーネル・配列affine・RGB888→RGB565変換・byte/halfwordコピーなど互いに無関係なプログラムが動くこと、専用opcodeが無いことを試験で確認する。

## 3. 実装・検証（v1）

実装：`rtl/compute_simd.v`、`model.py`（アセンブラ兼参照実行器）、`tests/run_compute.py`・`tests/tb_compute_simd.v`。試験側は、モデルのtrace（write/addr/data/**mask**）とRTLのmem要求を要求ごとに照合する。

- 既存264条件はコードを変更せず回帰（乱数列も不変）。追加は新しい乱数列で150条件。計414条件×2起動、1/2/4レーン、受付停止あり/なし。
- 新規試験：MIN/MAX/ABS/SAT8/PK565/UP565のランダム組合せ(述語含む)、独立Python式によるスカラー意味の照合、RGB888→RGB565の`STH`/`LDH`往復、byte配列オラクルによるLDB/LDBS/LDH/LDHS/STB/STHのbyte単位検証（隣接byte保存）、STB r0、アライン違反(error6、レーン1のみ違反、述語で除外)、byte範囲外/負アドレス/応答エラー、境界opcode(26有効・27不正)。
- ミューテーション確認：STHのmaskを故意に反転したRTLで、同じ試験がFATALで失敗することを確認（試験が実際にmaskを見ている）。
- 結果・ツール版・ソースSHA-256・Yosys統計は[検証JSON](../fpga/validation/compute-simd-ext-2026-11-04.json)。

## 4. 配置配線・STA（OSS nextpnr-himbaechel、試行）

**Gowin EDA 1.9.11.03：`D:/Gowin/` にはインストーラ(`Gowin_V1.9.11.03_Education_x64_win.exe`)があるだけで未導入のため、`gw_sh`による配置配線・STAは未実施。** 代わりにOSS CAD Suiteのyosys `synth_gowin` + `nextpnr-himbaechel`（`GW2A-LV18PG256C8/I7`、family GW2A-18）を使った。

条件と限界（重要）：
- コアは約300bitのポートを持ち、PG256に出せない。`tests/pnr_top.v`はPnR専用ラッパで、入力を1本のシリアルシフトレジスタ、出力を全bitのパリティ1本に縮約。ラッパのFF（約600）を含む。実機向けトップ、実ピン、実クロック制約ではない。ピン(H11/T10/C7)は`.cst`が必要なため適当に割当てただけ。
- 目標50MHz（Dockの27MHz発振器ではない。PLL未使用）、seed=1、1回の実行。nextpnrの遅延モデルはGowin公式STAと一致する保証がなく、**タイミング署名ではない**。
- 保存ログ：`fpga/validation/compute-simd-pnr/`。

| 構成 | LUT4 | DFF | ALU | MULT36X36 | BSRAM | 配線後Fmax(50MHz目標) |
|---|---|---|---|---|---|---|
| v0 1レーン | 4326 (20%) | 1217 | 254 | 1 | 1 | 61.0MHz 合格 |
| v1 1レーン | 6502 (31%) | 1230 | 334 | 1 | 1 | 53.8MHz 合格 |
| v0 2レーン | 8639 (41%) | 1765 | 392 | 2 | 1 | 59.2MHz 合格 |
| v1 2レーン | 11082 (53%) | 1833 | 540 | 2 | 1 | **48.9MHz 未達(50MHz)** |

- v1の拡張で2レーンのLUT4が約+2.4k(+28%)、Fmaxが約-10MHz。主因は、レーンごとに増えたALU出力mux、byte/halfword用のload整形・書込みmask・レーンアドレス保持で、レジスタファイルがFF+巨大MUXで実装されている構造（BSRAM/分散RAM未使用）に新命令が乗った結果と考えられる（原因の切り分けは未実施）。
- 2レーン50MHzは未達。クリティカルパスは命令メモリ出力(`program_mem` BSRAM)から始まる（クロックtoQ 2.26ns）。1レーンは50MHzで合格。
- 4レーンは未試行（2レーンでLUT53%のため、レジスタファイル構造の見直し前は収まりが厳しい見込みだが未計測）。DDR3・LINK・GFX・NPUとの併載、電力、実機動作は未検証。
