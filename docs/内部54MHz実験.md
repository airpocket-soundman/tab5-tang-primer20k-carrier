# Experimental 54MHz internal core clock

This branch preserves external Dock pins/electrical levels and the27MHz H11 oscillator. A dedicated rPLL makes54MHz internally (IDIV_SEL0, FBDIV_SEL1, ODIV_SEL16; VCO864MHz). Existing27MHz tops retain their behavior and no clock-query capability. This is an experimental image, not yet hardware verified.

Linux/MeOS have no implemented fractal-clock integration in these reviewed sources. Pins, packet bytes and drawing arithmetic do not change. Updated ESP-IDF host is required for correct54MHz timing interpretation; older hosts that ignore unknown INFO bits can still render matching pixels but incorrectly divide device cycles by27MHz. This incompatibility is explicit, not silently treated as compatible timing.

Optional capability: FRACTAL_INFO bit3 means CORE_CLOCK query supported;54MHz image returns020f (version2 requires a valid clock query). CORE_CLOCK/FRACTAL_CLOCK_MHZ opcode3d accepts zero arguments, returns integer MHz1..200 in result (54 for this image). Bad arguments status3. Default old27MHz tops keep INFO0107 and unknown-command status2 for3d. New host accepts version2 only with the required timing/clock capabilities, queries the clock, aborts if query/CRC/range invalid, and uses explicit27MHz fallback for legacy0107.

The54MHz top holds the platform asynchronously reset until PLL LOCK and external reset are asserted. Existing reset release and ARM synchronization remain; raw ARM/reset removal still immediately disables output drive. Timeout doubles to5400000 cycles to retain100ms. Heartbeat interval changes with the internal clock. A behavioral PLL model tests lock/reset policy and nominal clocks only; analog PLL behavior requires hardware validation.

The build variant triangle54 uses the same CST, explicit27MHz input and54MHz internal nextpnr SDC clock constraints, and a separate reference SDC generated-clock relation. Installed WASM nextpnr exposes --sdc but no Python pre-pack support; its generic parser supports create_clock rather than create_generated_clock. The implementation flow must report the internal clock constrained at54MHz; a nominal54MHz --freq alone must not be mistaken for an oscillator constraint or actual PLL frequency measurement. Routed timing and resource counts must pass before programming.
