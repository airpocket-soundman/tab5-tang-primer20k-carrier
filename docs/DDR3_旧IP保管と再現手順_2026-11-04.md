# 旧IP（Sipeed DDR-testのDDR3 IP）の保管と再現手順（2026-11-04）

`sampleip`／`sampleip_map` は、Sipeed公式サンプルに含まれる**旧ツール（GowinSynthesis 1.9.8.05）が生成したDDR3 IP**（暗号化）を使う。方針（ユーザー指示）：**IPはリポジトリにコミットしない。ローカルに保管し、入手方法と検証方法を明記し、ビルドは保管物の存在とSHA-256を確認してから進む。**

## 2. ローカルの保管場所
1. **ビルドが参照する場所**：`fpga/build/sipeed-ddr-test-e469df4c/`（各ワークツリーの `fpga/build/`）。`fpga/.gitignore` が `build/` を除外しているため、**git追跡されない**（`git check-ignore -v` で確認済み）。
2. **メインセッションのクローン（原本のコピー）**：`D:\esp\sipeed\TangPrimer-20K-example`（`DDR-test/LicheeTang20K_DDR_Test/` 以下）。CRLF変換されている場合があるが、LF正規化SHAは一致する（検証済み）。
3. 別のPCで再現するときは、`python fpga/tools/fetch_sipeed_ddr_ip.py --download`（ユーザー許可が必要なネットワーク取得）か、上記URLからcommitを固定して取得し、`--dest` で場所を指定して検証する。

## 3. 検証コマンド
```
python fpga/tools/fetch_sipeed_ddr_ip.py                         # ワークツリーのfpga/build配下を検証（既定）
python fpga/tools/fetch_sipeed_ddr_ip.py --dest D:/esp/sipeed/TangPrimer-20K-example/DDR-test/LicheeTang20K_DDR_Test   # クローンを検証
python fpga/tools/fetch_sipeed_ddr_ip.py --download              # 欠けているファイルを取得（要許可）→検証
```
全ファイル一致で `OK: all 13 files match the pinned hashes`、欠落・不一致があれば `FAIL: [...]` と終了コード1。

## 4. ビルド前の検査（運用）
- `prepare_variant.py sampleip|sampleip_map` は、上記の検証に失敗すると**停止**する（`SystemExit`、保管物が無い／改変されている）。
- `build.tcl` は、`sampleip`／`sampleip_map` で `ddr3_memory_interface.v` が存在しなければエラーで止まる。
- 試験：保管物の1ファイルを書き換えると検証が `sha256 mismatch` で失敗する（確認済み）。ただし、`build.tcl` 自体はSHAを計算しない（存在のみ）ので、**必ず `prepare_variant.py` を先に実行する運用**（`build_variants.ps1` はこの順）。
- 記録するとき：ビルド記録（`mem-variants-prehardware-2026-11-04.json`）には、使ったIPファイルのSHAをこのドキュメントの固定値で参照する。

## 5. 限界
- IPが暗号化されているため、スケジューラ観測（024f）が出ない。アドレスは14行幅のレイアウト（`sampleip_map` で対応）。
- 旧IPがなぜ校正を通せるのか（DLLの`CODESCAL`／`SCAL_EN`、DQ用IODELAY、コマンド／CK用IODELAY 40）は、ネットリストの比較による仮説で、確定していない（`docs/DDR3_公式サンプルとの差分一覧_2026-11-04.md` 6章）。
