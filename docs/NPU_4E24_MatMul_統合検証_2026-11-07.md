# NPU 4E24：DDR MatMulジョブ統合検証（2026-11-07）

4E24は、[単体MatMulシーケンサ](NPU_DDR_MatMulシーケンサ_単体検証_2026-11-07.md)を既存8OC loader/DDR adapterへ接続し、行列1件の要求でK/M/NタイルをFPGA内から実行する別候補である。4E23とその復帰FSは変更していない。新capability4E24を要求し、既存4E20 hostからの自動選択・fallbackは行わない。

wireの36B/9u32LE配置・CRC・エラー・session・host反映範囲は[Matrix V1仕様](NPU_DDR_MATRIX_V1.md)、共有定数は `fpga/npu/protocol/npu_matrix_v1.h`。SYS/core/top/buildは新規ファイル。新0x78により、INT8 A/BからINT32 CをDDRへ書き戻す。FP32 scale/bias epilogue、LayerNorm/Softmax/GELU、全graphの自律実行はまだ接続していない。

## RTL統合試験

`python fpga/npu/tests/run_ddr_matrix_core.py` で、実SYS/framer・sequencer・loader・8OC engine・arbiter・CDC bridge・mem_adapter・共有staging RAMを接続した。native DDR側だけを応答遅延付きモデルとする。APP_ROW_PADのnative addressを逆変換して正しいbyte addressを検査し、128MiB上端も既存試験から維持した。物理DDR PHYやジャンパ線の試験ではない。

178コマンドに合格した。元のCRC WRITE/READ、0x68 Conv ICブロック、generation/session、校正喪失、ARM、reset、再生防止に加え、以下を検証した。

| M×K×N | 自律tile数 | 数値出力 |
|---|---:|---:|
| 1×17×9 | 4 | 9 |
| 197×17×9 | 4 | 1,773 |
| 257×17×9 | 8 | 2,313 |
| 1×17×197 | 50 | 197 |

4 RUNから66 tileを実行し、4,292個のINT32結果が独立NumPy INT64 MatMul参照と一致した。M paddingはzero、channel pitch gapのA5 sentinelは不変。0x79とaccepted/completed32bit countも照合した。不正payload CRC後はcountもCも変化しない。M=65536は上位bitを捨てずcode1へ拒否し、その後0x67の再利用を拒否、DISARM協調resetで回復する。

実descriptor readyを停止し、accepted/completed/progressが0であることを確認した後、watchdog期限境界を注入してabort・書込みなし・numeric result無効を検査した。busy/readyの固定highを進捗にしない。またMATRIX実行中にDDR要求を保持して校正を落とし、status8・result無効・token解除を確認した。進捗更新はcoreのaccepted/completed counterの実変化だけから生成する。

確定試験は `fpga/build/npu-ddr-matrix-core-qualified`。TBのhost half-periodは200nsの理想デジタル信号であり、実測周波数やPHY認定ではない。最初の遅いTB実行は試験時間短縮のため途中停止し、数値の判定には用いていない。8個のbuildソースとproofコピーは、module名・LF正規化、およびlegacy TBのsource listに合わせたsequencer連結以外が同一であることをアーカイブのequivalence記録で確認した。

## hostと次段階

既存DeiTの74 MatMulは122batchesを含み、このRTLの1job=1batchでは最少122 RUNになる。主担当の初期host backendは、N≤8/M≤256のpanel単位でK全体をRUNへ渡す方式で、122件より多いpanel jobsとなる。元のgraph全Nを1RUNへ渡したという主張はせず、panel job数・内部tile数・wire commandsを区別する。この段階でもK16ごとのhost往復は削減できる設計だが、実測の効果は別途記録する。

従来2秒のhost待ちとは別に、4E24専用のbounded whole-job待ちとDISARM失敗処理が必要になる。AのbaseをM panel分ずらす場合、保守的なK×A_pitch予約範囲が後続Bへ触れない追加guardをhostが確保する。所有範囲・lease・paddingの契約を維持し、既存の8列slabを元graph全Nの領域と誤認しない。

host backendと物理試験の確定値は末尾に追記する。Linux/MeOS側の新APIは未実装で、参照した版と未確定範囲はMatrix V1仕様に記録した。DDR MatMul command統合は、画像→全NN FPGA内部→結果のみという最終目標の一部であり、P4 activation配置を最終形とするものではない。

## 追記：4E24/V15実機のcold/warm試験合格

本節は完了した4E24候補の履歴であり、現在の機器書込み状態を示すものではない。主担当はこの試験後、4E23へ復帰する手順で別のYOLO/UIデモ検証を進める。以降の現在状態は主担当の機器記録を参照する。

主担当が4E24をSRAMへ書込み、USER4E24/status6020を確認した。V15 host ELFは `0f69c3c7ab78a7a7b2f75424bd126b3ba9782201d63c316da88c84fba9726e7c`。legacy selftest5,208比較と、生行列197×17×9の1,904比較に合格した。後者はM paddingを含む1,872個のINT32比較と、出力前後32 byte guardの検査であり、有効数値出力1,904個という意味ではない。

その後CREW初回・ASTRONAUT再利用が両方成功した。各frameとも12ブロック、199操作、74 FPGA MatMul、122batches、51,468内部tiles、CPU MatMul0。hostはN≤8/M≤256 panelごとにK全体をRUNし、1frameの実行は3,929 matrix panel jobsだった。122 RUNや元graph全Nの一括実行を達成したとは扱わない。

CREW出力SHA256 `ee03e13dffb253c886318761969da2fd3de6ae40f41e10ca0eeb24544525240b`、ASTRO出力SHA256 `102995be897310f8dbd2a3ab8a9406346425e1071e6b950e979bcdc65314e70d`。独立した同一P4 CPU INT8参照との比較は両方1000値全bit一致、unequal_bits0/max_abs0。cookie1と50件の静的量子化Bを維持して完了frame数が1→2へ進んだ。

| 計測 | 時間 |
|---|---:|
| 常駐session準備 | 138.133369秒 |
| CREW初回 推論 /frame全体 | 108.445019 /108.667357秒 |
| CREW初回 準備を含むcold全体 | 246.800726秒 |
| ASTRO再利用 推論 /frame全体 | 108.673595 /108.979505秒 |
| 同P4 CPU ASTRO 推論 /全体 | 62.481998 /73.224470秒 |

4E23/V14再利用推論115.796370秒との履歴比較では7.122775秒（約6.15%）短縮した。各frameのwire bytesは37,110,044→33,719,450B（3,390,594B減）、host演算要求数は51,468 tile要求→3,929 matrix panel要求へ減った。これは記録した2構成の比較であり、他のhost変更・測定変動を分離した単一変更の反復A/Bとは扱わない。現状はなお同画像のCPU推論より遅い。

要求TX設定は正極性10,000,000Hz。cold完了→warm完了の累積DMA requests/wire_bytes/elapsed_us/allocations/unit_allocations差分はすべて0なので、warm frameの10MHz DMA送信実績とは主張しない。全wire bytesとDMA専用counterを分ける。cycle counter samplingも無効で、kernel/DDR cycles=0は処理時間ゼロではない。

[別保存した実機証跡](../fpga/validation/npu-ddr-matrix-4e24-physical-2026-11-07/checkpoint.json)に書込みlog、legacy/raw selftest、最終result、CPU/COLD/WARM生FP32、status、画面、trial log、provenance、独立SHAを保存した。host側の[原本physical archive](https://github.com/airpocket-soundman/tab5-fpga-gpu/tree/codex/resume-20261106/docs/validation/npu-matrix-4e24-2026-11-07/physical)24ファイルのSHAを検証してから必要部分をコピーした。V15 firmware本体/source snapshotはhost側に残し、carrierへ重複保存していない。コピーしたhost原本manifestにはその除外ファイルも含まれるため、carrierでの検証は別のSHA256SUMS.jsonを用いる。既存オフライン35 hash manifestは変更していない。

FPGAが担当するのは全MatMulで、P4 activation配置・量子化・LayerNorm/Softmax/GELU等は残る。通信も画像と結果だけにはなっていない。無例外STA未認定の条件も維持する。次のFP32連結については[資源評価と最小案](NPU_4E24後_FP32連結資源評価_2026-11-07.md)を参照し、4E24実機試験中に演算部のproduction変更は行っていない。
