# 引継ぎ資料（2026-11-05、Codex向け）

Claude（Sonnet 5.5）のセッションから Codex へ開発を渡すための資料。**状態の正本は `docs/引継ぎ_2026-11-05_第2版.md`**（`main` 48f91f1 時点）で、本書はそれに次を足す：このPCの環境、Claudeセッションがこのセッション内で実機確認したこと・オフラインで進めたこと、運用上の約束、落とし穴。実機で確認していないことは「未検証」と書いた。数値は記録元の資料から転記しており、本書の作成者が再測定していないものは「（記録）」と付けた。

## 0. 最初に守ること（ユーザーの方針・約束）

1. **実機の試験は、ユーザーが「止めて」と指示した状態で終わっている。** 再開はユーザーの指示を待つ。FPGAの書込みとTab5の書込みも、その指示の後に行う。
2. **実機に触れるのは1人（メイン）だけ。** COM4（Tab5）とJTAG（Dock）は、並列で複数のエージェントが触らない。作業中に一度、COM4が「使用中」で開けない事象があった（保持プロセスは特定できず、5秒後の再試行で解消）。Codexと並行する場合は特に競合に注意する。
3. **`main` へ勝手にマージしない。** 検証前のものは `claude/*` ブランチに置く運用。pushは各作業ブランチのみ。
4. **設計方針：専用API（フラクタル専用など）をFPGAに入れず、GFX全般に使える汎用GPUにする。**
5. **旧IP（Sipeedサンプル）はリポジトリにコミットしない。** ローカル保存し、入手方法を文書に明記する（`docs/DDR3_旧IP保管と再現手順_2026-11-04.md`）。ライセンス条件は未確認。再生成IPは検証して見込みがなければペンディング。
6. **DDR3の利用が最優先。並行開発は止めない。** 報告・説明は日本語。
7. 実証されていないこと（GPIO、電源、PARLIO DMA、転送性能、合成結果）を、実証済みとして書かない。FPGA DDR3は透過的なLinuxメインRAM増設ではない（`AGENTS.md`）。
8. ホスト側の仕様コピーは、本リポジトリを正とする。仕様・コマンド・ピンを変えたら、影響するホストへの反映要否を確認する（`AGENTS.md`）。

## 1. 現在地（要点）

詳細は `docs/引継ぎ_2026-11-05_第2版.md` の1・4・5章。

- **DDR3：** 旧IP＋自前ロジックで `sampleip_map_t4` が実機で合格（パターン、境界、128MiB全域、複数seed、10分soak）。`MEMV1`（RD／WR／CRC32）はGPIOで全段階合格、PARLIO＋DMAで 0.5/1/2MHz が合格（記録）。DDR3内部の帯域は約512MB/s（記録）。5MHzは低速PHY（27MHz同期）の限界で失敗。
- **GPU転送：** 基準線は20MHz連続RX。FPGAの応答位相イメージ（t4／t5、NEG）で25MHz・26.67MHzが全画素一致（記録）。32MHzは未達。ジャンパ線の物理限界とは断定していない。
- **Tab5最適化：** `host_prefill`、`reuse_stream_crc`、単体ベンチは実機確認済み（記録）。
- **再生成IP：** 400MHz／324MHz系の多数の変種で校正が通らず、ペンディング（5つの変種のstage1結果が `3299d99` に記録されている）。

## 7. 落とし穴

- **FPGA書込み：** 書込み直後の「Error found!」は既知。USERCODEとStatusが一致すれば正しい。`--cable-index 1` を使う（0は開けない）。
- **Tab5が `info` に応答しない：** 同じMEM probeファームを書き直すと復旧した。再現条件は未特定。
- **MEM probeの `--expected-elf-sha`：** ファームが申告する値と、手元のELFファイルのSHAは同じ値だった。コピーミスに注意。
- **`mem_stage_runner` のJSON：** 先頭のsnapshotは書込み相の途中値。最終値は `final`／末尾のsnapshotを読む。「PASS」でも先頭値の `verified_beats: 0` に惑わされない。
- **`record_variant.py`：** `clk400_notap` 系の判定が未対応の版があった（修正を依頼済み、`track-p2-ddr3-variants` で確認）。
- **opcode衝突：** 帯域測定（0x60〜0x6F）と `MEMV1`（0x60〜0x67）。別イメージで使い、同居させない。
- **BINのSHA：** 統合ファームのBIN SHAは、引継ぎ記録（`efb525cf…`）と今回のビルド（`dd448d5c…`）で一致しなかった。ツール版やパスの違いと見ているが未確認。同一バイナリとは扱わない。
- **`link_bringup_filtered.v` の衝突：** J・B・L・N が互いに衝突する。実機検証後に手作業で統合する。
