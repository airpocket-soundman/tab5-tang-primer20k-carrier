# FPGA応答位相の可変イメージ（トラックN、実験専用）

2026-11-04。実機に触れないオフライン作業。**RTLシミュレーション（機能同等性と遅延量）のみ。Gowin合成・配置配線・STA・実機は未実施。** `IODELAY` のポート名・パラメータ範囲はGowin UG289の記述に基づくが、ベンダーのシミュレーションライブラリが無く、ここでは未照合。

## 目的

25MHzでNEG・POSともに失敗する原因が受信窓のずれ（仮説A）なら、FPGAの応答データをP4のサンプル点に対して動かすと合格帯が動く。1つの変数（応答位相）だけを変えたイメージを用意し、ホスト側の位相（NEG/POS）と組み合わせて窓を探る（ホスト計画: `tab5-fpga-gpu` track-c `docs/dma-25mhz-isolation-plan.md` 実験2）。

## 構成

`link_bringup_filtered` にパラメータ `REPLY_PHASE_TICKS`（既定0）を追加。

- 0: 追加セルなし。`reply_clk = clean_reply_clk`で従来と同一。
- N>0: `reply_phase_delay` が整形済み返信クロックを216MHz標本クロックのNサイクル（約4.63ns×N、N=1..15で4.6〜69ns）遅らせる。パルス幅・間隔は不変。**シリアライザとBSRAM読出しポートの両方**が同じ遅延クロックで動くので、DATAだけが動くのではなく応答全体の位相が動く。

`platform/dock/tab5_dock_triangle54_filtered_phase_top.v`: 同ピンの`filtered_top`＋`REPLY_PHASE_TICKS`（粗調整）＋`REPLY_FINE_DLY`（0..127、各DATA出力に`IODELAY`の静的遅延、1段約18ps、DATA出力側のみ）。両方0で基準構成。

イメージ生成: `python fpga/builds/dock/make_phase_variant.py --ticks N`（または `--fine M`）で `fpga/build/phase-variants/phase_tN_fM/` にラッパtopと`build.tcl`を出す（ビルド・書込みはしない）。

## シミュレーション結果（`python fpga/link/tests/run_reply_phase.py --iverilog <iverilog.exe> --vvp <vvp.exe>`）

ticks 0/1/2/3/5/8/15 すべてで、情報・クリア・タイル（2066バイト）・DIR中断が機能し、ヘッダ／CRC／画素が一致、ホスト出力との衝突なし。ホスト2.5MHzでの、ホストCLK立上りからDATA変化までの最小遅延（ゲート遅延ゼロのモデル値）は 13.9／18.5／23.2／27.8／37.0／50.9／83.3ns で、追加分がticks×4.63ns（±1.5ns以内）に一致。**絶対値は実デバイスの遅延ではない。** `fpga/tools/run_existing_rtl.py` に `reply_phase` として組込み済み。

## 既知のリスク（実機で確認すること）

1. **OE/READY解除も遅れる。** 最終CLKを受けたシリアライザの`done`が遅延分だけ遅れるため、最後のバイト後にDATAを駆動し続ける時間がNサイクル分延びる。ホストがバスを取り戻す（ターンアラウンド）前に衝突しないか、`ticks`が大きいほど注意。シミュレーションでは100ns以内の解除を確認しただけ。
2. 遅延クロックでBSRAMを読むため、SYS側（54MHz）との境界の既存同期（`raw_done_sync`等）に影響しうる。CDC制約は未解析。
3. 位相を動かしても**CLK立上りの個数が増えているのが原因（仮説B）なら改善しない**。トラックJのエッジ数で先に切り分けるのが望ましい。
4. 216MHz標本クロック由来の量子化（4.63ns）より細かい位相は`REPLY_FINE_DLY`のみ。IODELAYの実遅延・温度依存は未測定。

## 実機での試験手順案（メインセッション用）

前提: 各イメージのFSのSHA-256とUSERCODEを記録。変えるのは**1変数だけ**。最初の失敗で停止、自動再試行・fallbackなし。

1. 基準: `make_phase_variant.py --ticks 0 --fine 0`（または既存`85bac224`）で20MHz NEG合格を再確認（ホスト設定は引継ぎ資料6章の基準線コマンド）。
2. 周波数を25MHzに固定、ホスト位相はNEGのまま、`--ticks 1,2,3,…`を1イメージずつ。各イメージで合否とCRC失敗位置を記録。
3. 同じ手順をPOSでも。合格帯が周期（40ns）内で連続して移動すれば仮説A。どのtickでも変化しないなら仮説Bまたは別原因。
4. 粗調整で合格帯に近づいたら`--fine`で細かく。
5. 各点でFPGAの`USERCODE`、Tab5ファームのSHA、ホスト設定をログに残す。
