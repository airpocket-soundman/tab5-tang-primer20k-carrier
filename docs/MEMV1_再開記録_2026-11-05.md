# MEMV1開発再開記録（2026-11-05）

基準資料は `引継ぎ_2026-11-05_第2版.md`。作業開始版はキャリア `48f91f1`、ESP-IDFホスト `dc2e9c4`。mainは変更せず、`codex/*` の作業ブランチで進める。実機操作は親エージェントだけが行い、並行担当はRTL・ホスト修正・オフライン検証を担当する。

## 対象実機と開始状態

- ユーザーが本プロジェクト用と指定したTab5：USB VID/PID `303A:1001`、USB serial `30:ED:A0:E2:FE:C0`。確認時はCOM4。別のTab5接続後もポート番号だけで対象を決めない。
- Tab5ファーム：`standalone_mem_bist_probe`、ELF SHA-256 `f2a278aae59b361ed97f8a7efedacfe7cc8ae4b9e0b858950068274752aba7c4`。DMA組込み済み、開始時はdisarmed。
- FPGA開始時の読戻しはUSERCODE `0x0573`、Status `0x6020`。第2版記載の `0xA692` とは異なり、開始イメージの機能は未特定。このイメージにはMEMV1要求を送らなかった。
- ピン、配線、電源条件、opcodeは変更しない。

## 基準線の復元と実機確認

旧Sipeed IPの固定13ファイルのSHA一致を確認し、ローカルでMEMV1を再ビルドした。旧IPとビットストリームはGit管理外に置く。現行HEAD版と旧記録のRTLを復元した版の両方で、コメント行を除外したFS SHA-256が旧合格記録と一致した。

`18821f3f7d957979be06aee0b8f6b8a806a40d144fdc6ea0acc28aef3a04450f`

SRAMのみへ書込み後、USERCODE `0xA692` とStatus `0x6020`を別操作で読み戻した。診断SDC下でSetup/Hold/Recovery/Removal違反0、最小Setup +0.057ns、Hold +0.074ns、66ピン一致。blanket async例外を含むため、これを全CDCの物理的な検証完了とは扱わない。

| 経路 | 試験範囲 | 結果 | 4KiB RD | 4KiB WR |
|---|---|---|---|---|
| GPIO | 全11段階 | PASS | 未分解 | 未分解 |
| DMA 0.5MHz | 全11段階 | PASS | 9741µs / 0.4205MB/s | 9775µs / 0.4190MB/s |
| DMA 1MHz | CANCEL以外の10段階 | PASS | 5553µs / 0.7376MB/s | 5598µs / 0.7317MB/s |
| DMA 2MHz | CANCEL以外の10段階 | PASS | 3479µs / 1.1773MB/s | 3525µs / 1.1620MB/s |

DMAはTX positive／RX positive。各試験の終了時にdisarmedを確認。各周波数1回の再現確認で、100回連続・温度・冷起動試験ではない。MB/sはファームが報告する1要求の時間に対する4096バイトの比で、PCのUSB操作・データ取得を含む時間ではない。

GPIO全試験では、不正要求14種、CRC不一致5種、末尾4KiB、CANCELを確認。既存RTL試験はMEMV1 209チェック（192参照ベクトル）を含め合格した。実機記録とソースハッシュは `fpga/validation/memv1-resume-2026-11-05/` に保存。

## 並行開発中の事項

- CANCEL：先頭WRと異なるCANCELのseqが返ると、ファームのDMA同期探索が拒否する。ホストの専用ブランチで修正・試験する。
- 高速返信：フィルタ付きクロック、返信serializer、読出しRAMの別クロックポートをopt-inで追加する。合成・STA・実機確認が済むまで高速版を既定にしない。
- 要求側：SYS27MHz同期のままTX5MHzを与えるRTL条件では、CAPSの要求CRCエラーを再現した。返信だけの置換でWR5MHzが成立するとは扱わない。まずTX2MHzとRX5〜20MHzを分けて評価する。

この節の高速版の結果はRTLモデル上の確認で、実機の帯域達成を示さない。進捗と最終の実機状態は検証後に追記する。

## CANCEL修正・周波数分離の実機確認

ホスト専用ブランチ `codex/memv1-cancel-sequence` のソース `3f53d16` を新規ビルドし、対象USB serialを再確認してTab5へ書き込んだ。書込みツールのハッシュ検査に成功し、起動後のELF SHA申告も一致した。

- BIN SHA-256：`3c1ea58a131f2933534746e3f3956b0de9907013a32616cd114beb61dd6b34dd`
- ELF／実行中申告SHA-256：`ea98777e43cbc926d342ecd8ab8386fa7e881c3a8b02cc1864734eae72246712`
- `mem_dma_split_rates=true`を確認。FPGAは復元した基準線 `0xA692`。
- 同一周波数指定0.5／1／2MHzで**全11段階合格**。1MHz・2MHzのCANCELは`cancelled`となり、未定義範囲・旧新ビートの照合・再書込みも合格した。
- 分離指定TX2MHz／RX1MHzでも全11段階合格。ARM前に設定ACKが指定した両周波数と一致することを確認した。
- 2MHzの4KiB RDは3482µs／1.1763MB/s。基準速度を維持した。周波数ごと1回の確認で長時間保証ではない。
- 全試験後にdisarmedを確認。記録は同検証フォルダーの`host-split-*.json`。

オフラインではnative326チェック、Python15件、実IDF HALによる許可8周波数の整数分周検証とESP-IDFビルドが合格。旧ファームでは分離周波数の能力申告がないため、ツールはARM前に拒否する。共通`--hz`は後方互換を保ち、周波数の自動切替・再試行は追加していない。
