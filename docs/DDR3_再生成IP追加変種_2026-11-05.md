# DDR3：再生成IPの追加変種（324MHz系・297MHz・360MHz）と実機試験順（2026-11-05）

方針は `DDR3_方針決定_旧IPを採用_2026-11-05.md`（再生成IPは期限つきで検証し、見込みがなければペンディング）に従う。本書は「追加のバリエーション数個」の用意と、実機の試験順・判定基準を記録する。オフライン作業のみ（実機・書込みは未実施）。ツールは Education 1.9.11.03、SDCはガード済み（診断用）。

## 1. 依頼した変種と、実際に作れたもの

| 依頼 | 結果 |
|---|---|
| A: 324MHz＋Addr_Cmd_Mode 2T | **生成不可**（下記2章） |
| B: 324MHz＋OUTPUT DRV HIGH | 作成（`nip_b_324_drvhigh`） |
| C: 324MHz＋2T＋DRV HIGH | **生成不可**（2T） |
| D: 300MHz | **300MHzは作れない**（下記3章）。最も近い **297MHz** を作成（`nip_d_297`） |
| E: 360MHz＋2T | 2Tが生成不可のため **360MHz・1T** を作成（`nip_e_360`） |

### 2T が生成できない理由（確認済み）
- 基準の `Addr_Cmd_Mode 1T` を `MEM_ADDR_CMD=2T` で置換して生成すると、`ERROR: Value '2T' is no found in configuration option 'ADDR_CMD_MODE'`。`2t`、`3T`、`Auto`、`2` も同じ。1:2／1:4、Memory_Clock 100〜400でも同じ。**Education 1.9.11.03 のDDR3 IPジェネレータは `1T` 以外を受理しない**（`DDR3.dll` の文字列にも `1T` しかない）。
- エラー時は `set_property` 全体が無効になり、IPが既定（200MHz・1:2・tCK 5000）で生成される。以前の「2T追記」が `1T` のままだった記録は、この挙動と整合する（重複キーではなく、値自体が無効だった）。
- Gowin 1.9.12.04（`D:\Gowin\Gowin_V1.9.12.04_x64`）は、このPCではライセンス検証エラー（License verification failed）で `gw_sh` が動かず、比較できない。`.ipc` の `ADDR_CMD_MODE=1` へ手で書き換えて読ませる試みは、モジュール未登録で失敗した（ネットリストの手改変はしない）。
- 2Tを評価する場合の候補：ライセンスのある版（1.9.12.04以降）で生成するか、GUIのIPカスタマイズで値の選択肢を確認する。**未実施・未確認**。

### 300MHz が作れない理由
`27MHz×(FBDIV+1)/(IDIV+1)=300` は `(FBDIV+1)/(IDIV+1)=100/9` が必要で、`FBDIV_SEL` は最大63（`FBDIV_SEL=99` は合成で EX0311「Invalid VCO／CLKOUT frequency」エラー）。そのため **297MHz（27×11、FBDIV=10、IDIV=0、ODIV=2、VCO 594MHz）、USER 74.25MHz** とした。IPの Memory_Clock も297で生成（tCK 3367ps）。

## 2. 変種の記録（ビルド済み、書込みなし）

共通：GW2A-LV18PG256C8/I7、IPは `MEM_IP_TAG=n2b/n2d/n2e` で別ディレクトリ生成、RTL試験（`run_tests.py` タグ付き、vendor initialization model を含む）合格、`prepare_guarded.py`（90端点）合格、ピン制約一致（66ポート、不一致0）。構成は324MHz系と同じ 1:4、CL6／CWL5。**観測タップ（スケジューラ内部のdeep語）は維持**。

| 変種 | IP設定 | PLL／USER | FS SHA-256 | USERCODE | Logic／Register | STA（setup違反端点／負の経路） |
|---|---|---|---|---|---|---|
| `nip_b_324_drvhigh` | 324MHz、1T、OUTPUT_DRV HIGH | 324／81 | `b27abd80addebb5dc52c70963a7538fd6c9712bf6773672864b356adb3439a90` | 0x4316 | 6482／6469 | 違反0。最悪setup +0.176ns、recovery +1.462ns、fmax user81 82.17MHz |
| `nip_d_297` | 297MHz、1T | 297／74.25 | `748f7860f31ce41f92ccb915ab2b44543deb0a1ab56ebfe7c55283ff805021c9` | 0x1F0E | 6513／6474 | setup違反3859端点（経路25）、recovery違反256経路。最悪setup −6.163ns、recovery −4.749ns |
| `nip_e_360` | 360MHz、1T | 360／90 | `b60bd1c2bf55ddd400f464485baaa033b35febbbc69ffdde681cb239f55b548f` | 0xDC96 | 6452／6476 | setup違反3861端点（経路25）、recovery違反256経路。最悪setup −6.626ns、recovery −5.602ns |

- USERCODEは、これまでの全イメージ（0x8D47、0x4783、0x9DDB、0xC783、0xA6D4、0x0233 など）と重複しない。
- **STAの違反（297／360）は、診断用（ガード済み）SDC条件付きのもの**。最悪経路は IP内部の `ddr_rsti_reg_* → gw_cmd0_mem_*/DI[0]`（sys27起点のリセット／ロード同期器 → コマンドFIFOメモリ）と、`reset_hold → ddr_init_internal_r/CLEAR`（recovery）で、`DDR3_clk400_SDC限定例外案_2026-11-04.md` のE5／E6と同種（クロック間の非同期経路。**非整数比クロック間違反が既知**）。ただし324MHz（B）では同じ経路で違反0のため、297／360での増加の原因（PLL比、配置配線）は**未解析**。実機で校正が通るかの診断には使うが、**タイミング合格の根拠にはならない**。
- 360MHz／297MHzは、メモリ側ホスト（MEM probe）の `SYSQUERY` が **(324,81) と (398,100) の組だけ**を受理するため、そのままでは表示値が受理されない（4章）。
- 297MHz変種のPLL：IDIV=0／FBDIV=10、PFD=27MHz。360MHz：IDIV=2／FBDIV=39、PFD=9MHz、VCO 720MHz。

### 観測タップ（deep語）の扱い
新ツールで生成したIPは、再合成ごとにネット名が変わる（`n219_4`／`n219_5` が存在しない）。`prepare_deep_taps.py` に再合成IP用の分岐を追加した（元の324MHz IPでは従来どおり）。
- 変種E（360MHz）：`cmd_accept = !cmd_empty & n223_3`（LUT2）なので、**bit29＝`issue_any`（= 書込み／読出し発行の和、`n223_3`）、bit30（issue_read）は定数0**。`head_write`／`head_read`（bit26／27）で種別を区別する。
- 変種B・D：`cmd_accept` の駆動がLUT4／LUT3で発行項がインライン化または曖昧なため、**bit29／30は定数0**。それ以外（FIFOポインタ、cmd_full／empty、cmd_accept、send_wr、write_full／empty、pre_info_valid、init_done、bank_state、refresh_request、idle1〜3、init_enable）は、元の324MHz IPと同じ意味で取れる。
- 記録先：各 `tap_audit.json` の `issue_resolution`（ビルド出力、非コミット）。

## 3. 再現方法
```
powershell -File fpga/mem/tests/build_newip2_variants.ps1          # B・D・E（IP生成→タップ→RTL試験→ガード済みSDC→ビルド）
$env:MEM_REC_DATE='2026-11-05'; $env:MEM_REC_SUMMARY='mem-variants-newip2-2026-11-05.json'
python fpga/mem/tests/record_variant.py nip_b_324_drvhigh nip_d_297 nip_e_360
```
- IP生成：`generate_ip.tcl`（`MEM_ADDR_CMD`、`MEM_CLK`、`MEM_EXTRA_CFG`）。SDC：`fpga/mem/config/mem_bist_n2b／n2d／n2e.sdc`。
- 記録：`fpga/validation/mem-variants-newip2-2026-11-05.json`、`fpga/validation/mem-variant-<名前>-2026-11-05/`（.fs.gz、レポート、タイミング、コンソール）。IPの`MemDDR3.vo`／`gwmc_param.v`／`.ipc`のSHA-256はJSONの`_ip`に記録（IP本体はコミットしない）。新ツールで再生成したIPを含むビットストリームの扱いは、既存の `mem-variant-clk400*` と同じ。

## 4. 実機で試す順序と判定基準
前提：MEM probeファーム＋`probe_mem_scheduler_diag.py`（段階1の既存手順）。**書込みはSRAMのみ**、毎回USERCODEを確認する。

順序（見込みの高い順）：
1. **`nip_b_324_drvhigh`**（324/81。ホストの`SYSQUERY`受理組と一致するので、ホスト変更なしで試せる。以前の324MHz版は校正が通る）。
2. **`nip_e_360`**、3. **`nip_d_297`**（`SYSQUERY`の組が未受理。下記のホスト側対応を先に入れるか、probeが拒否する場合は`sys_flags`の直読みで判断する）。

### 段階1：校正（calibrated）
- 合格：`calibrated`が真、`snapshot_fresh`が真、`command_ready`／`data_ready`が真。
- 不合格（今回までの400MHz系と同じ）：`sys_flags`＝2136、`snapshot_fresh`偽。→ その変種は打切り。
- 参考：旧IPの成功時は`sys_flags`＝905。

### 段階2：64ビートBIST（書込み→読出し照合）
- 合格：書込み・読出しとも完了し、ミスマッチ0、エラー無し。合格したら既存手順（パターン10本、境界6本、規模4本、複数seed）へ進む。
- 失敗時に取るもの（`probe_mem_scheduler_diag.py` のdeep語から）：
  1. **受理コマンド数**（cmd_accept回数）と、書込み中／読出し中のどこで止まったか。
  2. **コマンドFIFOポインタ**（cmd_wptr、cmd_rptr）、cmd_full／cmd_empty。以前の324MHz版は「受理5〜7件、read pointer 0、FIFO満杯、スケジューラが取り出さない」で停止。同じ症状かを比較する。
  3. **send_wr**、write_full／empty、write_rptr／wptr（書込みデータ経路）。
  4. **pre_info_valid、bank_state、init_done、init_enable、idle1〜3**（スケジューラが待機のままか）。
  5. **refresh_request**（周期的に変わる信号。固定値なら異常）、self_refresh_request。
  6. 変種Eの`issue_any`（bit29）。B・Dはbit29／30が常に0であることを前提に読む。
- 各変種で、上の値を324MHz旧版（以前の記録）と並べて、止まる位置が動くか（動けば設定の影響あり）を判断する。

### 打切り
- B・E・Dのいずれも段階1を通らない、または通っても段階2で同じ位置で止まる場合は、**再生成IPをペンディング**とし、旧IPで進める（方針決定どおり）。1つでも段階2を通れば、BIST全項目・soakへ進む。

## 5. ホスト側で必要な変更（ホストは触っていない）
- **MEM probeの`SYSQUERY`クロック受理表**：現在は(324,81)と(398,100)のみ。変種D・Eを`probe`で読むには、**(297,74)** と **(360,90)** の追加が必要（本変種は`MEM_MHZ`／`USER_MHZ`＝297／74、360／90を返す。297MHzのUSERは74.25MHzの整数切捨て）。追加しない場合は、probeがクロック不一致で拒否するため、`sys_flags`の直読みなど別手段になる。
- 反映要否は、Bのみで足りるうちは不要。D・Eを試すと決めた時点で、`tab5-fpga-gpu`側のprobe（受理表）を更新し、反映した版をここに記録する。

## 6. 既存RTL試験
`fpga/mem/tests/run_tests.py`（無タグ）：15項目すべてPASS（`prepare_deep_taps.py`・`prepare_variant.py`・`record_variant.py`・`generate_ip.tcl`の変更後に確認）。元の324MHz IPに対する`prepare_deep_taps.py`の経路は従来のまま（`n219_4`が存在する場合は新分岐に入らない）。
