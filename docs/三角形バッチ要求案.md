## Wire contract

Tentative opcodes are fixed for this experimental implementation: TRI_BATCH_CAPS0x40, TRI_BATCH0x41. CAPS args0/0 replies r4=64 maximum records, r5=1 format version. No existing INFO flag changes. Host must successfully query CAPS before sending an extended request.

BATCH starts with the existing8-byte request header and headerCRC. q4=count1..64, q5=format1; opcode bit7 remains optional tagged-response request. Then count records, each20 bytes in existing register order AX,AY,BX,BY,CX,CY,ZA,ZB,ZC,COLOR, all little endian16-bit. Coordinates retain signed Q12.4 and depths/color full unsigned16-bit. Trailer2 bytes are little-endian CRC16/CCITT-FALSE seededffff over header bytes0..5 followed by all record bytes (headerCRC bytes6..7 excluded). Total10+20*count bytes, maximum1290. No padding/training bytes enter request CRC.

Success response uses existing8-byte framing and request seq: status0,r4=count,r5=1. It appears only after all records execute. Tagged success/error response retains exactly8c3 prefix bytes outside responseCRC. Invalid header/payloadCRC yields status1, bad count/format status3, unsupported variant status2. Header validation precedes payload acceptance. Invalid header/count receives an immediate ordinary error; host sends no body until capability/header construction is valid. A malformed body consumes its declared bounded length, then rejects without drawing. Truncation/DIR change/idle timeout discards the staged batch; no partial byte becomes a new request. No capability fallback or automatic replay after ambiguous completion.

## Ownership and exactness

One bounded synchronous640x16 command RAM (1280 bytes, one18k BRAM expected; measure inference) stages ALL records. Only valid finalCRC unlocks replay. Replay submits ten setters then DRAW serially to unchanged triangle engine, preserving input order, top-left rules, signed clipping, interpolated depth and strict depth comparison/ties. CLEAR stays explicit before batches; empty tiles and tile scheduling are unchanged. One request outstanding. RAM is immutable during replay; request writes blocked. Existing renderer/watchdog limits remain, with operation progress renewing watchdog between completed commands. Timeout or ARM/reset invalidates the tile; host clears/restarts tile after rearming. Cancellation cannot roll back already executed records; no partial batch response is successful and host must not display partial tile.

## Cost and gates

Existing scalar path176 request/response bytes per triangle (plus tagged prefixes where enabled) and11 direction changes become20+10/N request bytes and one response per group. A64-record group amortizes704 scalar roundtrips into one. Render arithmetic/DSP unchanged; expected one BRAM plus CRC/index/replay control, actual synthesis/routing must be reported. Host staging max1290 bytes; no full-frame FPGA RAM or DDR required. Batch does not overlap compute/readback or create a general GPU ISA.

Tests must compare batch vs independent reference/scalar for counts1/2/63/64, all signed edge coordinates, depth ties/reversal, degenerate/offscreen triangles and both planes; corrupt every body byte/CRC, seq/header/count/format, truncation/DIR/ARM/reset/timeouts, repeated/tagged/untagged packets. Verify zero writes before finalCRC, no stale FIFO reuse, cancellation recovery and old full regression. Then resource/routed timing gates and parent-only finite hardware tests precede performance claims.
