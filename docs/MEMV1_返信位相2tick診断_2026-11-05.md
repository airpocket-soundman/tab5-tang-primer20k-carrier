# MEMV1返信位相2tick診断候補（2026-11-05）

状態：**オフライン回帰・窓モデル・PNR済み。実機26.67MHz NEGは全段階の途中で失敗、POSは最初のCAPSで失敗しており、安定認定しない。** `codex/memv1-reply-phase2`で開発した。D7F5（phase3、20MHz POSの限定実機基準）とA0A9のFS・作業ツリーは変更していない。phase1も明示指定を受け付けるが、phase1の合成・FS生成はしていない。

## 目的と変更

26.67MHz（160MHz／6）・32MHz（160MHz／5）における返信位相の切り分け用。既存の同一`reply_phase_delay`を**2tick＝約9.26ns**にして、serializerと読出しRAMを一緒に遅延する。filter、cooldown、要求側SYS27、wire opcode・バイト形式・ピン・電源・CDC同期ロジックは変更していない。

`REPLY_PHASE_TICKS=0`が既定bypass。ビルド用の明示指定は0／1／2／3へ拡張し、位相ごとに別のbuildディレクトリへ出力する。今回実際に生成したのはphase2だけである。

理想RTLでraw立上りからclean認定は13.89〜18.52ns、phase2を通すとserializer advanceは**23.15〜27.78ns**となる。26.67MHzのraw rising採取に対して次byte更新の名目予算は37.5−27.78＝9.72nsで、phase3の5.09nsから4.63ns増える。ただし実I/O経路・往復配線・P4 setupを含めた保証値ではない。遅延が一定であればタグprefixによって整数byteの位置差を吸収できる一方、採取境界をまたぐ遅延の変動はbyteの重複／欠落を起こし得るため、単一の名目予算だけで合否を決めない。

## 回帰と窓モデル

- phase2で既存全209checks／192ベクトルが合格。取消し、timeout、inflight校正喪失→STALE、reset、BIST共存を含む。
- 独立fault／新要求復帰／gen++同edgeのSTALEが合格。
- 追加10checksで全4KiB RD、タグ付きRD、CRC32、エラー応答、停止CLK、DIR・ARM・GENによる遮断、500ns／1ns sampler resetと復帰が合格。
- delay2の200pulseでedge数・遅延・幅、sampler停止中resetとstale pulse非再開が合格。

実際のfilter／phase delay／serializerと、同期128bit RAMを使う4KiB窓モデルを実行した。26.67MHzは周期37.5ns／HIGH18.75ns、32MHzは周期31.25ns／HIGH12.5・15.625・18.75nsを分離した。実divider5のdutyとclock反転の結果は波形で確認する必要があり、50%dutyだけに限定しない。

各波形はsampler初期位相0／1.5／3ns、片道配線＋Tco仮定 `(0,0)`／`(2ns,2ns)`／`(5ns,2ns)`、sampler周期jitter仮定0／交互±200psの18点。jitterとTcoは感度解析の仮定であり、実測PLL／I/Oの認定値ではない。

| 周期／HIGH | 物理fallingで全4KiB＋CRC一致 | 物理risingで全4KiB＋CRC一致 |
|---|---:|---:|
| 37.5ns／18.75ns | 18／18 | 12／18 |
| 31.25ns／12.5ns | 18／18 | 12／18 |
| 31.25ns／15.625ns | 18／18 | 12／18 |
| 31.25ns／18.75ns | 18／18 | 12／18 |

**全144条件でraw／clean／phase clockのedge数は一致し、filter faultなし。** risingの24不一致も失敗条件として保存し、データ補正やfallbackで成功扱いしていない。nominal CLKの認定・同期RAM先読みは検査するが、実P4の採取・電気波形・DDR3全経路を認定するモデルではない。

- USERCODE：**0x2182**。
- FS SHA-256：`a5593e2d8f080c253def75880d4c43c254f16dce2525dedb76392200ff3099e6`。
- FSはローカル`fpga/build/memv1-fast-phase2/out/mem_bist/impl/pnr/mem_bist.fs`のみ。旧IP／FSはGitに含めない。
- Logic6988／20736、Register5971／16173、BSRAM16／46、rPLL2／4、LW8／8。
- setup／hold違反endpointは0。報告最小slackはsetup **+0.033ns**、hold +0.074ns、recovery +3.155ns、removal +0.453ns。setup余裕は小さい。
- 216MHz内部15報告pathで最小+2.201ns、conditioned reply100報告pathで最小+7.001ns。5つのmetadata familyにそれぞれ実pathがあり、同期初段だけの6pin例外を維持した。
- `record_fastreply.py`でRTL・ビルド入力・209回帰・追加制御・窓モデルのsource SHAを照合した。

周波数・採取位相を含む**個別の診断プロファイル**であり、D7F5の20MHz POSやA0A9の16MHz NEGを無条件に置き換えるものではない。既存DDR診断SDCのclock-pair例外、外部I/O窓、温度・電源・冷起動・長時間soak、Linux／MeOSの実機適合は引き続き別の確認事項である。TXは2MHzのままで、TX5MHzを合格にした変更ではない。

## 親セッションの実機結果

USERCODE2182、ホストELF SHA-256 `f751a5644116187b5d7655cd20f79abe2fd65da9ba3af1da8874e77d4dd6bcff`、TX2MHz POS／RX26,666,666Hz、整数分周6のdriver／restore検証済みという条件で確認された。

- **RX NEG**：全段階試験のCAPS／STATUS／RD1／RD256／WR1／WR256／CRC32まで7段階は合格。その後8番目の`invalid`段階、拒否要求後のRDでtrailer CRC16不一致となり停止した（42トランザクションまで記録）。最初の読取り4段階が通っても、全段階・長期反復に合格したとは扱わない。

原本2件の圧縮コピーとSHA-256を`fpga/validation/memv1-phase2-hardware-2026-11-05/`、要点を同名JSONへ保存した。payloadのtrailer CRC不一致は転送失敗であり、この記録だけでDDR3内部の故障とも認定しない。D7F5の20MHz POS既知構成は別の基準として保持する。phase2も汎用置換ではなく、採取窓の部分的変化を見る診断候補である。
