# FPGA-only DDR bandwidth sweep

Diagnostic only; no Tab5 bus ports. DDR pins, H11 clock, T10 reset, and official sample UART TX M11 are the only constrained pins. Build requires the hash-verified Sipeed DDR-test e469df4c IP under `fpga/build/sipeed-ddr-test-e469df4c`; it is not committed. Run `gw_sh fpga/mem/standalone/build.tcl`. The PLL generates 398.25 MHz and the DDR user clock is 99.5625 MHz. The sample-style asynchronous clock-group exceptions are diagnostic, not timing sign-off.

After calibration is continuously asserted for 512 user clocks, the runner executes 1 MiB jobs: single-beat write, single-beat read, then for L=2,4,8,16,32,64: write L/read single/write single/read L. The diagnostic opts into seeding only one data lane to prevent XOR-fold cancellation of seed changes; the engine default remains unchanged. Each write/read pair uses a distinct seed (`0x12345678 XOR (job >> 1)`) and sequential addresses; each new write therefore replaces the preceding data. Thus both directions cross-check data that was written using the other burst length. Stop at the first error or checksum mismatch, without a deliberate reset. Each completed job is frozen for eight clocks before reporting. Calibration timeout is two seconds of user clocks; if the PLL or user clock never runs the UART cannot report it. Job total timeout is two seconds, with the engine's shorter no-progress timeout. Loss of controller reset/PLL also resets this diagnostic; observe a missing/truncated stream as failure.

UART is 115200 8N1 on M11, divider 864 at 99.5625 MHz. Capture binary before programming/reset, then `python fpga/mem/standalone/decode.py capture.bin --json result.json`. There are 26 fixed 111-byte records: `DBW1`, one byte each job, mode (0 write/1 read), log2 burst, flags (bit 0 write checksum match, bit 1 read match, bit 2 failure), error, then little-endian seed u32, six u64 counters (cycles, commands, write beats, read beats, command stalls, data stalls), three u128 checksums (write/read/expected), CRC16-CCITT (initial ffff, polynomial 1021, little endian) over the preceding 109 bytes. Error 0x80 means calibration timeout. Decoder independently validates schedule, seed, counts and generated checksums and rejects truncated, corrupted, extra, or failed records. Decimal MB/s uses 16 bytes per beat and 99.5625 MHz; no serial transfer time is included.

Simulation: with OSS CAD Suite on PATH, compile `iverilog -g2012 -s tb -o fpga/build/standalone-sim.vvp fpga/mem/standalone/tb_runner.v fpga/mem/standalone/standalone.v fpga/mem/rtl/mem_bw.v`, run `vvp fpga/build/standalone-sim.vvp` and decode `fpga/build/standalone-sim.bin --beats 64`; run again with `+corrupt` to inject a read error, or with `+dropwrite` to accept but discard all job 2 memory writes. Both stop on job 3 after four records and the decoder rejects the capture. The 13 expected 1 MiB checksums are distinct. This is an idealized DDR user-interface model, not hardware evidence. The old Sipeed tester sends write data before its burst command; this engine pairs the command with the first data beat, then sends the remaining beats. Burst operation and timing must be established on the actual IP and board.
