# FPGA単体によるDDR3内部帯域の改善（2026-11-05）

旧公式IPを変更せず、RAMクロック398.25MHz・USER99.5625MHzを維持し、1要求にまとめる128bitデータ数を1から64へ増やした。**書込み約1476 MB/s、読出し約1481 MB/s、通常転送の約2.9倍**を実機で確認した。理論1593 MB/sに対して約93%。MB/sは十進表記。

|---|---:|---:|

表は最終版3回の平均。各回1MiB、26条件、計78条件すべて合格。個別値・範囲・計数・チェックサムは`summary.json`、`trial-02`〜`trial-04`の`results.json`とUART原データに保存。通常転送の約512 MB/sを同じ回路で再現してから比較した。

## 実施と検証

- FPGA内で自動実行し、DockのUART（M11、COM27、115200 8N1）で結果だけを取得した。Tab5のパラレル通信・READY・DMAは使用せず、Tab5ファームと既存のパラレル通信ソースも変更していない。
- 各転送長について「まとめ書込み→通常読出し」「通常書込み→まとめ読出し」で相互照合した。書込み／読出しの各ペアは異なるデータを使う。受理ビート数・コマンド数・サイクル数・独立Python期待チェックサム・UARTのCRC16も検査した。
- 旧エンジンの全レーンへ同じseedをXORする方法では、線形PRNGとXOR-foldの組合せによりseedの差がチェックサムで相殺される。診断専用`SEED_ONE_LANE=1`で回避し、13ペアの1MiBチェックサムがすべて異なることを確認した。既存エンジンの既定動作は変更していない。
- シミュレーションでは全26条件が合格。job 2のメモリ書込みを全欠落させる故障注入でjob 3が停止し、結果も不合格になることを確認した。既定エンジンの9構成・独立モデル660ジョブの回帰も合格。
- `trial-01`は同一seedを再利用した初期の探索測定であり、最終のデータ完全性検証には数えない。初期結果のJSONにもその制限を追記した。

## 構成と再現

コードは`codex/ddr-bandwidth-burst`、実機測定版コミット`a4fd6fd`。`fpga/mem/standalone/README.md`にビルド、UART形式、シミュレーションと復号の手順を記載。旧IPの13ファイルは固定コミットのハッシュを照合した。旧IPとそれを含むビットストリームはGit管理外。

測定版FS SHA256: `c36e0c342f0b70a2977c89d581ca4c5886bfb8a099ad5f07c37e2c3fce13189d`、USERCODE `0x3B22`。ソースとIPのハッシュ、工具、タイミングは`build.json`、各ホストの参照版・要求と影響判断は`environment.json`、レポートは`offline/`。ホストwire仕様・コマンド・ピン・電源の変更はなく、ホストへの反映は不要。

## 適用範囲と残作業

1MiBの連続転送を3回のSRAM再構成で検証した結果で、電源再投入、全域、温度、長時間、ランダムアクセス、混在アクセスの性能保証ではない。STAは診断用のクロック群例外下でsetup/hold違反0、最悪setup +0.027nsと余裕が小さく、DDR全経路のタイミング保証ではない。

**通常アプリのメモリアダプタへ64データのまとめ転送を組み込む作業は未実施。** 次は境界・端数を処理するアダプタで同じ要求形式を採用し、実用途の性能と完全性を検証する。今回の結果をTab5との通信速度向上やLinuxメインRAM増設とは扱わない。

各実機試験の終了後に、元のFPGAイメージ（USERCODE `0xA0A9`、Status `0x6020`）へ復元し読戻しを確認した。フラッシュへの書込みは行っていない。
