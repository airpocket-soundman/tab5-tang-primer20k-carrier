## 部品の扱い

- **PCBAに出す:** 134部品。SMT部品に加えて、スルーホールの候補（SW4、JP1、JP3、J1）も、BOMとCPLに載せてあります。業者が実装できない場合は、`lcsc-separate-order.csv` のグループBを別途購入して、手はんだにします。その場合は、PCBAの注文から外してください（二重購入の防止）。
- **PCBAに含めない:** J3（Tab5用2×15ヘッダ、基板裏面、手はんだ）、ショートプラグ（C5305、2個）、取付穴（H1〜H6）。
- **実装しない（DNP）:** R4、R17、R18、R25、C8、C9、J6、J7、J8。
- **ユーザー支給:** Tab5、Tang Primer 20K Core、M3ねじ・スペーサ。
- r5からの部品の変更: 水晶を、SMT実装できるYXC X322512MSB4SI（C9002、20pF）に変更し、負荷用コンデンサ（C86、C87）を33pF（C1663）にしました。PESDは、UMW社の互換品（C3001955）です。JP1は、JP3と同じ1×3ヘッダ（C49257）にしました。

## 検証したこと（`gen/check_order.py`）

- ERCエラー0、PCB DRC違反0、未配線0。
- BOMとCPLの部品が、完全に一致。CPLの座標・角度が、範囲内。
- ガーバーに、全層（銅箔4層、マスク、シルク、ペースト、外形、ドリル）がある。
- ガーバー、CPL、補正記録が、同じ基板ファイル（SHA256 `1a5e4c9e…644d3`）から作られている。
- r4のファイル1234件の保全ハッシュが一致（`../verify_design.py`）。

これらは、データの整合の確認です。業者の受入確認や、実機での検証ではありません。

## 未解決・要確認（重要な順）

1. **ダイオード（D1〜D8）の極性。** LCSCのSS54、SMBJ15A、LEDのフットプリントは、パッド1がアノード、パッド2がカソードで、KiCadのフットプリントは逆（パッド1がカソード）です。パッド番号で当てはめると、実物が逆向きに載ります。**r5sのCPLは、極性（ピンの機能）で当てはめてあります**（`placement-corrections.json` の `number_match_alternative` に、番号合わせの値を残してある）。
   - **r4のCPLは、番号合わせの値のため、D1〜D8の向きが逆の可能性があります。** r4は未発注・未製造です。発注前に、r4のCPLの見直しが必要です（本ブランチでは、r4を変更していません）。
2. **極性を確認できなかった部品:** C1、C7（電解・POSCAP）、D10、D11（PESD）。LCSC側のデータにピン名がなく、番号合わせで配置しています。**注文時のプレビューで、極性マークを確認してください。**
3. **SW1／SW2（押しボタン）の回転:** KiCad側のパッド番号が重複していて、番号照合できません。幾何的な照合で0度としました。r4は270度でした（r4の値に誤りの疑い）。プレビューで確認してください。
4. **ランド長の差で、残差が0.3mmを超える部品:** L1（0.84mm）、D1／D2／D4（0.50mm）、U1（0.36mm）、C7（0.32mm）、SW1／SW2（0.70mm）。位置はr4と同じです。はんだ付けの実績は、未確認です。
5. **在庫・価格:** どの部品も、在庫と価格を確認していません。LCSCの水晶C5700075は、検索結果の抜粋で在庫0でしたので、C9002に変えました（在庫は、いずれも未確認）。PESD（UMW）は、元のNexperia製との特性の同等性が、未確認です。
6. **スルーホール部品の実装可否:** SW4、JP1、JP3は、JLCPCBで「波はんだ」の分類です。業者が実装できるか、追加の費用がかかるかは、見積りで確認が要ります。
7. **スイッチ（SW4）:** ピンの対応（pad1/8、2/7、3/6が同じスライダ位置で動く）は、EasyEDAの記号図からの推定です。シルクの `PGM / OFF / RUN` の向きも推定です。**実物の導通確認が必要です。** 電流定格は1Aです。
8. **JP3は、SW4と連動しません。** SW4をPGMにしたら、JP3も2–3にする必要があります（シルクに記載）。PROGRAMでJP3をRUN位置のままにすると、Tab5のHVINに約4.5Vが入ります。Tab5のHVIN許容電圧は未確認です。
9. **r5の設計上の未了事項（r5のREADMEにあるもの）:** USB差動配線・ESDスタブ・長さ差・参照面の確認、クリスタルの配置と負荷容量（水晶を変更したので、負荷容量の再確認が必要）、コネクタとCoreの嵌合、実機試験（電源、USB列挙、書き込み、全ホスト）。Coreの5V端子の絶対最大定格も不明です。
10. 実機でのUSB書き込み、LINK通信、通電は、一切確認していません。

## JLCPCBでの使い方（私は操作しません。注文もしません）

1. PCB: `gerbers.zip` をアップロード。4層、125×78mm、1.6mm、積層 `JLC04161H-7628`（`order-profile.json` 参照）。
2. PCBA: `jlc-bom.csv` と `jlc-cpl.csv` をアップロード。上面のみ。
3. プレビューで、**極性・ピン1の向き**（上の2、3）と、スルーホール部品の扱い（上の6）を確認。部品の在庫切れが出たら、代替を選ぶ前に、設計者へ相談。
4. `lcsc-separate-order.csv` のグループAを、LCSCで別途注文。

## 再生成

`gen/`（KiCad付属Python：export_order.py、make_cpl.py、sync_pcb_values.py など。通常のPython：make_order_bom.py、check_order.py、make_order_profile.py）。基板を変更したら、`export_order.py` → `make_order_bom.py` → `make_cpl.py` → `check_order.py` → `make_order_profile.py` の順に再実行する。LCSCの公式フットプリント（第三者データ）は、リポジトリに含めていない（`make_cpl.py` が取得してキャッシュする）。
