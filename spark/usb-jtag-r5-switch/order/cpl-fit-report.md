# r5s CPL 補正レポート (JLCPCB 部品配置 / LCSC 公式フットプリント座標)

- 作成日: 2026-11-06  /  基板SHA256(LF正規化): `ad8032500d942bfa793b4e9e081123dcec510f2b0d5ccf8b0dac6db43129429c`
- 生成: `spark/usb-jtag-r5-switch/full/design/kicad/gen/make_cpl.py`(EasyEDA取得物は第三者データのためリポジトリ外のキャッシュ。キャッシュがあればネットワーク不要)
- 対象: 134 部品(DNP・LCSC空欄・J3・H1-H6を除外)。すべて上面。裏面の実装対象部品なし(裏面はJ3のみで対象外)。

> **限界**: これは公式ライブラリ座標への補正であり、業者の最終的な部品向きの確認ではない。注文時のプレビューで必ず確認する。

## 1. 重要な所見(先に読むこと)

1. **極性の取り違えの可能性(r4にも波及)**: LCSC公式シンボルのピン名(A/K)とKiCadネットリストのピン機能を照合すると、D1, D2, D3, D4, D5, D6, D7, D8 は **パッド番号が電気的に入れ替わっている**(LCSC: 1=A,2=K、KiCad: 1=K,2=A。D3はKiCad側の役割をネット(パッド1=VIN=正側)から K と判断)。番号だけで重ねると、LCSCのカソードがKiCadのアノード側に載る(CPLの向きが180度逆)。ピン名で照合すると回転がKiCad向きと一致する(θ = KiCad回転)ため、こちらを `jlc-cpl.csv` に採用した。番号照合の結果は `placement-corrections.json` の `number_match_alternative` と下の表に残してある。SS54(C22452)のLCSCフットプリントはシルクのカソード棒がパッド2側にあり、シンボルのK=2と整合している。**r4のCPLは同じ参照名(D1-D8)で番号照合の値(逆向き側)になっているため、r4でも同じ問題がある可能性が高い。要確認。**
2. **SW1/SW2(C480272)**: KiCad側のパッド番号が重複していて番号照合できない。r4は角度270(残差1.75mm)だったが、パッド配置の幾何では 0 度(または180度、対称)が適合し、270度は合わない。r4の270度は誤りの可能性がある。r5sは 0 度とした。
3. 極性が機械的に確認できない部品: C1, C7(電解/タンタル。LCSCシンボルのピン名が「1」「2」のみ), D10, D11(同、ピン名なし)。番号照合(θ=KiCad回転)で配置したが、LCSC側のどちらが+/カソードかはデータから確認できない。プレビューで極性マークを確認すること。

## 2. 方法

1. KiCad側: `pcbnew.LoadBoard` の各フットプリントのパッドを番号ごとに重心化。座標は kicad-position.csv と同じ Gerber 座標(X = x_kicad - 2, Y = 79 - y_kicad)。
2. LCSC側: EasyEDA API の `packageDetail.dataStr` の `PAD~` を、部品原点(head.x, head.y)基準、0.254mm/unit、y を反転(y上向き)。番号ごとの重心。
3. 共通番号のパッド対を、LCSC座標を θ∈{0,90,180,270}度(反時計回り、y上向き)回して、最小二乗の平行移動 t を求めて KiCad へ合わせる。最大パッド中心残差が最小の θ を採用(同率は小さい θ)。CPL の Rotation = θ、Mid X/Y = t(LCSC原点が来るGerber座標)。
4. r4との差分(r4の手法の再現に必要だった取り扱い): (a) 両側でパッド数が異なる番号(SOT-223のタブ、PowerPAD、サーマルビア)は当てはめから外す。(b) LCSC側が複数のKiCadパッドを統合した名前(USB-Cの `A1B12` など)は、名前に含まれるKiCadパッド全部の重心と対応させる。(c) 番号が重複して照合できない部品(SW)は、全パッド重心の一致+最近傍距離で θ を選ぶ幾何照合に切り替える。(d) 上記の極性入れ替わりはピン名で対応を取る。

座標原点と pcbnew のパッド座標が kicad-position.csv の位置・向きと一致することを全対象部品で確認済み。
