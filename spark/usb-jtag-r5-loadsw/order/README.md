2026-11-06。**r5l**（B案のr5sから、SW4を信号専用にして、+5Vの電流をPMOSのロードスイッチに通す変種）の基板 `../full/design/kicad/tab5-fpga-carrier-r5l.kicad_pcb` から作った、JLCPCB向けの発注候補データ。r5s（`../../usb-jtag-r5-switch/`）は、そのまま残してあります。

## r5sからの変更（ロードスイッチ式）

SW4（G-Switch SS-23D03-G080）は、データシート原本で **0.3A・50V DC** 定格で、+5Vレール（Core、3.3V LDO、FT232H、HDMI 5V）の電流を通すには足りない可能性があるため、SW4の接点を**信号だけ**にしました（根拠・回路・SPICE結果は `../../../docs/r5s_SW4ロードスイッチ式の検討_2026-11-06.md`）。

- SW4: pad4（A極の共通）＝GND。pad1（RUN）＝SW_RUN、pad3（PGM）＝SW_PGM。B極（CFG1とGND）は、r5sのまま。
- RUN経路: Q11・Q12（AO3401A、背中合わせ。ドレイン＝BUCK_5V／+5V）、R91（100k）、R92（4.7k）。
- PGM経路: Q13・Q14（AO3401A、背中合わせ。ドレイン＝VBUS_PD／+5V）、R93（100k）、R94（4.7k）。
- PGM経路の過電圧ガード: Q15（AO3401A）、D12（BZT52C6V2、C19077403）、R95（10k）。VBUS_PDが約7Vを超えると、PGM経路が自動でオフになる。
- 追加は11部品（BOM 54→57行、134→145部品）。部品は上面のみ。新しい部品は、SW4の左側と、基板の上縁に置いた。
- シルクの `POWER OFF!` を、SW4の右側へ移した。SW4の部品番号の位置も動かした。

## 未解決・要確認（重要な順）

1. **ダイオード（D1〜D8）の極性。** LCSCのSS54、SMBJ15A、LEDのフットプリントは、パッド1がアノード、パッド2がカソードで、KiCadのフットプリントは逆（パッド1がカソード）です。パッド番号で当てはめると、実物が逆向きに載ります。**r5lのCPLは、極性（ピンの機能）で当てはめてあります**（`placement-corrections.json` の `number_match_alternative` に、番号合わせの値を残してある）。
   - r4のCPLも、同じ原因で、D1〜D8の向きが逆でした。**r4の2変種（full、lite-a）のCPLは、同日に修正しました**（`../../single-sided-r4/fix_cpl_polarity.py`、調査は `../../../docs/r4_CPLダイオード極性調査_2026-11-06.md`）。公開リポジトリ `tab5-fpga-carrier-spark` のCPLも、同日に修正して、公開しました。
2. **極性を確認できなかった部品:** C1、C7（電解・POSCAP）、D10、D11（PESD）。LCSC側のデータにピン名がなく、番号合わせで配置しています。**注文時のプレビューで、極性マークを確認してください。**
3. **SW1／SW2（押しボタン）の回転:** KiCad側のパッド番号が重複していて、番号照合できません。幾何的な照合で0度としました。r4は270度でした（r4の値に誤りの疑い）。プレビューで確認してください。
4. **ランド長の差で、残差が0.3mmを超える部品:** L1（0.84mm）、D1／D2／D4（0.50mm）、U1（0.36mm）、C7（0.32mm）、SW1／SW2（0.70mm）。位置はr4と同じです。はんだ付けの実績は、未確認です。
5. **在庫・価格:** どの部品も、在庫と価格を確認していません。LCSCの水晶C5700075は、検索結果の抜粋で在庫0でしたので、C9002に変えました（在庫は、いずれも未確認）。PESD（UMW）は、元のNexperia製との特性の同等性が、未確認です。
6. **スルーホール部品の実装:** SW4、JP1、JP3、J1は、JLCPCBで「波はんだ」等の分類ですが、`quote-jlcpcb-2026-11-06.md` の見積もりでは、**実装対象になりました**（手はんだの費用 $3.61。個別の選択肢は出ませんでした）。そのため、グループBの別途購入は、通常は不要です。
7. **スイッチ（SW4）:** ピンの対応（pad1/8、2/7、3/6が同じスライダ位置で動く）は、EasyEDAの記号図からの推定です。シルクの `PGM / OFF / RUN` の向きも推定です。**実物の導通確認が必要です。** 電流定格は、LCSCの掲載値が1Aですが、メーカー（G-Switch）のデータシートでは **0.3A、50V DC** です（2026-11-06に原本を確認）。**r5lでは、SW4が+5Vの電流を通さない**（信号だけ）ため、この定格は問題になりません。ピン対応（pad1/8、2/7、3/6が連動）は、データシートの回路図（2段の共通端子が同じ列へ連動）と一致しています。どのレバー位置がRUN／PGMかは、実物で確認してください（`PGM / OFF / RUN` のシルクは、パッド配置からの推定）。
8. **JP3は、SW4と連動しません。** SW4をPGMにしたら、JP3も2–3にする必要があります（シルクに記載）。PROGRAMでJP3をRUN位置のままにすると、Tab5のHVINに約4.5Vが入ります。Tab5のHVIN許容電圧は未確認です。
9. **r5の設計上の未了事項（r5のREADMEにあるもの）:** USB差動配線・ESDスタブ・長さ差・参照面の確認、クリスタルの配置と負荷容量（水晶を変更したので、負荷容量の再確認が必要）、コネクタとCoreの嵌合、実機試験（電源、USB列挙、書き込み、全ホスト）。Coreの5V端子の絶対最大定格も不明です。
10. 実機でのUSB書き込み、LINK通信、通電は、一切確認していません。
11. **CH224A（U1）:** 実機で、12V要求（RUN）と5V要求（OFF、PROGRAM）が出ることを、確認していません。PDアダプタとPCのUSB-Cで、VBUSの電圧を測ってください。データシートは、WCH公式（中国語、V2.1）の原本を読んで確認しました。
12. **見積もり（2026-11-06）:** 合計 **$170.10**（PCB 5枚＋実装2枚、送料別）。r5s（$168.83）より $1.27 高い。内訳と画面での注意は `quote-jlcpcb-2026-11-06-r5l.md`。AO3401A（C15127）と4.7kΩ（C23162）はBasic。BZT52C6V2（C19077403）はExtended。**同じ部品番号の行が重複する3組（C4・C5とC10、C6とC20系、JP1とJP3）は、両方の行にチェックを入れないと、数量に入りません。** 配置ビューアでの、新部品の向きの目視確認は、できていません。
13. **ロードスイッチ式（Q11〜Q15、D12）の検証は、汎用モデルのSPICE（`../sim-spice/`）だけです。** メーカーのモデルでも、実機でもありません。特に次を、実機で確認してください。
    - RUN、PGM、OFF の各位置で、+5Vの電圧（1Aで約0.17V下がる見込み）と、BUCK_5V／VBUS_PDへの逆流が無いこと。
    - PGMへ切り替えた瞬間の突入電流（USB側の電流制限）。未評価です。必要なら、PGM経路のゲートとソースの間に容量を足して、立ち上がりを遅くします。
    - 過電圧ガードの動作電圧（SPICEで、VBUSがランプで上がるとき、+5Vのピークは5.5〜7.7V）。+5Vレールに瞬間的に7V超が出ます。Core、FT232H、3.3V LDOの絶対最大定格との関係は、未確認です。
    - AO3401A（C15127）と、BZT52C6V2（C19077403）の、在庫と価格。
    - 12V要求のまま、PGMへ切り替えたとき（CH224Aが5Vへ再交渉するまでの間）の挙動。ガードは、この場合も働く設計ですが、再交渉の時間は未確認です。
    - 基板の注意: VBUS_PD経路の一部は、内層（In2.Cu、0.5mm）です。PGMで流す電流が大きいと、発熱が心配です（r5sと同じ配線方式）。

## JLCPCBでの使い方（私は操作しません。注文もしません）

1. PCB: `gerbers.zip` をアップロード。4層、125×78mm、1.6mm、積層 `JLC04161H-7628`（`order-profile.json` 参照）。
2. PCBA: `jlc-bom.csv` と `jlc-cpl.csv` をアップロード。上面のみ。
3. プレビューで、**極性・ピン1の向き**（上の2、3）と、スルーホール部品の扱い（上の6）を確認。部品の在庫切れが出たら、代替を選ぶ前に、設計者へ相談。
4. `lcsc-separate-order.csv` のグループAを、LCSCで別途注文。

## 再生成

`gen/`（KiCad付属Python：export_order.py、make_cpl.py、sync_pcb_values.py など。通常のPython：make_order_bom.py、check_order.py、make_order_profile.py）。基板を変更したら、`export_order.py` → `make_order_bom.py` → `make_cpl.py` → `check_order.py` → `make_order_profile.py` の順に再実行する。LCSCの公式フットプリント（第三者データ）は、リポジトリに含めていない（`make_cpl.py` が取得してキャッシュする）。
