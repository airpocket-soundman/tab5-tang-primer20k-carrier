# r5l の EasyEDA Pro 版（KiCad 取り込み版・途中成果）

2026-11-07。**KiCad のr5l（正本）を EasyEDA Pro へ API で取り込んだもの。EasyEDA で設計した「ネイティブ設計」ではない。実機未検証。** r4 の `.epro2`（部品情報・紐付けまで仕上げたもの）とは、完成度が違う。

## 成果物

| ファイル | 内容 |
|---|---|
| `spark-r5l-loadsw-kicad-import.epro2` | EasyEDA Pro のプロジェクト（基板1枚、回路図1枚、1つのボードに結合）。API の `getProjectFile` で書き出し |
| `final-checks.json` | 書き出し時点の、基板DRC・回路図DRCの結果 |
| `step1〜step11-*.js` | EasyEDA ブリッジ（`spark/easyeda_call.py`）で実行した手順。`make_import_compat.py` が、取り込み用コピーを作る |
| `compare_pads.py`、`kicad_pads.py`、`compare_tracks.py`、`kicad_track_lengths.py`、`export-*.js`、`count-pcb.js` | KiCad との照合用 |

## 作り方（再現）

1. `python make_import_compat.py`：KiCad のコピーを作る（基板はネット番号つき、回路図は電源記号をラベルに。幾何は変えない）。`import-compat/` は、`.gitignore` で除外。
2. `step1-import-pcb.js`：KiCad プロジェクトとして新規取り込み。
3. `step3-align-rules.js`：EasyEDA の設計ルールを、KiCad の最小値（銅間隔0.127mm、穴0.25mm、基板端0.3mm、ビア0.5/0.3mm）に揃える。
4. `step2-pcb-drc.js` と `step5-sch-drc.js`：DRC。
5. `step10-restore-and-export.js`、`step11-final-checks-export.js`：ボードの組み替えと、`.epro2` の書き出し。

## 未了・制約

1. **回路図DRCの致命的エラー76件は、未解決。** 原因は特定していない（DRCの内訳ログを取得できなかった）。r4 では、電源記号をラベルに置き換えた回路図の取り込み、部品とフットプリントの紐付け、メタデータ（LCSC部品番号）の書き込みで、致命的エラー0にした。r5lでは、電源ラベル版の回路図を取り込んだが、部品の紐付けをしていないため、致命的エラーが161件に増えたので、最初の取り込み版（76件）に戻した。
2. **LCSC部品番号などのメタデータは、EasyEDA側へ入れていない。** BOMは、KiCad側の `order/jlc-bom.csv` が正。
3. **回路図のネットリストの照合は、していない**（API の `getNetlist` が失敗）。基板のパッドごとのネットは、KiCad の回路図から作ったネットリストと照合済み。
4. 取り込み版であり、EasyEDA で設計した100%ネイティブ設計とは言えない（Sparkの応募資格は、主催者への確認が必要）。
5. 保護回路（指摘1）を見直して基板が変わる場合は、取り込みをやり直す。
