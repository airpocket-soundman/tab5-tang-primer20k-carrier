# r5c：VBUS過電圧遮断つき（C案）

2026-11-06。現行r5（`../usb-jtag-r5/`、**変更なし**）のコピーに、**ジャンパ誤設定の保険**として、USB-C VBUSとJP2 pin3の間へ過電圧遮断回路を追加した設計案。KiCad（10.0.6）の回路図と基板。**未製造・実機未検証。**

## 目的と位置づけ

- 危険なのは、JP2=PROGRAM（pin2–3）、JP4=RUN（CFG1=GND、12V要求）の状態でPD充電器をつなぐこと。VBUSの12Vが、Coreの5Vレールへ入る。
- C案は、VBUS側が約6V以上になったら、Coreへの経路（`VBUS_PGM`）を自動で切る。
- **PoCの方針により、12V混入の実機試験は行わない。** 遮断動作の根拠は、シミュレーション（`sim-spice/`）だけである。実機では、通常動作（5Vで遮断しないこと、電圧降下）だけを確認する。**保護機能として検証済みとは言えない。**
- Coreの5V端子の絶対最大定格は、公式資料に記載がない。遮断電圧の上限（約7.3V）が安全かどうかは、未確認。

## 回路

```
VBUS_PD ──┬── Q9.S (AO3401A)  Q9.D ───────────── VBUS_PGM ──→ JP2 pin3
          │        Q9.G = OVP_G
          ├── R91 10k ── OVP_G ── Q10.D (2N7002)  Q10.S=GND  Q10.G=OVP_NG
          ├── R92 100k ── OVP_NG ── Q11.C (MMBT3904)  Q11.E=GND  Q11.B=OVP_B
          └── D12 BZT52C6V2 (K=VBUS_PD, A=OVP_Z) ── R93 1k ── OVP_B ── R94 4.7k ── GND
```

- 正常: Q10オン → Q9オン（Coreへ給電、60〜80mΩ）。
- 過電圧: D12導通 → Q11オン → Q10オフ → Q9のゲートがR91でVBUSへ → Q9オフ。
- 上流の`VBUS_PD`（R1、R2、R88、D2、USB-C）は、遮断回路の手前に残る。USB有無検出、CH224Kへの給電、`/VIN`へのOR合流には影響しない。

## 現行r5との差分

| 項目 | 内容 |
|---|---|
| 追加（8部品） | Q9 AO3401A（C15127）、Q10 2N7002（C8545）、Q11 MMBT3904（C20526）、D12 BZT52C6V2（C19077403）、R91 10k（C25804）、R92 100k（C25803）、R93 1k（C21190）、R94 4.7k（C23162） |
| 変更（1部品） | JP2 pin3のネットが `VBUS_PD` → `VBUS_PGM` |
| 基板 | JP2〜4の上側の空き領域（x 38〜48、y 12〜23）へ配置。JP2 pin3への配線を `VBUS_PGM` に付け替え、`VBUS_PD`のD2側への経路をIn2層で張り直した。r4のファイルは変更なし |
| 調達（JLCPCB） | D12だけがextended（SOD-123）。他の7点はbasic（確認済み） |

r5の既存の銅箔は、上記の付け替え（In2の2本の削除とJP2 pin3のネット変更）以外は、ネット・位置とも変更していない（`gen/diff_nets.py`で確認）。

## 検証結果（`verify_design.py`、通常のPythonで実行）

| 項目 | 結果 |
|---|---|
| 回路の接続（遮断回路の接続、r5の機能の不変） | 合格 |
| r5との差分 | 追加8部品とJP2の変更のみ |
| ERC | エラー0、警告213（r5は208。ライブラリシンボル差の警告が5件増えた） |
| PCB DRC | 違反0、未配線0（`--schematic-parity`付き） |
| 回路図との整合（parity） | net_conflict 199（ネット名の`/`有無の差。r5と同じ）、footprint_symbol_mismatch 154（r5と同じ） |
| r4の保全ハッシュ | 1234件一致 |

回路図・基板の再現手順:

1. `gen/build_r5.py`（通常のPython）で、回路図・BOM・接続契約を生成する。**このスクリプトは自分自身の`make_sch.py`を書き換える仕様**なので、このディレクトリのコピーでのみ実行すること。
2. `gen/add_ovp.py`（KiCad付属Python）で、現行r5の基板を読み取り元に、8部品の追加と配線を行う。配線は`gen/maze.py`（小さなA*ルーター）で行い、最後に必ずKiCadのDRCで検証する。

## シミュレーションの要点（`sim-spice/README.md`、KiCad同梱のngspiceによる机上値）

| ケース | 結果 |
|---|---|
| 正常（1A負荷） | 電圧降下 約60mV（16角条件で46〜77mV）。静止電流 約0.5mA |
| 遮断電圧（ゆっくりした立ち上がり） | 公称6.6V、16角条件で5.68〜7.25V |
| 5.5V給電 | 全16角条件で誤遮断なし（下限5.68Vとの余裕は約0.18V） |
| PDの5V→12Vステップ（30mV/µs） | Voutのピーク 5.9〜7.5V（公称6.8V）、遮断後は約0V |
| 12V、20Vの定常 | Q9はオフを維持、Voutほぼ0。D12は最大32mW／86mW（定格350mW） |
| **1V/µsの急峻な12V立ち上がり** | **ほぼ保護できない**（Voutが約10〜12Vまで上がる）。ゲートの時定数の限界 |

- 部品値の感度を54通り掃引したが、窓の下限≥5.5Vを保ったまま上限を下げる組合せは、実質なかった。確定値（6.2V／R93=1k／R94=4.7k）のままとする。
- **R93の電力:** 20V定常で最大約166mWとなり、0603の一般的な定格（約100mW）を超える。12V（本件の想定）では約28mWで問題ない。**PD 20Vが来うる構成にするなら、R93の定格・パッケージを見直す。**
- Coreには、遮断が働くまでの間に、約6〜7.7Vが出る（PDステップ時の最大）。

## 未確認事項

- 遮断電圧は、汎用モデルでの机上値（`sim-spice/`）。実デバイスの特性ばらつきは未測定。ゼナーの温度係数、MOSFETしきい値の温度変化、製造ばらつきは、モデルに入っていない。
- 12V混入時の遮断動作の実機確認は、行わない方針。
- Coreの5V端子の絶対最大定格。
- 配置・配線は、KiCad上のDRCだけの確認。電流（約1.5A）に対する配線幅・ビアの余裕は、設計者の確認が要る。
- 製造用データ（Gerber等）は作っていない。
